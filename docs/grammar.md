# effectful-yaml 言語仕様（草案 0.8）

effectful-yaml は、素の YAML の上に**作用**（effect）つきの計算を埋め込む言語である。
すべての文書は一般の YAML パーサーでそのままパースでき、`$` で始まるキーを持つマッピングだけが計算として解釈される。
`$` を含まない YAML 文書は、それ自身を値とする妥当なプログラムである。
ファイルに置いた文書を effectful-yaml だと明示したいときは、拡張子 `.eyaml` を用いる。

本仕様は現行の文法と評価モデルだけを記す。
意味論の理論的な背景は[理論的背景](theory.md)に、判断の理由と退けた代替案、草案間の変更は[設計の経緯](history.md)に記す。

## 設計原則

- **素の YAML**：文法上の拡張を一切持たない。特殊な構文はすべてマッピングのキーと文字列の中に閉じ込める。YAML タグ（`!do` など）を使わないのは、タグが JSON 部分集合で表現できず、タグを拒否するパーサー[^1]や jq のような既存ツールと相性が悪いからである。
- **カーネルは最小**：言語が意味を直接与えるのは、少数の構文だけである。標準の演算とハンドラはすべて `std` 名前空間にあり、その意味論はカーネルへの展開で定まる。
- **作用は紙面に現れる**：作用を起こすのは演算の呼び出しと、欠落しうるパスアクセスだけである。裸の参照 `${x}` は純粋であり、作用を隠さない。
- **形は書いたとおり**：値がリストになるのは、literal なリストと、選択をリストに集めるハンドラ（`$std.list` など）の値だけである。処理系が形を補うことはなく、どのハンドラにも捕まらずに境界へ達した選択はエラーになる。「分岐が何本になるか」を読み手が数えなくても、値の形は紙面から読める。
- **リストは常にデータ**：YAML のリストがデータでなくなるのは、導出形 `$do` の直下だけである。この例外を一つに絞ることで、「このリストは値なのか文の並びなのか」という読み手の迷いをなくす。`$do` はカーネルへの展開で定まるので、カーネルはこの例外を持たない。
- **暗黙の null を作らない**：未定義の参照はエラーになる。存在しないキーと添字、渡されていないパラメータ、未初期化のセルの読み出しは、null になるのではなく失敗作用 `std.fail` を起こす。失敗は捕捉できるが、捕捉しなければ文書全体のエラーになる。
- **停止する**：一般再帰に相当する原始（fix）を置かず、関数値の流れの検査（評価モデルの節）が自己適用を評価前に拒否する。`$collect` は有限の構造しか回らないので、妥当な文書の評価は、停止しない登録演算をホストが与えない限り必ず停止する。
- **型クラスを持たない**：作用の多相はハンドラが担う。演算は抽象的な名前であり、その意味は包囲する最も近いハンドラが選ぶので、同じ演算がハンドラごとに別の意味を持てる（`std.each` は `$std.list` の下では全分岐の列挙に、`$std.first` の下では最初の成功までの探索になる）。値のオーバーロードはそもそも提供せず、`==` は構造的等価に、算術は数値だけに固定する。

[^1]: たとえば PyYAML の `safe_load` は、登録されていないローカルタグを既定で拒否する。

## 評価モデル

文書はテンプレートとして外側から評価される。
`$` で始まるキーを持つマッピングを **`$` 式**と呼ぶ。
評価関数は次の規則に従う。

- スカラーは、`${...}` の補間を解決した値になる。
- リストは、各要素を先頭から順に評価したリストになる。
- `$` キーを持たないマッピングは、各値を文書順に評価したマッピングになる。
- `$` 式は、主キーごとに定められた規則で評価する。

一つの `$` 式に置ける主キー（`$do` や `$collect` など）は一つだけである。
`$then` のような補助キーは、主キーに従属するものだけを置ける。
`$` キーとそれ以外のキーの混在はエラーである。
例外として、本体を欠いた `{$with: 節}` は主キーを持たないが、`$do` の文としてだけ置ける（`$do` の節）。

### 予約キーとカーネル

ドットを含まない `$` キーは言語が予約する。
予約キーは次の 14 個であり、予約されていないドットなしの名前はエラーになる。

`$do` `$let` `$in` `$if` `$then` `$else` `$fn` `$body` `$handle` `$with` `$resume` `$collect` `$into` `$default`

このうちカーネル、すなわち評価器が意味を直接与える構文は次の 6 形である。

- 参照と式 `${...}`
- 束縛と逐次 `$let`（`$in`）
- 分岐 `$if`（`$then` `$else`）
- 関数 `$fn`（`$body`）と呼び出し
- ハンドラ `$handle`（`$with` `$resume`）
- 畳み込み `$collect`（`$with` `$into`）

文の並び `$do` と、`$fn` に引数名の列を書く形は**導出形**であり、意味はカーネルへの展開で定める。
`$in` は `$let` のほかに `$std.state` が、`$default` は std の演算とハンドラ（`$std.param` と `$std.opt`）が使う補助キーである。

補助キーのうち `$in` と `$with` の役割は、どの形でも変わらない。
`$in` は常に本体、すなわちその形がスコープを及ぼす計算を導く（`$let`、`$std.state`）。
`$with` は常に解釈、すなわち演算または要素を解釈する節や関数を導く（`$handle`、`$collect`）。
`$handle` の `$with` に書くローカル作用の宣言（ハンドラの節）もこの割り当てを崩さない。宣言が与えるのは演算の解釈であり、それを呼ぶ名前の束縛は解釈に付随する。
将来加わる形もこの割り当てに従う。

演算はカーネルに属さない。
`$collect` は名前がドットを含まないことが示すとおり演算ではなく、作用を起こさない畳み込みの構文である。

### 作用境界

データの中に現れた最も外側の `$` 式を**作用境界**と呼ぶ。
境界の内側で演算が起こす作用は、途中にハンドラがなければ境界まで伝播し、そこで処理系の**既定ハンドラ**が処理する。
選択だけは既定ハンドラを持たない。選択を値にするのは明示のハンドラだけであり、境界へ達した選択はエラーになる。
入れ子の `$` 式は境界にならないので、`$do` の中の `$do` は単なるグループ化である。

演算は `$` 式の引数の中であればどこにでも置ける。
たとえば文 `- [1, {$std.each: [a, b]}]` はリストの要素の位置で選択を行うので、外側のブロック全体が 2 通りに分岐する。

境界が互いに独立であることには意味がある。
兄弟関係にある二つの境界は作用を共有しないので、データ部分の評価は順序に依存しない。
複数の場所で状態や選択を共有したければ、その範囲全体を一つの `$do` で包み、単一の境界にする。

### 作用の推論

作用は演算の名前で数える。
各ノードの**作用集合**は、その内側に出現する演算の名前を合併し、ハンドラが節に挙げた名前を除いて、節と `return` の本体の作用を加えたものである。
出現だけを見るので、実行されない分岐の演算も作用に数える。
導出形は展開してから数える（`$std.where` の出現は `std.each` を加える）。
ローカル作用の宣言も展開してから数える。宣言が生む内部の演算名は、宣言を書いたハンドラが必ず節に挙げているので、そのハンドラより外へは現れない（ハンドラの節）。
欠落しうるパスアクセス（後述）は `std.fail` を作用集合に加える。
ホスト登録の演算の出現も、実装が失敗を通知できるので `std.fail` を作用集合に加える。
これにより、文書が要求するハンドラの一覧（作用シグネチャ）が実行前に定まる。

境界に達した作用は、処理系が文書を std の既定ハンドラの系列で包んだものとして処理される。
系列は外側から失敗、パラメータ、ログ、状態の順である。

- **失敗**：捕捉されずに届いた `std.fail` は、その値をメッセージとして文書全体のエラーになる。
- **パラメータ**：`std.param` は起動時に与えられたパラメータ表を読む。
- **ログ**：`std.log` は値をホストのログ出力に流す。
- **状態**：暗黙の `$std.state: {}` が置かれる。境界にあるので文書内のどの選択のハンドラよりも外側であり、状態は分岐をまたいで文書順に貫流する。この振る舞いを変えたいときは `$std.state` を明示的に置く。

選択（`std.each`）には既定ハンドラがない。
境界へ達した選択は `unhandled choice` のエラーになるので、選択を含む計算は `$std.list` `$std.mapping` `$std.first`、または `std.each` の節を持つ `$handle` で包む。

### 関数値の流れと停止性

処理系は評価の前に、関数値の流れを文書全体で推論し、自己適用を含みうる文書をエラーとして拒否する。
関数値を作るのは `$fn` だけである。
パラメータとホスト演算の結果は常にデータであり、閉包が文書の外から入ってくることはない。
したがって文書に現れる `$fn` は有限個であり、文書内の各位置に現れうる関数値は、実行せずに過大近似できる。
各 `$fn` が見る関数値——パラメータに流れ込みうる値、本体の中の適用の呼び先、本体の中の演算の値（状態のセルを通って戻る値と、節の `$resume` で再開される値を含む）——から、構造（マッピング・リスト・分岐）をたどって別の `$fn` に到達しうるとき、前者は後者に依存する。
この依存が循環をなす（自分自身への依存を含む）文書は、評価前にエラーになる。
例外として、`$resume` の結果の適用は依存に数えない。継続の適用はハンドラの畳み込みに沿って必ず停止するからである（`$std.state` の展開はこの形である）。
値が関数とデータの間で分岐すること自体は誤りではない。
検査が拒むのは、自己適用が要求する循環だけである。
関数値を状態のセルに置き、読み出して適用する後結び（Landin の knot）も、演算の値の経路として同じ循環に数える。
推論は作用の推論と同じ出現主義であり、実行されない分岐（`$if` の選ばれない側、`$default`）の中の適用も数える。
検査は注釈を要しない。
型を書く構文はなく、予約キーも増えない。
この検査の失敗位置は、評価時の失敗位置と違い、`$` 式の内側へも降りる構文上の位置（例 `config.$let.f`）で報告される。
この検査に通った文書の評価は、停止しない登録演算をホストが与えない限り必ず停止する。

### 合成と境界

作用境界がどこに生じるかを、構文上の位置ごとに三つに分けて定める。

**合成**：`$let` の右辺から後続の束縛と `$in` の本体への流れ、`$do` の文の並び、`$if` の選ばれた分岐、関数呼び出し（`$.名前`）と演算の引数と本体、`$collect` の対象と関数本体、そして境界の内側に現れるデータ構成（リストの要素、`$` キーを持たないマッピングの値）は、境界を作らない。
内側で起きた作用は周囲の計算へそのまま合流する。
データ構成は作用を起こさないが、遮りもしない。
文 `- [1, {$std.each: [a, b]}]` が外側のブロック全体を 2 通りに分岐させ、選択のハンドラの下で `[1, a]` と `[1, b]` の 2 分岐になるのはこのためであり、`$let` の右辺に `$std.each` を書くと包囲する逐次の全体が分岐するのも、関数呼び出しの作用が「引数の作用と本体の作用の合併」になるのも同じ理由による。

**部分処理**：ハンドラ（`$handle` の本体、および std の派生ハンドラの本体）が処理する範囲は、そのハンドラが節に挙げた演算だけを取り除く。
それ以外の作用はそのまま透過し、ハンドラ自身の値へ合流する。
既定の状態（貫流）が選択をまたぐのは、既定の状態ハンドラが境界にあり、文書内のどの選択のハンドラよりも外側だからである。

**境界**：作用境界の節で定めたとおり、データの中に現れた最も外側の `$` 式と、文書全体だけが境界である。
境界に達した計算は、残るすべての作用を既定ハンドラの系列で処理し尽くしてから、初めて具体的な値になる。
境界の内側には、明示のハンドラを除いて作用を堰き止める場所はない。

境界に達した計算に選択が残っていればエラーである。
選択を値にできるのは、それを処理するハンドラ（`$std.list` `$std.mapping` `$std.first`、および `std.each` の節を持つ `$handle`）だけであり、そのハンドラの形が値の形を決める。
`$if` は合成なので、選ばれた分岐の選択だけが周囲へ合流する。
`$then` にだけ選択が現れる `$if` は、`$else` 側が選ばれれば選択を起こさない。

**引数の評価順**：演算も関数呼び出しも、引数を評価してから、それぞれ演算の実行・本体の評価に進む（値渡し）。
引数の評価で起きた作用は堰き止められず、周囲へ合流する。
`{$.f: {$std.each: [1, 2]}}` は、引数の選択が周囲へ合流するので、f の呼び出しごと分岐する（f が 1 回で `[1, 2]` を受け取るのではない）。
`$std.param` の `$default` は例外で、`$if` の分岐と同じ**遅延位置**である。
パラメータが渡されていれば `$default` は評価されず、その作用も起きない。
作用の推論は出現主義なので、評価されない場合でも `$default` の中の演算は作用集合に数える（`$if` の選ばれない分岐と同じ扱い）。

## 参照と式

**参照**：`${式}` は文字列の中に式の値を埋め込む。
文字列全体が一つの `${式}` であるときは値そのもの（型を問わない）になり、それ以外のときは値を文字列化して埋め込む。
リストとマッピングと null の文字列化はエラーである。

参照が解決するのは `$let` と `$fn`、および `$with` のローカル作用の宣言が導入した束縛だけである。
パラメータは `std.param`、状態は `std.get` という演算を通じて読む。
この区別により、作用を起こす読み出しは必ず演算として紙面に現れる。

**パスの部分性**：`${x}` のような裸の参照は純粋である。
`${x.y}` や `${xs[0]}` のようにパスをたどる参照は、キーや添字が存在しないとき失敗作用 `std.fail` を起こす。
失敗はハンドラで捕捉でき、捕捉しなければ境界で文書全体のエラーになる。
一方、束縛名そのものが未定義であること、マッピングでない値のキーをたどること、型の不一致は、データではなく文書の形の誤りなので、捕捉できないエラーのままである。
作用の推論では、パスをたどる参照の出現が `std.fail` を作用集合に加える。

`${}` の中に YAML 構造（演算の呼び出しなど）を書くことはできない（理由は[設計の経緯](history.md)）。
演算の結果を式で使うには、`$let` で名前を付けてから参照する。

YAML の規則上、`[...]` や `{...}` のフロー形式の中では `${x}` を含むスカラーに引用符が必要になる[^2]。
ブロック形式ではそのまま書ける。
本仕様の用例は、参照を含む箇所をブロック形式で書くことでこれを避けている。

[^2]: フロー文脈のプレーンスカラーは `{` などのフロー指示子を含められない（YAML 1.2 の ns-plain-safe(flow)）。これは本言語ではなく YAML 自体の制約である。

**エスケープ**：文字列とキーの中の `$$` は literal な `$` 一文字になる。
たとえば値 `"costs $$5"` は `costs $5` に、キー `$$do` は literal なキー `$do` に評価される。
`$` 式かどうかの判定は補間より前に、書かれたままのキーに対して行う。

式の文法は次のとおり最小限にとどめる。

```
式      := 論理和
論理和  := 論理積 ("||" 論理積)*
論理積  := 否定 ("&&" 否定)*
否定    := "!" 否定 | 比較
比較    := 加算 (("==" | "!=" | "<" | "<=" | ">" | ">=") 加算)?
加算    := 乗算 (("+" | "-") 乗算)*
乗算    := 単項 (("*" | "/" | "%") 単項)*
単項    := 数値 | '文字列' | true | false | null | 参照名 | "(" 式 ")"
参照名  := 名前 ("." 名前 | "[" 自然数 "]")*
```

- 比較 `==` と `!=` は値の構造的な等価性を判定する。大小比較と算術は数値だけに定義され、それ以外の型に適用するとエラーになる。
- `&&` と `||` と `!` の被演算子、および `$if` と `std.where` の条件は真偽値でなければならない。真偽値への暗黙の変換は行わない。
- `.名前` はマッピングのキーを、`[自然数]` はリストの 0 起点の添字を参照する。存在しないキーや添字は `std.fail` を起こす。
- 0 除算はエラーになる。文字列の連結は補間で書く。

式にはリストとマッピングのリテラルがない。
空リストとの比較が必要なときは、`$let` で `empty: []` のように名前を付けてから `${xs == empty}` と書く。

## 束縛と制御

`$let` と `$if` は作用を持たない構文である。
文の並び `$do` はカーネルへの展開で定まる導出形であり、本節で併せて定める。

### $let

```yaml
$let:
  x: 式1
  y: 式2
$in: 本体の式
```

`$let` は逐次のカーネル構文である。
右辺を文書順に評価し、その値を名前に束縛して、`$in` の本体を評価する。
本体の値が全体の値であり、束縛は本体から `${x}` で参照できる。
この評価の規則は関数呼び出しの規則（関数の節）と同一である。
右辺は引数と同じく値渡しで評価され、本体はレキシカルスコープで評価され、作用は右辺と本体の合併である。
すなわち `$let` は無名関数の即時適用と同じ意味を持つが、名前を経ない適用を書く形が無いので、導出形ではなくカーネルに置く。
後の束縛の右辺からは先の束縛を参照できる。
同じ名前の再束縛は許され、外側の束縛を隠す。
束縛名にドットは使えない。呼び出しの名前空間の区切りと衝突するからである。
`$in` を省いた `$let` は `$do` の文としてだけ書ける（`$do` の節）。

`$let` は非再帰であり、右辺から自分自身や後の束縛は見えない。

右辺の評価は作用を起こしてよい。
`x: {$std.each: [a, b, c]}` は「a、b、c のそれぞれを x として」と読める。
束縛が作用を起こすかどうかは、右辺に演算が見えるかどうかと一致する。

右辺が作用を起こす場合、束縛を書く順序は意味を持つ。
とりわけ、`$std.each` より前に書いた `$std.get` は分岐する前に一度だけ実行され、全分岐が同じ値を見る。
`$std.each` より後に書けば分岐ごとに実行される。

値を捨てて作用だけを残したい右辺は、`_` のような参照しない名前に束縛する慣用で書く。
`_` はただの束縛名であり、言語は特別扱いしない。
YAML は一つのマッピングの中の重複キーを許さないので、捨てる文が二つ以上あるときは名前を変えるか、`$do` で書く。

### $do

```yaml
$do:
- 文1
- 文2
- 結果式
```

`$do` は直下のリストを文の並びとして先頭から評価し、最後の文の値を全体の値とする。
これが「リストはデータ」の唯一の例外である。
空の `$do` の値は null である。

文には任意の式のほか、本体を欠いた二項形と演算を置く。
最後の文を除き、文の値は捨てられる。
`std.where` と `std.set` と `std.log` の値は null であり、この位置に置くのがなじむ。
YAML には unit 型がないため、値を返さないことを表すには null を unit の代用とする。

スコープを持つ二項形（`$let`、`$std.state`、`$handle`）は本体をちょうど一つ持ち、本体の載る位置は形ごとに定まる。

| 形 | 本体の位置 | 本体を欠いた形（= 文） |
|---|---|---|
| `$let` | `$in` | `{$let: 束縛}` |
| `$std.state` | `$in` | `{$std.state: 初期値}` |
| `$handle` | 主キーの値 | `{$with: 節}` |

本体を欠いた二項形は文として置ける。
展開は、残りの文を `$do` に包んで本体の位置に入れる。
`$collect` は本体（継続）を持たないので文形を持たない。

`$do` は導出形であり、意味は次の展開で定める。
規則は上から順に、最初に一致したものを適用する。
私的名は文書から参照できない捨て名である。

```
{$do: []}                              ≡ null
{$do: [{$let: 束縛}, 残り...]}         ≡ {$let: 束縛, $in: {$do: [残り...]}}
{$do: [{$std.state: 初期値}, 残り...]} ≡ {$std.state: 初期値, $in: {$do: [残り...]}}
{$do: [{$with: 節}, 残り...]}          ≡ {$handle: {$do: [残り...]}, $with: 節}
{$do: [結果]}                          ≡ 結果
{$do: [文, 残り...]}                   ≡ {$let: {私的名: 文}, $in: {$do: [残り...]}}
```

展開により、`$let` 文の束縛が残りの文から見えることと、途中の文の値が捨てられることが定まる。
同じ展開により、`$with` 文と `$std.state` 文も残りの文をスコープに取ることが定まる。
`$with` 文のローカル作用の宣言（ハンドラの節）が導入する束縛も、この本体すなわち残りの文から見える。`$let` 文の束縛と同じスコープ規則である。
先に置いた `$with` 文ほど外側のハンドラになる。
本体を欠いた文を末尾に置くと、その本体は `{$do: []}` すなわち null になる。
文の並び替えが意味を変えるのは、`$let` の束縛順と同じ理由である。

### $if

```yaml
$if: 条件式
$then: 式
$else: 式
```

`$if` は条件の値に応じて `$then` か `$else` の一方だけを評価する。
`$else` は省略できない。
条件が真偽値でなければエラーになる。

## 関数

### $fn

```yaml
$fn: パラメータ名
$body: 式
```

`$fn` は関数の値を作る。
評価すると、定義位置の束縛を捕まえた**閉包**になる。
閉包が境界の外へ出て文書の値に残ることはエラーである。
ローカル作用の宣言が束縛する素通しの閉包には、これとは別に、宣言したハンドラの動的範囲の外で呼ばれたときのエラーがある（ハンドラの節）。

カーネルの関数はパラメータをちょうど一つに固定する。
複数の値を渡すときはマッピングで一つに包み、本体から `${arg.名前}` のようにパスで参照する。

#### 引数名の列と部分適用

`$fn` には相異なる名前の列（1 個以上）も書ける。
この形は導出形であり、意味はカリー化の展開で定める。

```
{$fn: [a, b, ...残り], $body: 本体} ≡ {$fn: a, $body: {$fn: [b, ...残り], $body: 本体}}
{$fn: [a], $body: 本体}            ≡ {$fn: a, $body: 本体}
```

展開の各段は一引数のカーネル関数なので、一つ固定の原則は崩れない。
**部分適用**は通常の適用そのものである。
先頭の引数だけを与える呼び出しは、残りの引数を待つ閉包を値として返す。

```yaml
$let:
  add:
    $fn: [a, b]
    $body: ${a + b}
  succ:
    $.add: 1
$in:
  $.succ: 41
```

適用の規則も既存のままである。
引数の式はその適用の位置で正格に評価され、値が閉包に捕まり、再評価されない。
したがって引数の式の作用は部分適用の位置で一度だけ生じ、本体の作用は最後の引数が与えられて本体が走る位置で生じる。

空の列、文字列でない要素、名前の重複は形の誤りでありエラーになる。
全引数を与えないまま閉包が文書の値に残れば、既存の関数値の脱出のエラーに落ちる。
`$handle` の節と `$collect` の `$with` は処理系が一引数で呼ぶ位置なので、そこに引数 2 個以上の `$fn` を書くと閉包が結果の値になり、多くの場合そのまま脱出のエラーへ至る。

### 呼び出しと名前空間

関数の呼び出しは演算の呼び出しと同じ形 `{$名前: 引数}` で書く。
名前は形で三つに分かれ、解決の優先順位のような暗黙の規則を持たない。

- **`$.名前`**：ドットで始まる名前は、レキシカルな束縛を指すローカル名前空間である。名前はドット区切りの単純な識別子の列（`名前(.名前)*`）で、最初の区画が束縛を解決し、残りの区画があればその値のマッピングを順にキーでたどる。たどり着いた値が関数でなければエラーになる。束縛を導入するのは `$let` と `$fn`、および `$with` のローカル作用の宣言（ハンドラの節）である。最初の区画が `return` である呼び出しは形の誤りであり、後述のとおり評価前に拒否される。
- **`$名前空間.名前`**：ドットを含む名前は演算を指す。`std.` で始まる名前は標準演算であり、それ以外はホストに登録された演算である。
- **`$名前`**：ドットを含まない名前は予約キーである。予約されていない名前はエラーになる。

グローバル名前空間（ドットを含まない名前）は言語が予約し、予約キーにドットを含む名前を今後も追加しない。
したがって、名前空間を持つ関数と演算が将来の予約キーと衝突することはない。
`$.名前` が何区画のドットを持っても、先頭のドットで区別がつくので、この一意性は崩れない。
ハンドラの節名にも同じ構造の予約がある（ハンドラの節）。裸の識別子の空間で言語が予約するのは `return` ただ一つであり、今後増やさない。
`$let` の束縛名自体にはドットを使えない（束縛と制御の節）ため、名前の中のドットは常に「束縛名の終わり・キーアクセスの始まり」の区切りとして読める。
たとえば `$.a.self` は、束縛 `a` の値をマッピングとして読み、キー `self` の値を関数として呼ぶ。
呼び出しの経路の解決は関数という文書の形に関わるので、失敗作用ではなくエラーの語彙（`undefined reference`、`cannot access key`、`missing key`）で報告する。
添字 `[0]` はこの経路では書けない。
添字の先や、計算した式の先にある関数は、`$let` で名前に束縛してから `$.名前` で呼ぶ。
`${x}` の参照は呼び出しではないので、この規則の対象外である。

**`$.return` の予約**：最初の区画が `return` である呼び出し（`$.return` と `$.return.x` を含む）は形の誤りであり、処理系はその出現を評価前に `return is reserved: $.return is not callable` で拒否する。
`return` は節名の裸の識別子の空間に予約されているので、`$with` に書いた `return` は return 節であってローカル作用の宣言ではなく、束縛を導入しない。
したがってこの形の呼び出しは決して解決しない。
`$let` や `$fn` が `return` という名前に束縛すること自体は妨げず、`${return}` の参照も通常どおり解決する。
拒むのは `$.return` という呼び出しの形だけである。

引数を評価してからパラメータに束縛し、本体を定義位置の環境で評価する（レキシカルスコープ）。
呼び出しの作用は、引数の作用と本体の作用の合併である。
関数の本体に現れる演算は、その関数がどの位置から呼ばれるかによらず作用シグネチャに数えられる（演算の節）。
本体が選択を起こす関数は、呼び出しの経路が実行時に決まる場合も含めて、選択を処理するハンドラの内側で呼ぶ。

`$let` が非再帰なので、名前による再帰は書けない。
反復は `$std.each` と `$collect` のようにデータ構造に沿った形で書く。
関数値の自己適用は構文では排除できないが、評価前の関数値の流れの検査が拒否する（評価モデルの「関数値の流れと停止性」）。
言語は fix に相当する原始を提供しない。

## $collect

`$collect` は畳み込みのカーネル構文である。
構造を先頭から回りながら、要素ごとの結果を一つの構造に組み立てる。

```yaml
$collect: 対象の式
$with: 一引数関数の式
$into: list または mapping   # 省略時 list
```

- 対象はリストまたはマッピングである。マッピングは `{key: キー, value: 値}` のエントリの列として文書順に回る。
- `$with` の関数を各要素に文書順に適用する。関数は要素ごとにリストを返さなければならない。
- `$into: list` のとき、全要素の結果リストを文書順に**連結**したリストになる。
- `$into: mapping` のとき、結果リストの各要素は `key` と `value` のちょうど二つのキーを持ち `key` が文字列であるマッピングでなければならず、全エントリを集めた一つのマッピングになる。キーの重複はエラーである。
- 空の対象の値は、`$into: list` なら空リスト、`$into: mapping` なら空マッピングである。

`$collect` 自身は作用を起こさず、ハンドラで捕捉できない。
作用は対象の式と `$with` の関数本体の作用の合併である（関数呼び出しと同じ規則）。
対象が有限である限り適用は有限回なので、`$collect` は停止性を壊さない。

map は要素を一要素リストで包む関数で、filter は空リストを返す分岐で、連結は恒等関数で書ける。
アキュムレータを伴う古典的な fold は、`$collect` と `$std.state` の組で導出できる（用例の節）。

```yaml
# 各要素を二重にする: [1, 1, 2, 2, 3, 3]
$collect: [1, 2, 3]
$with:
  $fn: x
  $body:
  - ${x}
  - ${x}
```

## 演算

演算は作用を起こす `$` 式であり、名前は必ずドットを含む。
演算の名前そのものが作用の名前である。
各演算は、包囲する最も近いハンドラの節か、境界の既定ハンドラが処理する。
文書に出現する演算名を集めれば、その文書が要求するハンドラの一覧、すなわち文書の**作用シグネチャ**が評価前に得られる。
処理系は、標準でもホスト登録でもなく、どのハンドラの節にも現れない演算を含む文書を評価前に拒否する。
この検査は演算の出現に対して全域であり、実行が到達しない位置の演算も、実行時にしか呼び先が決まらない関数の本体の演算も同じく拒否の対象になる。

### 標準の演算

`std.` で始まる名前は言語が予約する標準演算であり、ホストは `std.` 名前空間に演算を登録できない。
作用を起こす標準演算は次の 6 つである。

| 演算 | 意味 |
|---|---|
| `$std.each: リストまたはマッピング` | 要素を一つずつ選ぶ。値は選ばれた要素。 |
| `$std.param: 名前` | 起動時に与えられたパラメータを読む。 |
| `$std.get: 名前` | セルの現在値を読む。 |
| `$std.set: マッピング` | セルに値を書く。未作成のセルは作られる。値は null。 |
| `$std.log: 式` | 値をログに流す。値は null。 |
| `$std.fail: 式` | 計算を失敗させる。値をエラーメッセージとする。 |

補足を述べる。

- `$std.each` の引数がリストなら各要素を、マッピングなら各エントリを `{key: キー, value: 値}` の形で、文書順に選ぶ。`$std.each: ${xs}` のようにデータ駆動の反復が書ける。空のリストやマッピングは分岐 0 本を意味し、その分岐は打ち切りになる。
- `$std.param` は補助キー `$default` を取れる。`{$std.param: 名前, $default: 式}` は、`{$std.param: 名前}` を `$handle` で包み `std.fail` の節で `$default` の式を返す形への展開と等価である。したがってパラメータが渡されていないときの値は `$default` の式であり、`$default` がなければ `std.fail` が境界まで伝播してエラーになる。
- `$std.get` の名前空間は `$let` の束縛とは別である。同名でも互いに関係しない。未初期化のセルの読み出しは `std.fail` を起こす。この失敗は `$std.state` の展開の節の本体で起こるので、そのセルを解決する状態ハンドラの位置で生じる。暗黙の既定状態は境界にあるため、文書内で捕捉するには、明示の `$std.state` を捕捉するハンドラの内側に置く。
- `$std.set` は複数のセルを文書順に書ける。

### 打ち切りの導出形 $std.where

```yaml
$std.where: 条件式
```

`$std.where` は条件を満たさない分岐を打ち切る。
導出形であり、意味は次の展開で定める。

```
{$std.where: 条件式} ≡ {$if: 条件式, $then: null, $else: {$std.each: []}}
```

条件が真なら値は null である。
偽なら空の `$std.each` が分岐 0 本の選択となり、包囲する選択のこの分岐が打ち切られる。
条件が真偽値でなければエラーになる。
`$std.where` は演算ではないので、ハンドラの節の名前にならず、捕捉もされない。
打ち切りを処理するのは、展開に現れる `std.each` を処理する選択のハンドラである。
作用集合への寄与も展開のとおり `std.each` である。

### 計算したキーの照会 $std.lookup

```yaml
$std.lookup:
  in: マッピングの式
  key: キーの式
```

`$std.lookup` はマッピングを計算したキーで引く標準演算である。
式のパス `${m.k}` のキーが literal に限られるのに対し、`$std.lookup` はキーを式で与えられる。
意味は選択による照合への展開で定める。

```yaml
$let:
  m: in の式
  k: key の式
$in:
  $std.first:
    $do:
    - $let:
        e:
          $std.each: ${m}
    - $std.where: ${e.key == k}
    - ${e.value}
```

キーが在ればその値になり、無ければ `$std.first` の規則によりこの位置で `std.fail` が起きる。
したがって欠落は、パスアクセスの欠落と同じように `$std.opt` と `$handle` で扱える。
失敗の値の文言だけは展開に委ねず、欠落したキーを含む説明文とする。
`in` の値がマッピングでないことと `key` の値が文字列でないことは、データの変動ではなく形の誤りなのでエラーである（`$collect` のエントリ検査と同じく契約に含め、展開には現れない）。
作用集合への寄与は `std.fail` と引数の式の作用だけである。展開の中の選択は `$std.first` が処理し尽くすので、外へは出ない。
`std.lookup` はハンドラの節の名前にならない。
実装は O(1) の照会で最適化してよいが、観測できる振る舞いは展開と一致しなければならない。

### マッピングのマージ $std.merge

```yaml
$std.merge: マッピングのリストの式
```

`$std.merge` は複数のマッピングを一つに重ねる標準演算である。
同じキーは後のマッピングの値が勝ち、キーの位置は初出の位置が保たれる。
マージは浅い。値がともにマッピングでも再帰せず、後の値がそのまま採られる。
入れ子の階層で重ねたいときは、その階層に `$std.merge` を書く。
null は普通の値として上書きする。キーの削除はマージの仕事ではなく、`$std.mapping` と `$std.where` の省略の慣用で行う（マッピングの生成と変換の用例）。

意味は二項のマージの左畳み込みで定める。
空のリストは `{}` に、`[m1, ..., mn]` は `{}` から始めて m1 から mn までを順に重ねた結果になる。
二項の merge(a, b) の意味は次の展開で定める。

```yaml
# merge(a, b) の展開。b が勝ち、キーの位置は初出の位置。
$let:
  a: 先の式
  b: 後の式
$in:
  $std.mapping:
    $do:
    - $let:
        phase:
          $std.each: [0, 1]
        src:
          $if: ${phase == 0}
          $then: ${a}
          $else: ${b}
        e:
          $std.each: ${src}
        fresh:
          $if: ${phase == 0}
          $then: true
          $else:
            $std.opt:
              $let:
                _:
                  $std.lookup:
                    in: ${a}
                    key: ${e.key}
              $in: false
            $default: true
    - $std.where: ${fresh}
    - key: ${e.key}
      value:
        $if: ${phase == 0}
        $then:
          $std.opt:
            $std.lookup:
              in: ${b}
              key: ${e.key}
          $default: ${e.value}
        $else: ${e.value}
```

a の側（phase 0）は自分のキーをその位置のまま並べ、b に同じキーが在ればその値で差し替える。
b の側（phase 1）は a に無いキーだけを後ろに足す。
二つの `$std.each` の入れ子が全エントリを一列に並べ、`$std.mapping` が集め直す。

マージは結合的で単位は `{}` であり、この性質はキーの並びを含めて成り立つ。
引数がリストでないことと、要素がマッピングでないことは、データの変動ではなく形の誤りなのでエラーである（`$collect` のエントリ検査と同じく契約に含め、展開には現れない）。
`$std.mapping` がキーの重複をエラーにするのとは矛盾しない。あちらは新しいマッピングの構成であり重複は誤りの兆候、こちらは重複を優先順位で解決することが目的だからである。
作用集合への寄与は引数の式の作用だけである。展開の中の選択は `$std.mapping` が、照会の欠落は `$std.opt` が処理し尽くすので、外へは出ない。`std.merge` はハンドラの節の名前にならない。
引数は式でよいので、`$std.merge: ${overlays}` のようにデータ駆動の重ね合わせも書ける。
実装は直接のマージで最適化してよいが、観測できる振る舞いは展開と一致しなければならない。

### 第一階の標準演算

作用を起こさず、値から値を計算するだけの標準演算を第一階の標準演算と呼ぶ。
導出できないが評価器の協力も要らないので、カーネルではなく供給の層に置く。
第一階の標準演算は `$std.range` ただ一つである。

| 演算 | 意味 |
|---|---|
| `$std.range: 自然数 n` | リスト `[0, 1, ..., n-1]`。数から構造への唯一の橋。 |

第一階の演算も演算の一般規則に従う。
出現は作用シグネチャに数えられ、ハンドラの節で捕捉して意味を差し替えることもできるが、既定の意味は純粋であり、作用を起こさない。
`$std.range` の引数が自然数でなければエラーになる。
回数の上界つきの unfold（種と関数からの列の生成）は、`$std.range` と `$collect` と `$std.state` で書ける（用例の節）。
上界の代わりに述語で止める unfold は while ループそのものであり、fix と同じ強さを持つので提供しない。

### ホスト登録の演算

処理系に登録された演算は、呼ぶだけで作用を起こす。
ハンドラは登録時にホスト言語で与えるか、文書内の `$handle` で与える。

```yaml
password: {$vault.read: secret/db/password}
```

ホストの実装は、値を返す代わりに失敗を通知できる。
処理系は通知を、演算の呼び出し位置で起きた `std.fail`（値は通知された値）として扱い、通常の規則で伝播させる。
したがって途中の `$std.opt` や `std.fail` の節を持つ `$handle` が捕捉でき、捕捉されなければ文書全体のエラーになる。
失敗の通知はデータ起因の部分性（一致しないセレクタなど）のためにあり、ホスト実装のその他の例外は捕捉できないエラーである。

登録演算の名前は `vault.read` のようにドットで名前空間を含まなければならない。
グローバル名前空間は言語の予約キーのためにあり、`std.` 名前空間は標準演算のためにあるので、利用者はそれ以外の名前空間を使う。
名前が長くなるときは、引数を素通しする `$fn` を `$let` で短い名前に束縛する慣用で書く（用例の演算の部分適用）。
閉包をホスト言語のハンドラへ渡すことはできない。
処理系はこれを二重に検査する。
文書内のどの節にも現れない演算の引数に閉包が流れうる文書は評価前に拒まれ、実行時にホストへ渡る直前の引数にも同じ検査が働く。

## ハンドラ

ハンドラは、内側の作用をその場で処理し、外へ伝播させない `$` 式である。
カーネルのハンドラは `$handle` ただ一つであり、std の派生ハンドラはすべて `$handle` と `$collect` への展開で定義される。

### $handle

```yaml
$handle: 本体の式
$with:
  演算名:
    $fn: 引数名
    $body: 節の本体
  return:
    $fn: 値名
    $body: 式
```

`$handle` は利用者が定義するハンドラである。
本体の中で `$with` に書いた演算が呼ばれると、対応する**節**が演算の引数を受け取って評価される。
節の名前は形で分類する。
規則は上から順に、最初に一致したものを適用する。

| 節名の形 | 意味 |
|---|---|
| `$` で始まる名前 | エラー |
| `return` | return 節 |
| 識別子をドットで繋いだ名前（`名前(.名前)+`） | その演算にマッチする節 |
| ドットを含まない識別子 | ローカル作用の宣言（後述） |
| それ以外（空の名前、ドットで始まるか終わる名前、識別子でない文字を含む名前） | エラー |

`$` で始まる節名を今エラーにしておくのは、将来の予約節のために形を空けておくためである。
言語が裸の識別子の空間に予約する節名は `return` ただ一つであり、今後増やさない。
増やすときは `$` を前置した形を使う。
ドットなしの `$` キーを予約キーのために予約するのと同じ構造の約束であり、利用者が選んだローカル作用の名前が将来の言語の追加と衝突することはない。

- 節の本体では `{$resume: 値}` で継続を再開できる。その値は、演算の呼び出し位置に「値」を返して残りの計算（`return` 節を含む）を進めた結果である。
- `$resume` は節の本体の中で呼べる。節の本体で作られた閉包の本体も含み、閉包が捕まえるのはその節の起動に対応する継続である。一度も呼ばない（打ち切り）ことも、複数回呼ぶことも許される。
- 節が `$resume` を呼ばずに値に達したときは、その値がハンドラ全体の値になる（打ち切り）。継続の途中で打ち切られた場合は、その継続を呼んだ `$resume` の位置ではなく、ハンドラ全体が節の値になる。
- ハンドラは深い。再開後の計算にも同じハンドラが効き続ける。
- 節の本体が起こす作用は、このハンドラ自身ではなく外側で処理される。
- `return` 節は、本体が演算を起こさず値に達したときにその値を変換する。省略時は恒等である。

作用の推論では、`$with` に現れた演算の名前が集合から除かれ、節と `return` の本体の作用が加わる。

本体を欠いた `{$with: 節}` は `$do` の文として置ける（`$do` の節）。
文の位置以外の単独の `$with` はエラーである。

#### ローカル作用の宣言

ドットを含まない節名は、そのハンドラだけが処理するローカルな作用を宣言する。

```yaml
$handle: 本体
$with:
  throw: 節
```

意味はカーネルへの展開で定める。
処理系は宣言の位置（`$handle` または `$do` の `$with` 文）の構文パスから内部の演算名を決定的に生成する。
以下ではその名前を `throw@位置` と書く。
私的名は文書から参照できない捨て名である。

```yaml
$handle:
  $let:
    throw:
      $fn: 私的名
      $body:
        $throw@位置: ${私的名}
  $in: 本体
$with:
  throw@位置: 節
```

宣言は、引数を素通しして内部の演算を呼ぶ関数を本体にレキシカルに束縛する。
本体は `{$.throw: 引数}` でその関数を呼び、節が引数を受け取る。
`$let` が値を束縛して `$.名前` で呼ぶのと同じ読み方が `$with` にも通り、利用者は名前空間を書かずに自分の作用を宣言できる。
名前空間つきの演算名が要るのは、std とホスト登録と文書間の約束、すなわち外の世界が関与する場所だけである。

規則は次のとおりである。

- 束縛が見えるのは本体だけである。節の本体、`return` 節、ハンドラの外側からは見えない。節の本体が起こす作用を外側が処理するという規則と揃う。
- `$do` の `$with` 文では、残りの文の並びが本体にあたる。束縛は残りの文から見える（`$let` 文と同じスコープ規則）。
- 内部の演算名は宣言ごとに生成される。別のハンドラが同じ `throw` を宣言していても名前は別なので、束縛を経た呼び出しは必ず宣言元のハンドラに届く。偶然の捕捉は起こらない。
- 内部の演算名は識別子に使えない `@` を含む。利用者が書ける名前は識別子とドットだけからなるので、衝突は構造的に起こらない。「演算の名前は必ずドットを含む」という規則（演算の節）も、利用者が書ける名前への制約であって、展開が生む内部名には課さない。呼び出しの三分が保たれるのは、利用者が内部名を書けないことによる。
- 束縛は普通の束縛である。同じ名前の再束縛で隠せるし、`${throw}` で参照して別名を付けられるし、値として文書の外に残せば関数値の脱出のエラーになる。
- ドットを含む節や `return` 節との混在も、一つの `$with` に複数のローカル宣言を書くことも許される。
- 同じ `$handle` が二度起動されると、二つの起動は同じ内部名を共有する。ある起動から持ち出された閉包が別の起動の動的範囲の内側で呼ばれれば、その起動の節が受け取る。

作用の推論では、内部の演算の出現は素通しの関数の本体、すなわちハンドラの本体の内側にあり、その名前をハンドラが節に挙げているので、作用集合から必ず除かれる。
すなわちローカル作用が静的に外へ漏れることはなく、漏れうるのは動的範囲だけである。
素通しの閉包がハンドラの外へ持ち出されて呼ばれると、内部の演算はどのハンドラにも捕まらずに境界へ達する。
このとき境界は、未登録の演算としてではなく `local effect 'throw' escaped its handler (declared at 宣言位置)` のエラーとして報告する。
静的な検査がこれを防がないのは、出現の位置がハンドラの内側にあるからであり、レキシカルな名前と動的な範囲が別物であることの帰結である（[理論的背景](theory.md)）。

閉包に関するエラーは二つあり、起きる条件が違う。

- **関数値の脱出**：閉包が作用境界の外へ出て文書の値に残った（関数の節）。値になった時点で判定する。
- **ローカル作用の脱出**：素通しの閉包が、宣言したハンドラの動的範囲の外で呼ばれた。呼び出しの時点で判定する。

一つの閉包が両方に当たりうる。
ハンドラの外へ返された素通しの閉包は、呼ばれれば後者、文書の値に残れば前者になる。

```yaml
$handle:
  $do:
  - {$.throw: boom}
  - never
$with:
  throw:
    $fn: msg
    $body: caught ${msg}
```

```yaml
caught boom
```

節が `$resume` を呼ばないので、`$.throw` の呼び出しで本体が打ち切られ、節の値がハンドラ全体の値になる。
`std.fail` の節を持つ `$handle` と同じ形を、名前空間を持たない自前の作用で書いたものである。

入れ子のハンドラが同じ名前を宣言しても、内部名が別なので取り違えは起こらない。

```yaml
$handle:
  $do:
  - $let:
      up: ${throw}
  - $handle:
      a: {$.throw: x}
      b: {$.up: y}
    $with:
      throw:
        $fn: m
        $body:
          $resume: inner ${m}
$with:
  throw:
    $fn: m
    $body:
      $resume: outer ${m}
```

```yaml
a: inner x
b: outer y
```

内側の本体で `$.throw` が指すのは内側の宣言なので、`a` は内側の節が受ける。
`up` は外側の宣言が束縛した関数の別名であり、内側のハンドラの中で呼んでも別の内部名を持つので、内側の節を素通しして外側の節に届く。
どちらの節も `$resume` で再開するため、残りの計算は同じ二つのハンドラの下で続く。

### std の派生ハンドラ

| 形 | 処理する演算 | 値 |
|---|---|---|
| `$std.list: 式` | `std.each` | 全分岐の結果を文書順に並べたリスト |
| `$std.mapping: 式` | `std.each` | 全分岐の `{key, value}` を集めたマッピング |
| `$std.first: 式` | `std.each` `std.fail` | 失敗しなかった最初の分岐の値 |
| `$std.state: 初期値, $in: 式` | `std.get` `std.set` | 本体の値 |
| `$std.opt: 式` | `std.fail` | 本体の値。失敗なら `$default` の式の値（省略時 null） |

派生ハンドラの意味論は展開が定める。
実装は等価な組み込みで最適化してよいが、観測できる振る舞い（値、作用、ログの順序）は展開と一致しなければならない。

**$std.list** の展開は次のとおりである。

```yaml
$handle: 本体
$with:
  std.each:
    $fn: xs
    $body:
      $collect: ${xs}
      $with:
        $fn: x
        $body:
          $resume: ${x}
  return:
    $fn: x
    $body:
    - ${x}
```

ハンドラは深いので、各 `$resume` の値は残りの計算を同じハンドラで処理し尽くしたリストであり、`$collect` がそれらを連結する。
内側に選択がなければ `return` 節だけが働き、要素 1 のリストになる。
`$std.where` の打ち切りは、展開により空の `$std.each` として現れ、`std.each` の節が 0 個の候補を畳んで分岐を消す。
分岐の中の失敗は節にないので処理せず、全体の失敗として伝播させる。

**$std.mapping** は同じ骨格で、`return` 節が `{key, value}` を単エントリのマッピングにし（`$collect` の `$into: mapping`）、`std.each` の節が各再開の結果のエントリを集め直す。
エントリの検査（ちょうど二つのキー、`key` は文字列、重複の禁止）は `$collect` の契約に含まれるので、展開には現れない。
`$std.where` で分岐を打ち切れば、条件を満たすエントリだけを持つマッピングが作れる。
これは「null を入れること」と「キーが無いこと」の区別、すなわちキーの条件付き省略を兼ねる。

**$std.state** の展開は、節が状態変換関数を返す古典的なパラメータ付きハンドラである。
`std.get` の節を示す（`std.set` と `return` も同型）。

```yaml
std.get:
  $fn: name
  $body:
    $fn: s
    $body:
      $let:
        hits:
          $collect: ${s}
          $with:
            $fn: e
            $body:
              $if: ${e.key == name}
              $then:
              - ${e.value}
              $else: []
        k:
          $resume: ${hits[0]}
      $in:
        $.k: ${s}
```

継続の再開結果も状態変換関数なので、それを現在の状態に適用して続行する。
`${hits[0]}` は未初期化のセルでちょうど `std.fail` を起こす。
展開の全体は、本体をこのハンドラで包んで得た関数を初期値に適用する形であり、初期値の式は本体より先に評価される。
`$in` を欠いた `{$std.state: 初期値}` は `$do` の文として置ける（`$do` の節）。
文の位置以外ではエラーである。
`$std.state` を選択に対してどこに置くかで、状態と分岐の関係が決まる。

```yaml
# 貫流（既定と同じ）: 状態が分岐から分岐へ持ち越される
$std.state: {n: 0}
$in:
  $std.list: 選択を含む本体
```

```yaml
# 分岐点で分かれる: 各分岐が選択時点の状態を引き継ぎ、以後は独立に進む
$std.list:
  $std.state: {n: 0}
  $in: 選択を含む本体
```

貫流と分岐点の 2 例の区別は、文の置き場所でも表現できる。
`$std.state` 文を包囲する `$do` に置けば貫流になり、選択のハンドラの中の `$do` に置けば分岐点で分かれる。

**$std.first** は選択と失敗を処理し、失敗しなかった最初の分岐の値に評価される。
最初の成功より後の分岐は評価されず、その作用も起きない。
すべての分岐が失敗または打ち切りなら、全体が `std.fail` になる。
展開は成功の印を私的な演算のパラメータ付きハンドラで持ち回る形になり、紙面に収まらないので参照文書に置く。

**$std.opt** は失敗を翻訳する。
補助キー `$default` を取れる。

```yaml
# {$std.opt: 式, $default: 既定値の式} の展開。失敗を既定値に変える。
$handle: 式
$with:
  std.fail:
    $fn: _
    $body: 既定値の式
```

`$default` を省いた `{$std.opt: 式}` は `$default: null` と等価である。
`$default` は `$std.param` の `$default` と同じ遅延位置であり、本体が失敗したときだけ評価される。
出現主義なので、評価されない場合でも `$default` の中の演算は作用集合に数える。

`$default` は値を返す式に限らず、作用を起こす式でもよい。
失敗した分岐を包囲する選択から黙って外す定型は次の形である。

```yaml
# 失敗を包囲する選択の打ち切りに変える定型
$std.opt: 式
$default: {$std.where: false}
```

展開では `$default` の式が `std.fail` の節の本体になるので、その打ち切り（`$std.where` の展開が起こす `std.each`）はこの `$std.opt` 自身ではなく外側で処理され（`$handle` の規則）、包囲する選択の分岐ごと打ち切られる。
失敗しうる式を要素とみなして選択に流し込むときの標準形であり、欠落したキーを持つデータを黙って除外する用途に使う。
打ち切りは選択なので、この形は選択のハンドラの内側で使う。

## 用例

### 値だけの文書

```yaml
greeting: hello
```

`$` 式を含まない文書はそれ自身に評価される。
値はそのまま計算の結果である。

### 選択の基本形

```yaml
$std.list:
  $let:
    x: {$std.each: [a, b, c]}
    y: {$std.each: [x, y, z]}
  $in:
    $std.each:
    - ${x}
    - ${y}
```

`$std.list` が全分岐の結果を文書順に並べる。
`$in` の本体も選択なので、分岐は 3 × 3 × 2 の 18 本ある。

```yaml
[a, x, a, y, a, z, b, x, b, y, b, z, c, x, c, y, c, z]
```

`$in` の本体を literal なリストに変えると、意味が「2 つの結果を選ぶ」から「2 要素のリストを返す」に変わる。

```yaml
$std.list:
  $let:
    x: {$std.each: [a, b, c]}
    y: {$std.each: [x, y, z]}
  $in:
  - ${x}
  - ${y}
```

```yaml
[[a, x], [a, y], [a, z], [b, x], [b, y], [b, z], [c, x], [c, y], [c, z]]
```

この 2 例の対比が「リストは常にデータ、選択は `$std.each`」という原則の眼目である。

### 打ち切りつきの選択

```yaml
$std.list:
  $do:
  - $let:
      x: {$std.each: [1, 2, 3]}
      y: {$std.each: [1, 2, 3]}
  - $std.where: ${x < y}
  - - ${x}
    - ${y}
```

```yaml
[[1, 2], [1, 3], [2, 3]]
```

リスト内包表記に相当する形である。

### パラメータと条件分岐

```yaml
server:
  host: {$std.param: db_host}
  port: {$std.param: db_port, $default: 5432}
  tls:
    $if: {$std.param: use_tls}
    $then:
      cert: /etc/ssl/cert.pem
    $else: null
```

`db_host: example.com` と `use_tls: false` を渡して評価すると次になる。

```yaml
server:
  host: example.com
  port: 5432
  tls: null
```

三つの境界は互いに独立であり、パラメータは読み出し専用なので、評価順序は結果に影響しない。

### 分岐を貫く状態

```yaml
$std.list:
  $do:
  - $std.set: {n: 0}
  - $let:
      name: {$std.each: [web, db, cache]}
      id: {$std.get: n}
  - $std.set:
      n: ${id + 1}
  - name: ${name}
    id: ${id}
```

状態の既定ハンドラは境界にあり、`$std.list` より外側なので、セル `n` は分岐をまたいで貫流し、連番が振られる。

```yaml
- name: web
  id: 0
- name: db
  id: 1
- name: cache
  id: 2
```

`id` の束縛は `name` の束縛より後、すなわち選択より後にあるから、分岐ごとに読み直される。
二つの束縛を入れ替えると読み出しは分岐の前に一度だけ実行され、全分岐の `id` が 0 になる。

### マッピングの生成と変換

```yaml
$std.mapping:
  $let:
    e: {$std.each: {web: 80, db: 5432}}
  $in:
    key: svc-${e.key}
    value: ${e.value}
```

```yaml
svc-web: 80
svc-db: 5432
```

マッピングを `$std.each` で分解し、`$std.mapping` で組み立て直す形である。
途中に `$std.where` を挟めば、条件を満たすエントリだけを残せる。

### 欠落するデータの除外

```yaml
$std.list:
  $let:
    row:
      $std.each:
      - {date: d1, code: c1}
      - {date: d2}
      - {date: d3, code: c3}
  $in:
    date: ${row.date}
    code:
      $std.opt: ${row.code}
      $default: {$std.where: false}
```

```yaml
- {date: d1, code: c1}
- {date: d3, code: c3}
```

2 行目には `code` が無いので、パスアクセス `${row.code}` が `std.fail` を起こし、`$default` の `{$std.where: false}` がそれを分岐の打ち切りに変える。
失敗を null で埋めたいときは `$default` を省く。

### 回数つきの unfold

```yaml
$std.state: {acc: 1}
$in:
  $collect: {$std.range: 5}
  $with:
    $fn: _
    $body:
      $let:
        v: {$std.get: acc}
        _:
          $std.set:
            acc: ${v * 2}
      $in:
      - ${v}
```

```yaml
[1, 2, 4, 8, 16]
```

種 1 と関数 (*2) から先頭 5 要素を生成する。
書き込みの値は要らないので、捨て名 `_` に束縛している。
`$std.range` が回数をリストに変え、`$collect` が回り、`$std.state` が種を持ち回る。
アキュムレータを伴う fold も同じ組み合わせで書ける。

### 関数と合成

```yaml
$let:
  double:
    $fn: x
    $body: ${x * 2}
  succ:
    $fn: x
    $body: ${x + 1}
$in:
  $.succ:
    $.double: 20
```

```yaml
41
```

呼び出しの入れ子が合成である。
内側が先に評価され、その値が外側の引数になるので、`succ(double(20))` を読み下した形になる。
段が長くなるときは、`$let` で一段ずつ名前を付けて並べる。

### 演算の部分適用

マッピング引数の演算は、引数を組み立てるカリー化された関数（adapter）を一度宣言すれば部分適用できる。
表を固定した照会関数を作り、キーの各分岐に適用する。

```yaml
$std.list:
  $let:
    codes: {ja: 81, us: 1}
    look:
      $fn: [m, k]
      $body:
        $std.lookup:
          in: ${m}
          key: ${k}
    dial:
      $.look: ${codes}
    c: {$std.each: [ja, us]}
  $in:
    $.dial: ${c}
```

```yaml
- 81
- 1
```

部分適用 `{$.look: 表}` の引数はその位置で一度だけ評価され、閉包に捕まる。
返った閉包 `dial` は残りの引数 `k` を待つ普通の関数値であり、`$collect` の `$with` にもそのまま置ける。

### 失敗の捕捉

```yaml
port:
  $handle:
    $let:
      p: {$std.param: port, $default: 0}
    $in:
      $if: ${p <= 0 || p > 65535}
      $then:
        $std.fail: invalid port ${p}
      $else: ${p}
  $with:
    std.fail:
      $fn: msg
      $body:
        $do:
        - $std.log: ${msg}
        - 5432
```

節が `$resume` を呼ばないので、失敗した時点で本体は打ち切られ、節の値 5432 がハンドラ全体の値になる。

### 最初に成功する分岐

```yaml
log_level:
  $std.first:
    $do:
    - $let:
        v: {$std.each: [{$std.param: log_level, $default: null}, {$std.param: fallback_log_level, $default: null}, info]}
    - $std.where: ${v != null}
    - ${v}
```

`$std.first` が選択を処理するので、値はリストではなく、条件を満たした最初の分岐のものになる。
パラメータが一つも渡されていなければ `info` になる。

### 文形のハンドラ

```yaml
$do:
- $with:
    std.fail: {$fn: _, $body: 0}
- $std.lookup: {in: {}, key: missing}
```

```yaml
0
```

本体を欠いた `$with` 文がハンドラとして働き、続く文で `$std.lookup` の照会が起こす `std.fail` を節が既定値に変える。

```yaml
$do:
- $std.state: {n: 0}
- $std.set: {n: 41}
- $let:
    n: {$std.get: n}
- ${n + 1}
```

```yaml
42
```

本体を欠いた `$std.state` 文が状態のハンドラを開き、後続の文が同じセルを読み書きする。
