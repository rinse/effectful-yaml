# effectful-yaml 言語仕様（草案 0.13）

effectful-yaml は、素の YAML の上に**作用**（effect）つきの計算を埋め込む言語である。
すべての文書は一般の YAML パーサーでそのままパースでき、`$` で始まるキーを持つマッピングだけが計算として解釈される。
`$` を含まない YAML 文書は、それ自身を値とする妥当なプログラムである。
ファイルに置いた文書を effectful-yaml だと明示したいときは、拡張子 `.eyaml` を用いる。

本仕様は文法と評価モデルを記す。
意味論の理論的な背景は[理論的背景](theory.md)に、判断の理由と退けた代替案、草案間の変更は[設計の経緯](history.md)に記す。

## 設計原則

- **素の YAML**：文法上の拡張を一切持たない。特殊な構文はすべてマッピングのキーと文字列の中に閉じ込める。YAML タグ（`!do` など）を使わないのは、タグが JSON 部分集合で表現できず、タグを拒否するパーサー[^1]や jq のような既存ツールと相性が悪いからである。
- **構文と呼び出しは綴りで分かれる**：ドットを含まない `$` キーは言語が予約する構文であり、ドットを含む `$` キーは環境にある値の呼び出しである。読み手はドットの有無だけで、言語が意味を与える形か、値の呼び出しかを見分けられる。
- **名前空間は環境である**：`std` もホストが与える名前も、文書の最外の環境にある束縛にすぎない。`$std.each` は束縛 `std` のキー `each` にある値の呼び出しであり、`$let` の束縛の呼び出しと同じ規則で読める。
- **カーネルは最小**：言語が意味を直接与えるのは、参照・`$let`・`$if`・`$fn`・`$handler` の 5 形だけである。標準の演算と関数はすべて `std` の中の値であり、その意味論はカーネルへの展開か、値から値への規則で定まる。
- **作用は紙面に現れる**：作用を起こすのは演算の呼び出しと、欠落しうるパスアクセスだけである。裸の参照 `${x}` は純粋であり、作用を隠さない。
- **形は書いたとおり**：値がリストになるのは、literal なリストと、選択をリストに集める `std.list` の値だけである。処理系が形を補うことはなく、どのハンドラにも捕まらずに境界へ達した選択はエラーになる。「分岐が何本になるか」を読み手が数えなくても、値の形は紙面から読める。
- **リストは常にデータ**：YAML のリストがデータでなくなるのは、導出形 `$do` の直下だけである。この例外を一つに絞ることで、「このリストは値なのか文の並びなのか」という読み手の迷いをなくす。`$do` はカーネルへの展開で定まるので、カーネルはこの例外を持たない。
- **暗黙の null を作らない**：未定義の参照はエラーになる。存在しないキーと添字、渡されていないパラメータ、未初期化のセルの読み出しは、null になるのではなく失敗作用 `std.fail` を起こす。失敗は捕捉できるが、捕捉しなければ文書全体のエラーになる。
- **停止する**：一般再帰に相当する原始（fix）を置かず、関数値の流れの検査（評価モデルの節）が自己適用を評価前に拒否する。反復はすべて有限の構造に沿うので、妥当な文書の評価は、停止しないホストの値を与えない限り必ず停止する。
- **型クラスを持たない**：作用の多相はハンドラが担う。演算は抽象的な名前を持つ値であり、その意味は包囲する最も近いハンドラが選ぶので、同じ演算がハンドラごとに別の意味を持てる（`std.each` は `std.list` の下では全分岐の列挙に、`std.first` の下では最初の成功までの探索になる）。値のオーバーロードはそもそも提供せず、`==` は構造的等価に、算術は数値だけに固定する。

[^1]: たとえば PyYAML の `safe_load` は、登録されていないローカルタグを既定で拒否する。

## 評価モデル

文書はテンプレートとして外側から評価される。
`$` で始まるキーを持つマッピングを **`$` 式**と呼ぶ。
評価関数は次の規則に従う。

- スカラーは、`${...}` の補間を解決した値になる。
- リストは、各要素を先頭から順に評価したリストになる。
- `$` キーを持たないマッピングは、各値を文書順に評価したマッピングになる。
- `$` 式は、主キーごとに定められた規則で評価する。

`$` 式は、主形か、文脈の導入を伴うマッピングのどちらかである。

**主形**は、主キー（`$do` や `$if` や呼び出しの `$std.each` など）ちょうど一つと、その主キーに従属する補助キー（`$then` など）だけからなる。
データのキーとの混在はエラーである（`{$std.param: x, name: api}`）。

**文脈の導入を伴うマッピング**は、頭キー `$let`、`$for`、`$handler` を一つ以上持つ。
頭は `$in` と組で書く形であり、`$in` を省いて頭だけを書くと、残りに文脈を導入する（文脈の導入の節）。
文書順で最初の頭キーがそのマッピングに文脈を導入し、そのキーを除いた**残り**が本体である。
残りは次のいずれかである。

- `$in` ただ一つ。その値が本体の式である。
- データのマッピング。
- 主形。
- 再び文脈の導入を伴うマッピング。

残りがこのどれでもないマッピングはエラーである（`{$let: 束縛, $in: 式, キー: 値}`）。
`{$let: 束縛}` のように残りが空のマッピングは `$do` の文の位置でだけ書け、残りの文の並びを本体に取る（`$do` の節）。

頭キーどうしの並びは文書順であり、先に書いたものが外側になる。
頭キー以外のキーの位置は意味を持たない。
YAML は一つのマッピングの中の重複キーを許さないので、各頭キーは一つずつしか置けない。

補助キー `$default` はどの `$` 式にも添えられる（`$default` の節）。
`$` 式の形の判定は `$default` を除いてから行う。

### 予約キーとカーネル

ドットを含まない `$` キーは言語が予約する。
予約キーは次の 12 個であり、予約されていないドットなしの名前はエラーになる。

`$do` `$let` `$in` `$if` `$then` `$else` `$fn` `$body` `$for` `$handler` `$resume` `$default`

このうちカーネル、すなわち評価器が意味を直接与える構文は次の 5 形である。

- 参照と式 `${...}`
- 束縛と逐次 `$let`（`$in`）
- 分岐 `$if`（`$then` `$else`）
- 関数 `$fn`（`$body`）と呼び出し
- ハンドラ `$handler`（`$in` `$resume`）

文の並び `$do`、`$fn` に引数名の列を書く形、選択の束縛の頭 `$for`、既定値の補助キー `$default` は**導出形**であり、意味はカーネルへの展開で定める。
`$in` は `$let`、`$for`、`$handler` が本体に使う補助キーである。

`$in` の役割はどの形でも変わらない。
`$in` は常に本体、すなわちその形がスコープを及ぼす計算を導く。
将来加わる形もこの割り当てに従う。

畳み込みの構文はカーネルにない。
構造を回る反復は `std` の関数 `std.collect` が与える（std の節）。

### 名前と環境

文書は**環境**の下で評価される。
環境は名前から値への束縛の列であり、`$let` と `$fn`、および `$handler` のローカル作用の宣言が延ばす。
文書の最外の環境を**初期環境**と呼び、処理系が用意する。
初期環境には、標準の演算と関数を収めたマッピングを値とする束縛 `std` と、ホストが与えた束縛がある（ホストの値の節）。

`$` キーは名前の形で二つに分かれ、解決の優先順位のような暗黙の規則を持たない。

- **ドットを含まない名前 `$名前`**：予約キーである。予約されていない名前はエラーになる。
- **ドットを含む名前 `$パス`**：環境にある値の呼び出しである。パスは名前をドットで繋いだ列で、最初の区画が束縛を解決し、残りの区画があればその値のマッピングを順にキーでたどる。最初の区画が空の `$.名前` は、一区画のパスを予約キーと区別して書く形である。

`$std.each` は束縛 `std` のキー `each` の値の呼び出しであり、`$vault.read` はホストが与えた束縛 `vault` のキー `read` の値の呼び出しであり、`$.f` は束縛 `f` の値の呼び出しである。
三つはすべて同じ規則で解決され、呼び出しの規則も同じである（関数の節、演算とハンドラの節）。
`std` は普通の束縛なので、`$let` で隠せる。
隠したいときは意図してそうする。

パスの最初の区画がどの束縛にも解決しない呼び出しや参照を含む文書は、評価を始める前に `undefined reference` で拒否される。
環境はレキシカルに決まるので、この判定は評価を要しない。
残りの区画がマッピングにないことは、参照ではデータ起因の失敗 `std.fail`、呼び出しでは形の誤りのエラーである（関数の節）。

### 値

値は三種に分かれる。

- **データ**：スカラー、リスト、マッピング。文書の値になれる。
- **関数**：`$fn` が作る閉包。呼び出すと本体が走る。
- **演算**：作用の名前を持つ値。呼び出すと作用を起こし、包囲する最も近いハンドラの節が引数を受け取る。

演算の値を作るのは、初期環境（`std` とホストの値）と `$handler` のローカル作用の宣言だけである。
ハンドラは値の種類ではない。
ハンドラを立てるのは構文 `$handler` であり、再利用するハンドラは本体の閉包を受け取る関数として書く（`$handler` の節）。

関数と演算は文書の中でだけ意味を持つ。
どちらかが作用境界の外へ出て文書の値に残ることはエラーである。
関数と演算を `==` で比較することもエラーである。

### 作用境界

データの中に現れた最も外側の `$` 式を**作用境界**と呼ぶ。
境界の内側で演算が起こす作用は、途中にハンドラがなければ境界まで伝播し、そこで処理系の**既定ハンドラ**が処理する（作用の推論の節）。
入れ子の `$` 式は境界にならないので、`$do` の中の `$do` は単なるグループ化である。

演算は `$` 式の引数の中であればどこにでも置ける。
たとえば文 `- [1, {$std.each: [a, b]}]` はリストの要素の位置で選択を行うので、外側のブロック全体が 2 通りに分岐する。

境界が互いに独立であることには意味がある。
兄弟関係にある二つの境界は作用を共有しないので、データ部分の評価は順序に依存しない。
複数の場所で状態や選択を共有したければ、その範囲全体を一つの `$do` で包み、単一の境界にする。

### 作用の推論

作用は演算の値で数える。
処理系は評価の前に、関数値の流れの検査（次節）と同じ近似で、各呼び出しの位置に流れうる演算の値を求める。
各ノードの**作用集合**は、その内側の呼び出しに流れうる演算を合併し、ハンドラが節に挙げた演算を除いて、節と `return` の本体の作用を加えたものである。
出現だけを見るので、実行されない分岐の演算も作用に数える。
導出形は展開してから数える（`$for` の出現は `std.each` を加え、`$default` の出現は本体の `std.fail` を除いて既定値の式の作用を加える）。
欠落しうるパスアクセスと、失敗を通知しうるホストの値の呼び出しは `std.fail` を加える。
これにより、文書が要求するハンドラの一覧（作用シグネチャ）が実行前に定まる。

境界に達した作用は、処理系が文書を std の既定ハンドラの系列で包んだものとして処理される。
系列は外側から失敗、パラメータ、ログ、状態の順である。

- **失敗**：捕捉されずに届いた `std.fail` は、その値をメッセージとして文書全体のエラーになる。
- **パラメータ**：`std.param` は起動時に与えられたパラメータ表を読む。
- **ログ**：`std.log` は値をホストのログ出力に流す。
- **状態**：暗黙の `$handler: {$std.state: {}}` が置かれる。境界にあるので文書内のどの選択のハンドラよりも外側であり、状態は分岐をまたいで文書順に貫流する。この振る舞いを変えたいときは `std.state` を明示的に置く。

ホストが与えた演算には、ホストの実装が既定ハンドラとして付いている。
選択（`std.each`）と、ローカル作用の宣言が作った演算には既定ハンドラがない。
境界へ達した選択は `unhandled choice` のエラーになり、境界へ達したローカル作用は脱出のエラーになる（ハンドラの節）。
選択を値にするのは、それを処理する明示のハンドラ（`std.each` の節を持つ `$handler`、およびそれを立てる `std.list` `std.mapping` `std.first`）だけであり、そのハンドラの形が値の形を決める。

### 関数値の流れと停止性

処理系は評価の前に、関数値と演算の値の流れを文書全体で推論し、自己適用を含みうる文書をエラーとして拒否する。
関数値を作るのは `$fn` だけである。
パラメータとホストの値の呼び出しの結果は常にデータであり、閉包が文書の外から入ってくることはない。
したがって文書に現れる `$fn` は有限個であり、文書内の各位置に現れうる関数値は、実行せずに過大近似できる。
各 `$fn` が見る関数値——パラメータに流れ込みうる値、本体の中の呼び出しの呼び先、本体の中の演算の値（ハンドラの節が返す値、状態のセルを通って戻る値、節の `$resume` で再開される値を含む）——から、構造（マッピング・リスト・分岐）をたどって別の `$fn` に到達しうるとき、前者は後者に依存する。
この依存が循環をなす（自分自身への依存を含む）文書は、評価前にエラーになる。
例外として、`$resume` の結果の適用は依存に数えない。継続の適用はハンドラの畳み込みに沿って必ず停止するからである（`std.state` の展開はこの形である）。
値が関数とデータの間で分岐すること自体は誤りではない。
検査が拒むのは、自己適用が要求する循環だけである。
関数値を状態のセルに置き、読み出して適用する後結び（Landin の knot）も、演算の値の経路として同じ循環に数える。
推論は作用の推論と同じ出現主義であり、実行されない分岐（`$if` の選ばれない側、`$default`）の中の呼び出しも数える。
検査は注釈を要しない。
型を書く構文はなく、予約キーも増えない。
この検査は、`$` キーを含めて文書の構文をそのまま降りる構文パス（例 `config.$let.f`）で位置を報告する。
この検査に通った文書の評価は、停止しないホストの値を与えない限り必ず停止する。

### 合成と境界

作用境界がどこに生じるかを、構文上の位置ごとに三つに分けて定める。

**合成**：`$let` の右辺から後続の束縛と `$in` の本体への流れ、`$do` の文の並び、`$if` の選ばれた分岐、呼び出しの引数と本体、`std.collect` の対象と関数本体、そして境界の内側に現れるデータ構成（リストの要素、`$` キーを持たないマッピングの値）は、境界を作らない。
内側で起きた作用は周囲の計算へそのまま合流する。
データ構成は作用を起こさないが、遮りもしない。
文 `- [1, {$std.each: [a, b]}]` が外側のブロック全体を 2 通りに分岐させ、選択のハンドラの下で `[1, a]` と `[1, b]` の 2 分岐になるのはこのためであり、`$let` の右辺に `$std.each` を書くと包囲する逐次の全体が分岐するのも、関数呼び出しの作用が「引数の作用と本体の作用の合併」になるのも同じ理由による。

**部分処理**：ハンドラが処理する範囲は、そのハンドラが節に挙げた演算だけを取り除く。
それ以外の作用はそのまま透過し、ハンドラ自身の値へ合流する。
既定の状態（貫流）が選択をまたぐのは、既定の状態ハンドラが境界にあり、文書内のどの選択のハンドラよりも外側だからである。

**境界**：作用境界の節で定めたとおり、データの中に現れた最も外側の `$` 式と、文書全体だけが境界である。
境界に達した計算は、残るすべての作用を既定ハンドラの系列で処理し尽くしてから、初めて具体的な値になる。
境界の内側には、明示のハンドラを除いて作用を堰き止める場所はない。

`$if` は合成なので、選ばれた分岐の選択だけが周囲へ合流する。
`$then` にだけ選択が現れる `$if` は、`$else` 側が選ばれれば選択を起こさない。

**引数の評価順**：呼び出しは、引数を評価してから、関数なら本体の評価に、演算なら作用に進む（値渡し）。
引数の評価で起きた作用は堰き止められず、周囲へ合流する。
`{$.f: {$std.each: [1, 2]}}` は、引数の選択が周囲へ合流するので、f の呼び出しごと分岐する（f が 1 回で `[1, 2]` を受け取るのではない）。
本体を評価する前にハンドラを立てたいときは、値渡しの呼び出しではなく `$handler` の `$in` に本体を書く。
`$default` の式は例外で、`$if` の分岐と同じ**遅延位置**である。
本体が失敗しなければ `$default` は評価されず、その作用も起きない。
作用の推論は出現主義なので、評価されない場合でも `$default` の中の演算は作用集合に数える（`$if` の選ばれない分岐と同じ扱い）。

## 参照と式

**参照**：`${式}` は文字列の中に式の値を埋め込む。
文字列全体が一つの `${式}` であるときは値そのもの（型を問わない）になり、それ以外のときは値を文字列化して埋め込む。
リストとマッピングと null と関数と演算の文字列化はエラーである。

参照が解決するのは環境の束縛だけである。
`${std.list}` のように `std` の値を参照して、関数や演算の値を取り出せる。
パラメータは `std.param`、状態は `std.get` という演算を通じて読む。
この区別により、作用を起こす読み出しは必ず演算として紙面に現れる。

**パスの部分性**：`${x}` のような裸の参照は純粋である。
`${x.y}` や `${xs[0]}` のようにパスをたどる参照は、キーや添字が存在しないとき失敗作用 `std.fail` を起こす。
失敗はハンドラで捕捉でき、捕捉しなければ境界で文書全体のエラーになる。
一方、束縛名そのものが未定義であること、マッピングでない値のキーをたどること、型の不一致は、データではなく文書の形の誤りなので、捕捉できないエラーのままである。
作用の推論では、パスをたどる参照の出現が `std.fail` を作用集合に加える。

`${}` の中に YAML 構造（呼び出しなど）を書くことはできない（理由は[設計の経緯](history.md)）。
演算の結果を式で使うには、`$let` で名前を付けてから参照する。

YAML の規則上、`[...]` や `{...}` のフロー形式の中では `${x}` を含むスカラーに引用符が必要になる[^2]。
ブロック形式ではそのまま書ける。
本仕様の用例は、参照を含む箇所をブロック形式で書くことでこれを避けている。

[^2]: フロー文脈のプレーンスカラーは `{` などのフロー指示子を含められない（YAML 1.2 の ns-plain-safe(flow)）。これは本言語ではなく YAML 自体の制約である。

**エスケープ**：文字列とキーの中の `$$` は literal な `$` 一文字になる。
たとえば値 `"costs $$5"` は `costs $5` に、キー `$$do` は literal なキー `$do` に評価される。
`$` 式かどうかの判定は補間より前に、書かれたままのキーに対して行う。

式の文法は次のとおり最小限にとどめる。

```
式      := 論理和
論理和  := 論理積 ("||" 論理積)*
論理積  := 否定 ("&&" 否定)*
否定    := "!" 否定 | 比較
比較    := 加算 (("==" | "!=" | "<" | "<=" | ">" | ">=") 加算)?
加算    := 乗算 (("+" | "-") 乗算)*
乗算    := 単項 (("*" | "/" | "%") 単項)*
単項    := 数値 | '文字列' | true | false | null | 参照名 | "(" 式 ")"
参照名  := 名前 ("." 名前 | "[" 自然数 "]")*
```

- 比較 `==` と `!=` は値の構造的な等価性を判定する。大小比較と算術は数値だけに定義され、それ以外の型に適用するとエラーになる。
- `&&` と `||` と `!` の被演算子、および `$if` と `std.where` の条件は真偽値でなければならない。真偽値への暗黙の変換は行わない。
- `.名前` はマッピングのキーを、`[自然数]` はリストの 0 起点の添字を参照する。存在しないキーや添字は `std.fail` を起こす。
- 0 除算はエラーになる。文字列の連結は補間で書く。

式にはリストとマッピングのリテラルがない。
空リストとの比較が必要なときは、`$let` で `empty: []` のように名前を付けてから `${xs == empty}` と書く。

## 束縛と制御

`$let` と `$if` は作用を持たない構文である。
文の並び `$do` と選択の束縛の頭 `$for` はカーネルへの展開で定まる導出形であり、本節で併せて定める。
文脈の導入も本節で定める。

### $let

```yaml
$let:
  x: 式1
  y: 式2
$in: 本体の式
```

`$let` は逐次のカーネル構文である。
右辺を文書順に評価し、その値を名前に束縛して、`$in` の本体を評価する。
本体の値が全体の値であり、束縛は本体から `${x}` で参照できる。
この評価の規則は関数呼び出しの規則（関数の節）と同一である。
右辺は引数と同じく値渡しで評価され、本体はレキシカルスコープで評価され、作用は右辺と本体の合併である。
すなわち `$let` は無名関数の即時適用と同じ意味を持つが、名前を経ない適用を書く形が無いので、導出形ではなくカーネルに置く。
後の束縛の右辺からは先の束縛を参照できる。
同じ名前の再束縛は許され、外側の束縛を隠す。
束縛名にドットは使えない。パスの区切りと衝突するからである。
`$in` を省いて束縛だけを書いた `{$let: 束縛}` は、残りに文脈を導入する（文脈の導入の節）。

`$let` は非再帰であり、右辺から自分自身や後の束縛は見えない。

右辺の評価は作用を起こしてよい。
`x: {$std.each: [a, b, c]}` は「a、b、c のそれぞれを x として」と読める。
束縛が作用を起こすかどうかは、右辺に呼び出しが見えるかどうかと一致する。

右辺が作用を起こす場合、束縛を書く順序は意味を持つ。
とりわけ、`$std.each` より前に書いた `$std.get` は分岐する前に一度だけ実行され、全分岐が同じ値を見る。
`$std.each` より後に書けば分岐ごとに実行される。

値を捨てて作用だけを残したい右辺は、`_` のような参照しない名前に束縛する慣用で書く。
`_` はただの束縛名であり、言語は特別扱いしない。
YAML は一つのマッピングの中の重複キーを許さないので、捨てる文が二つ以上あるときは名前を変えるか、`$do` で書く。

### $do

```yaml
$do:
- 文1
- 文2
- 結果式
```

`$do` は直下のリストを文の並びとして先頭から評価し、最後の文の値を全体の値とする。
これが「リストはデータ」の唯一の例外である。
空の `$do` の値は null である。

文には任意の式のほか、文脈の導入（文脈の導入の節）と呼び出しを置く。
最後の文を除き、文の値は捨てられる。
`std.where` と `std.set` と `std.log` の値は null であり、この位置に置くのがなじむ。
YAML には unit 型がないため、値を返さないことを表すには null を unit の代用とする。

`$do` は導出形であり、意味は次の展開で定める。
規則は上から順に、最初に一致したものを適用する。
私的名は文書から参照できない捨て名である。

```
{$do: []}                            ≡ null
{$do: [{$let: 束縛}, 残り...]}       ≡ {$let: 束縛, $in: {$do: [残り...]}}
{$do: [{$for: 束縛}, 残り...]}       ≡ {$for: 束縛, $in: {$do: [残り...]}}
{$do: [{$handler: 式}, 残り...]}     ≡ {$handler: 式, $in: {$do: [残り...]}}
{$do: [結果]}                        ≡ 結果
{$do: [文, 残り...]}                 ≡ {$let: {私的名: 文}, $in: {$do: [残り...]}}
```

展開により、`$in` を省いた `$let`・`$for`・`$handler` が残りの文に文脈を導入することと、途中の文の値が捨てられることが定まる。
文脈として導入される `$let` の束縛と、`$handler` のローカル作用の宣言（ハンドラの節）の束縛は、本体すなわち残りの文から参照できる。
先に文脈を導入した `$handler` ほど外側のハンドラになる。
ハンドラを重ねたいときはこの形で書く。
最後の文で導入した文脈の本体は `{$do: []}` すなわち null である。
文の並び替えが意味を変えるのは、`$let` の束縛順と同じ理由である。

### 文脈の導入

`$let`、`$for`、`$handler` は、頭と `$in` の二つのキーで書く `$` 式である。
頭は形ごとのキーに、本体は `$in` に書く。

| 形 | 頭 | 本体 |
|---|---|---|
| `$let` | 束縛（キー `$let`） | `$in` |
| `$for` | 選択の束縛（キー `$for`） | `$in` |
| `$handler` | 節または関数の式（キー `$handler`） | `$in` |

頭は本体を評価する文脈、すなわち本体の前提を定める。
`$let` は束縛を、`$for` は選択の束縛を、`$handler` は作用の処理を、本体の文脈に加える。
`$in` を省いて頭だけを書くと、その頭は、それを置いた並びの残りに文脈を導入する。

**文脈の導入は、それを置いた並びの残りを本体に取る。**
`$do` の文として置けば、残りの文の並び `{$do: [残り...]}` が本体になる。
マッピングのキーとして置けば、残りのキーからなるマッピングが本体になり、残りが `$in` ただ一つならその値が本体になる。
残りを持たない頭は本体を欠くので、単体では式にならない（構文の節）。

文脈の導入を伴うマッピングの展開は頭ごとに一段である。
本体式は、残りが `{$in: 式}` ならその式、そうでなければ残りのマッピングである。

```
{$let: 束縛} ∪ 残り     ≡ {$let: 束縛, $in: 本体式}
{$for: 束縛} ∪ 残り     ≡ {$for: 束縛, $in: 本体式}
{$handler: 式} ∪ 残り   ≡ {$handler: 式, $in: 本体式}
```

残りが `$in` ただ一つなら、この展開は恒等である。
`{$let: 束縛, $handler: 式, $in: 本体}` は `{$let: 束縛, $in: {$handler: 式, $in: 本体}}` と等価であり、`$in` は最後の頭の本体になる。
スカラーやリストを本体にするときは `$in` に書く。
頭を交互に重ねたいときは `$do` で書く。

残りが主形であってもよい。
`{$fn: x, $let: 束縛, $body: 式}` の `$let` は `$fn` 全体を包むので、束縛は関数の外で一度だけ評価され、`x` は束縛の右辺から見えない。

頭は自分の値を持たず本体の値をそのまま返すので、残りを本体にしても値は失われない。
`std.where` や `std.log` は頭にならず、値を捨てる文は `$do` の役目である。

文脈の導入を伴うマッピングは `$` キーを持つので `$` 式である。
データの位置に置けば全体が一つの作用境界になり、合成の位置に置けば周囲の計算に合流する。
文脈として導入される `$let` の束縛と、`$handler` のローカル作用の宣言の束縛は、本体すなわち残りから参照できる。
先に書いた頭の束縛は、後の頭の `$for` の右辺と `$handler` の式からも見える。

### $if

```yaml
$if: 条件式
$then: 式
$else: 式
```

`$if` は条件の値に応じて `$then` か `$else` の一方だけを評価する。
`$else` は省略できない。
条件が真偽値でなければエラーになる。

### $for

```yaml
$for:
  x: 式1
  y: 式2
$in: 本体の式
```

`$for` は選択の束縛を導入する頭である。
右辺の値の要素を一つずつ選び、選ばれた要素を名前に束縛して本体を評価する。
導出形であり、意味は次の展開で定める。

```
{$for: {x1: 式1, ..., xn: 式n}} ∪ 残り ≡ {$let: {x1: {$std.each: 式1}, ..., xn: {$std.each: 式n}}} ∪ 残り
{$do: [{$for: 束縛}, 残り...]}         ≡ {$for: 束縛, $in: {$do: [残り...]}}
```

`x: [a, b, c]` は「a、b、c のそれぞれを x として」と読める。
展開の `$std.each` は展開先の環境で解決するので、`std` を隠せば `$for` もそれに従う。
束縛は `$let` の束縛なので、右辺は文書順に評価され、後の束縛の右辺からは先の束縛を参照できる。
束縛名にドットは使えない（`$let` と同じ）。
本体は `$in` に書き、`$in` を省けば残りに文脈を導入する（文脈の導入の節）。
残りを持たない `{$for: 束縛}` は `$do` の文の位置でだけ書ける。
他の頭と同じマッピングに並べたときの内外は文書順である。
`$let` で束縛したデータの要素を `$for` で選ぶので、`$let` を先に書く並びが普通である。
作用集合への寄与も展開のとおり `std.each` である。
選択に意味を与えるのは、展開に現れる `std.each` を処理する包囲するハンドラ（`std.list`、`std.mapping`、`std.first`、または `std.each` の節を持つ `$handler`）であり、そのハンドラの形が値の形を決める。

## 関数

### $fn

```yaml
$fn: パラメータ名
$body: 式
```

`$fn` は関数の値を作る。
評価すると、定義位置の束縛を捕まえた**閉包**になる。
閉包が境界の外へ出て文書の値に残ることはエラーである。

カーネルの関数はパラメータをちょうど一つに固定する。
複数の値を渡すときはマッピングで一つに包み、本体から `${arg.名前}` のようにパスで参照する。

#### 引数名の列と部分適用

`$fn` には相異なる名前の列（1 個以上）も書ける。
この形は導出形であり、意味はカリー化の展開で定める。

```
{$fn: [a, b, ...残り], $body: 本体} ≡ {$fn: a, $body: {$fn: [b, ...残り], $body: 本体}}
{$fn: [a], $body: 本体}            ≡ {$fn: a, $body: 本体}
```

展開の各段は一引数のカーネル関数なので、一つ固定の原則は崩れない。
**部分適用**は通常の適用そのものである。
先頭の引数だけを与える呼び出しは、残りの引数を待つ閉包を値として返す。

```yaml
$let:
  add:
    $fn: [a, b]
    $body: ${a + b}
  succ:
    $.add: 1
$in:
  $.succ: 41
```

適用の規則は一引数の関数と同じである。
引数の式はその適用の位置で正格に評価され、値が閉包に捕まり、再評価されない。
したがって引数の式の作用は部分適用の位置で一度だけ生じ、本体の作用は最後の引数が与えられて本体が走る位置で生じる。

空の列、文字列でない要素、名前の重複は形の誤りでありエラーになる。
全引数を与えないまま閉包が文書の値に残れば、関数値の脱出のエラーになる。
ハンドラの節と `std.collect` の関数は処理系が一引数で呼ぶ位置なので、そこに引数 2 個以上の `$fn` を書くと閉包が結果の値になり、多くの場合そのまま脱出のエラーへ至る。

### 呼び出し

呼び出しは `{$パス: 引数}` の形で書く。
パスは環境で解決され、たどり着いた値が関数なら関数の呼び出し、演算なら演算の呼び出しになる（名前と環境の節）。
データにたどり着けばエラーである。

関数の呼び出しは、引数を評価してからパラメータに束縛し、本体を定義位置の環境で評価する（レキシカルスコープ）。
呼び出しの作用は、引数の作用と本体の作用の合併である。
関数の本体に現れる演算は、その関数がどの位置から呼ばれるかによらず作用シグネチャに数えられる。
本体が選択を起こす関数は、呼び出しの経路が実行時に決まる場合も含めて、選択を処理するハンドラの内側で呼ぶ。

パスの解決は文書の形に関わるので、残りの区画がマッピングにないことは失敗作用ではなくエラーの語彙（`cannot access key`、`missing key`）で報告する。
添字 `[0]` はパスでは書けない。
添字の先や、計算した式の先にある関数は、`$let` で名前に束縛してから `$.名前` で呼ぶ。
`${x}` の参照は呼び出しではないので、この規則の対象外である。

**`$.return` の予約**：最初の区画が `return` である呼び出し（`$.return.x` のような形を含む）は形の誤りであり、処理系はその出現を評価前に `return is reserved: $.return is not callable` で拒否する。
`return` はハンドラの節名として予約されているので、`$handler` に書いた `return` はローカル作用の宣言ではなく、束縛を導入しない。
したがってこの形の呼び出しは決して解決しない。
`$let` や `$fn` が `return` という名前に束縛すること自体は妨げず、`${return}` の参照も通常どおり解決する。
拒むのは `$.return` という呼び出しの形だけである。

`$let` が非再帰なので、名前による再帰は書けない。
反復は `$for` と `std.collect` のようにデータ構造に沿った形で書く。
関数値の自己適用は構文では排除できないが、評価前の関数値の流れの検査が拒否する（評価モデルの「関数値の流れと停止性」）。
言語は fix に相当する原始を提供しない。

## 演算とハンドラ

### 演算

演算は作用の名前を持つ値である。
呼び出し `{$パス: 引数}` のパスが演算に解決すると、引数を評価してから、その演算の作用を起こす。
作用は、包囲する最も近いハンドラのうち、その演算の節を持つものが処理する。
どのハンドラも持たなければ境界の既定ハンドラが処理する（作用の推論の節）。

演算の値そのものは引数に何も要求しない。
引数の形（`std.each` にはリストかマッピング、`std.set` にはマッピング）は、標準のハンドラがその節で課す約束であり、利用者のハンドラが同じ演算を処理するときは、その節が引数をそのまま受け取る。

演算の値を得る経路は三つあり、どれも同じ種類の値である。

- `std` が最初から持つ演算（`std.each` など）。
- ホストが初期環境に与えた演算。ホストの実装が既定ハンドラとして付いている。
- `$handler` のローカル作用の宣言が作った演算。既定ハンドラはなく、境界に達すれば脱出のエラーになる。

`${std.each}` のように演算の値を参照して、束縛したり、マッピングに入れたり、関数に渡したりできる。
別名を経た呼び出しも同じ演算の作用を起こす。

### $handler

```yaml
$handler:
  演算名:
    $fn: 引数名
    $body: 節の本体
  return:
    $fn: 値名
    $body: 式
$in: 本体の式
```

`$handler` はハンドラを立てるカーネル構文である。
頭のキー `$handler` に節を書き、その下で `$in` の本体を評価する。
`$in` を省いて頭だけを書いた `{$handler: 節}` は、残りに文脈を導入する（文脈の導入の節）。

`$handler` の式は、literal な**節のマッピング**か、関数に評価される式のどちらかである。
節のマッピングは `$` で始まらないキーだけからなるマッピングであり、キーが節の名前、値が節の関数である。
それ以外の式（`${std.list}` のような参照、`{$std.state: {n: 0}}` のような `$` 式）は評価して関数を得なければならず、その形の意味は次の展開で定める（ハンドラの再利用の節）。

```
{$handler: 関数の式, $in: 本体} ≡ {$let: {私的名: 関数の式}, $in: {$.私的名: {$fn: 捨て名, $body: 本体}}}
```

以下は節のマッピングを書いた形について定める。
節の名前は `$handler` の位置の環境で解決する。

| 節の名前 | 意味 |
|---|---|
| `return` | return 節 |
| ドットを含む名前（`std.each`） | パスとして解決した演算の節 |
| 先頭がドットの名前（`.sig`） | 一区画のパスとして解決した演算の節（束縛 `sig` の値） |
| ドットを含まない名前（`throw`） | ローカル作用の宣言（ローカル作用の宣言の節） |

解決先が演算でなければエラーである。
節の値は一引数の関数でなければならない。

**節の起動**：本体の中で、節を持つ演算が呼ばれると、対応する節が演算の引数を受け取って評価される。

- 節の本体では `{$resume: 値}` で継続を再開できる。その値は、演算の呼び出し位置に「値」を返して残りの計算（`return` 節を含む）を進めた結果である。
- `$resume` は節の本体の中でだけ書ける。節の本体に書いた `$fn` の本体も含み、その閉包が捕まえるのはその節の起動に対応する継続である。節の本体の外（その `$handler` の `return` 節、その `$handler` の本体、`$handler` の外にある関数の本体）に書いた `$resume` は形の誤りであり、評価前に拒まれる。範囲は字句で決まるので、節の本体の中に入れ子にした `$handler` の本体と `return` 節からは、外側の節の継続が見える。一度も呼ばない（打ち切り）ことも、複数回呼ぶことも許される。
- 節が `$resume` を呼ばずに値に達したときは、その値がその節の起動の値になる（打ち切り）。起動が本体から直接起きたのなら、それがハンドラ全体の値である。別の節が呼んだ `$resume` の継続の中で起きたのなら、それがその `$resume` の値であり、呼んだ節の本体はそこから続く（`std.first` の展開はこの規則で失敗した分岐を飛ばす）。
- ハンドラは深い。再開後の計算にも同じハンドラが効き続ける。
- 節の本体が起こす作用は、このハンドラ自身ではなく外側で処理される。
- `return` 節は、本体が演算を起こさず値に達したときにその値を変換する。省略時は恒等である。

作用の推論では、`$handler` の節が挙げた演算が集合から除かれ、節と `return` の本体の作用が加わる。

#### ハンドラの再利用

再利用するハンドラは、本体の閉包を受け取る関数として書く。

```yaml
$let:
  fallback:
    $fn: run
    $body:
      $handler:
        std.fail: {$fn: _, $body: 0}
      $in: {$.run: null}
$in:
  a:
    $handler: ${fallback}
    $in: {$std.lookup: {in: {}, key: missing}}
  b:
    $handler: ${fallback}
    $in: 7
```

```yaml
a: 0
b: 7
```

`$handler: ${fallback}` は展開により `{$.fallback: {$fn: 捨て名, $body: 本体}}` であり、`fallback` は受け取った閉包を節のマッピングの下で呼ぶ。
本体を閉包で渡すのは、呼び出しが値渡しだからである。
`{$.fallback: 本体}` と書けば本体の作用は引数の評価で周囲へ合流し、`fallback` の節には届かない。
`$handler` と `$in` はカーネルにある唯一の遅延位置であり、本体の閉包化はここで済むので、言語の他の位置は値渡しのままでよい。

`std.list`・`std.mapping`・`std.first`・`std.state` の値はこの形の関数であり（std の節）、`$handler: ${std.list}` と `{$std.list: {$fn: 捨て名, $body: 本体}}` は同じ意味である。
引数で節を調整するハンドラは、カリー化した関数で書き、`$handler: {$.orElse: 0}` のように部分適用の呼び出しを式に置く（用例の節）。
関数の式で与えたハンドラはローカル作用の宣言を持たない。

関数値の流れの検査は、本体の閉包を受け取る関数を、その閉包の本体の中で再び使う形を自己適用として拒む。
`std` の関数はホストの値であり `$fn` ではないので、`std.list` の中に `std.list` を重ねることはこの制限を受けない。

#### ローカル作用の宣言

`$handler` に節のマッピングを書いたとき、ドットを含まない節の名前（`return` を除く）は、そのハンドラだけが処理するローカルな作用を宣言する。

```yaml
$handler:
  throw: 節
$in: 本体
```

宣言は、`$handler` を評価するたびに新しい演算の値を作り、その節を置き、本体に名前を束縛する。
本体は `{$.throw: 引数}` でその演算を呼び、節が引数を受け取る。
`$let` が値を束縛して `$.名前` で呼ぶのと同じ読み方が `$handler` にも通り、利用者は名前空間を書かずに自分の作用を宣言できる。
名前空間つきの演算が要るのは、std とホストと文書間の約束、すなわち外の世界が関与する場所だけである。

規則は次のとおりである。

- 宣言は節のマッピングのキーとしてだけ書ける。関数の式で与えた `$handler` は宣言を持たない。束縛を導入するのは構文の仕事であり、値は束縛を導入できない。
- 束縛が見えるのは本体だけである。同じ `$handler` の節の本体、`return` 節、ハンドラの外側からは見えない。
- `$in` を省いた `$handler` では、残りが本体にあたる。束縛はそこから見える（`$let` と同じスコープ規則）。
- 演算の値は宣言ごとに、評価のたびに作られる。別のハンドラが同じ `throw` を宣言していても値は別なので、束縛を経た呼び出しは必ず宣言元のハンドラに届く。偶然の捕捉は起こらない。同じ `$handler` が二度評価されれば、二つの起動は別の演算を持つ。
- 束縛は普通の束縛である。同じ名前の再束縛で隠せるし、`${throw}` で参照して別名を付けられるし、値として文書の外に残せば脱出のエラーになる。
- 宣言した演算をハンドラの外へ持ち出し、別の `$handler` で処理してよい。そのハンドラの節の名前は `.throw` のように書き、束縛を経て同じ演算に解決する。
- 名前空間つきの節や `return` との混在も、一つの `$handler` に複数の宣言を書くことも許される。

作用の推論では、宣言が作る演算の呼び出しはその演算を作用集合に加え、宣言したハンドラがそれを除く。
演算の値が持ち出されて別の位置で呼ばれうることは、関数値の流れと同じ推論で数える。
それでも実行時に、どのハンドラにも捕まらずに境界へ達したローカル作用は、`local effect 'throw' escaped its handler (declared at 宣言位置)` のエラーとして報告する。
宣言位置は、宣言を書いた `$handler` の構文パスである。

```yaml
$handler:
  throw:
    $fn: msg
    $body: caught ${msg}
$in:
  $do:
  - {$.throw: boom}
  - never
```

```yaml
caught boom
```

節が `$resume` を呼ばないので、`$.throw` の呼び出しで本体が打ち切られ、節の値がハンドラ全体の値になる。
`std.fail` の節を持つ `$handler` と同じ形を、名前空間を持たない自前の作用で書いたものである。

入れ子のハンドラが同じ名前を宣言しても、演算の値が別なので取り違えは起こらない。

```yaml
$handler:
  throw:
    $fn: m
    $body:
      $resume: outer ${m}
$in:
  $do:
  - $let:
      up: ${throw}
  - $handler:
      throw:
        $fn: m
        $body:
          $resume: inner ${m}
    a: {$.throw: x}
    b: {$.up: y}
```

```yaml
a: inner x
b: outer y
```

内側の本体で `$.throw` が指すのは内側の宣言なので、`a` は内側の節が受ける。
`up` は外側の宣言が束縛した演算の別名であり、内側のハンドラの中で呼んでも別の演算なので、内側の節を素通しして外側の節に届く。
どちらの節も `$resume` で再開するため、残りの計算は同じ二つのハンドラの下で続く。

### $default

```yaml
$std.param: 名前
$default: 式
```

`$default` は、どの `$` 式にも添えられる補助キーである。
本体が `std.fail` を起こしたとき、その式の値を代わりにする。
導出形であり、意味は次の展開で定める。
私的名は文書から参照できない捨て名である。

```
{主形 ∪ {$default: 式}} ≡ {$handler: {std.fail: {$fn: 私的名, $body: 式}}, $in: 主形}
```

`$default` を除いた残りが `$` 式全体であり、文脈の導入を伴うマッピングに添えれば、その頭と本体をまとめて包む。
節が `$resume` を呼ばずに式へ達するので、失敗した時点で本体は打ち切られ、既定値がハンドラ全体の値になる。
`$default` は遅延位置であり、本体が失敗したときだけ評価される（引数の評価順の節）。
展開により `$default` の式は `std.fail` の節の本体なので、そこに書いた `$resume` は失敗した位置から本体を再開する。

`$default` は値を返す式に限らず、作用を起こす式でもよい。
失敗した分岐を包囲する選択から黙って外す定型は次の形である。

```yaml
$std.lookup: {in: "${row}", key: code}
$default: {$std.where: false}
```

展開では `$default` の式が `std.fail` の節の本体になるので、その打ち切り（`std.where` が起こす `std.each`）はこの `$handler` 自身ではなく外側で処理され、包囲する選択の分岐ごと打ち切られる。
失敗しうる式を要素とみなして選択に流し込むときの標準形であり、欠落したキーを持つデータを黙って除外する用途に使う。
打ち切りは選択なので、この形は選択のハンドラの内側で使う。

## std

`std` は初期環境の束縛であり、値は標準の演算と関数を収めたマッピングである。
ホストは `std` の中に値を加えられない。

| 名前 | 種類 | 意味 |
|---|---|---|
| `std.each` | 演算 | 要素を一つずつ選ぶ。値は選ばれた要素。 |
| `std.param` | 演算 | 起動時に与えられたパラメータを読む。 |
| `std.get` | 演算 | セルの現在値を読む。 |
| `std.set` | 演算 | セルに値を書く。値は null。 |
| `std.log` | 演算 | 値をログに流す。値は null。 |
| `std.fail` | 演算 | 計算を失敗させる。値をエラーメッセージとする。 |
| `std.where` | 関数 | 条件を満たさない分岐を打ち切る。 |
| `std.range` | 関数 | 自然数 n をリスト `[0, ..., n-1]` に変える。 |
| `std.collect` | 関数 | 構造を回り、要素ごとの結果を一つの構造に組み立てる。 |
| `std.lookup` | 関数 | マッピングを計算したキーで引く。 |
| `std.merge` | 関数 | マッピングのリストを一つに重ねる。 |
| `std.list` | 関数 | 本体の閉包を受け取り、全分岐の結果を文書順に並べたリストにする。 |
| `std.mapping` | 関数 | 本体の閉包を受け取り、全分岐の `{key, value}` を集めたマッピングにする。 |
| `std.first` | 関数 | 本体の閉包を受け取り、失敗しなかった最初の分岐の値にする。 |
| `std.state` | 関数 | 初期値と本体の閉包を受け取り、状態のハンドラの下で本体を評価する。 |

関数の意味論は展開が定める。
本体の閉包を受け取る四つの関数は `$handler` の式に置く形で使う（ハンドラの再利用の節）。
処理系は等価な組み込みで最適化してよいが、観測できる振る舞い（値、作用、ログの順序）は展開と一致しなければならない。
展開の中で起きる作用は、展開が名指すハンドラが処理し尽くすので、外へは出ない。
展開の中から境界へ達した作用のエラー文言は、展開の内側ではなく、利用者が書いた呼び出しの形と位置を名乗る。

### 演算

作用を起こす標準の演算は 6 つである。
その意味は、既定ハンドラ（作用の推論の節）と標準のハンドラの節が与える。

- `std.each` の引数がリストなら各要素を、マッピングなら各エントリを `{key: キー, value: 値}` の形で、文書順に選ぶ。`$std.each: ${xs}` のようにデータ駆動の反復が書ける。空のリストやマッピングは分岐 0 本を意味し、その分岐は打ち切りになる。選ばれた要素に名前を付けるのは頭 `$for` である。
- `std.param` の引数は名前の文字列である。渡されていないパラメータの読み出しは、呼び出し位置で `std.fail` を起こす。既定値を添えるには `$default` を使う。
- `std.get` の名前空間は `$let` の束縛とは別である。同名でも互いに関係しない。未初期化のセルの読み出しは `std.fail` を起こす。この失敗は `std.state` の展開の節の本体で起こるので、そのセルを解決する状態ハンドラの位置で生じる。暗黙の既定状態は境界にあるため、文書内で捕捉するには、明示の `std.state` を捕捉するハンドラの内側に置く。
- `std.set` は複数のセルを文書順に書ける。
- `std.log` の既定ハンドラは値をホストのログ出力に流す。
- `std.fail` の既定ハンドラは値をメッセージとして文書全体のエラーにする。

### 関数

**std.where** は条件を満たさない分岐を打ち切る。

```yaml
$std.where: 条件式
```

```yaml
# std.where の値
$fn: cond
$body:
  $if: ${cond}
  $then: null
  $else: {$std.each: []}
```

条件が真なら値は null である。
偽なら空の `$std.each` が分岐 0 本の選択となり、包囲する選択のこの分岐が打ち切られる。
条件が真偽値でなければエラーになる。
打ち切りを処理するのは、展開に現れる `std.each` を処理する選択のハンドラである。
作用集合への寄与も展開のとおり `std.each` である。

**std.range** は自然数 n をリスト `[0, 1, ..., n-1]` に変える。
数から構造への唯一の橋であり、回数の上界つきの反復に使う。
引数が自然数でなければエラーになる。
導出できないが評価器の協力も要らないので、値から値への規則で定める。
回数の上界つきの unfold（種と関数からの列の生成）は、`std.range` と `std.collect` と `std.state` で書ける（用例の節）。
上界の代わりに述語で止める unfold は while ループそのものであり、fix と同じ強さを持つので提供しない。

**std.collect** は畳み込みである。
構造を先頭から回りながら、要素ごとの結果を一つの構造に組み立てる。

```yaml
$std.collect:
  in: 対象の式
  with: 一引数関数の式
  into: list または mapping   # 省略時 list
```

- 対象はリストまたはマッピングである。マッピングは `{key: キー, value: 値}` のエントリの列として文書順に回る。
- `with` の関数を各要素に文書順に適用する。関数は要素ごとにリストを返さなければならない。
- `into: list` のとき、全要素の結果リストを文書順に**連結**したリストになる。
- `into: mapping` のとき、結果リストの各要素は `key` と `value` のちょうど二つのキーを持ち `key` が文字列であるマッピングでなければならず、全エントリを集めた一つのマッピングになる。キーの重複はエラーである。
- 空の対象の値は、`into: list` なら空リスト、`into: mapping` なら空マッピングである。

`std.collect` 自身は作用を起こさず、ハンドラで捕捉できない。
作用は引数の式と `with` の関数本体の作用の合併である（関数呼び出しと同じ規則）。
対象が有限である限り適用は有限回なので、`std.collect` は停止性を壊さない。
関数を引数に取るので導出できないが、値から値への規則で定まり、評価器が実装する。

map は要素を一要素リストで包む関数で、filter は空リストを返す分岐で、連結は恒等関数で書ける。
アキュムレータを伴う古典的な fold は、`std.collect` と `std.state` の組で導出できる（用例の節）。

```yaml
# 各要素を二重にする: [1, 1, 2, 2, 3, 3]
$std.collect:
  in: [1, 2, 3]
  with:
    $fn: x
    $body:
    - ${x}
    - ${x}
```

**std.lookup** はマッピングを計算したキーで引く。

```yaml
$std.lookup:
  in: マッピングの式
  key: キーの式
```

式のパス `${m.k}` のキーが literal に限られるのに対し、`std.lookup` はキーを式で与えられる。
意味は選択による照合への展開で定める。

```yaml
# std.lookup の値
$fn: arg
$body:
  $handler: ${std.first}
  $in:
    $do:
    - $for:
        e: ${arg.in}
    - $std.where: ${e.key == arg.key}
    - ${e.value}
```

キーが在ればその値になり、無ければ `std.first` の規則によりこの位置で `std.fail` が起きる。
したがって欠落は、パスアクセスの欠落と同じように `$default` と `$handler` で扱える。
失敗の値の文言だけは展開に委ねず、欠落したキーを含む説明文とする。
`in` の値がマッピングでないことと `key` の値が文字列でないことは、データの変動ではなく形の誤りなのでエラーである（`std.collect` のエントリ検査と同じく契約に含め、展開には現れない）。
作用集合への寄与は `std.fail` と引数の式の作用だけである。

**std.merge** は複数のマッピングを一つに重ねる。

```yaml
$std.merge: マッピングのリストの式
```

同じキーは後のマッピングの値が勝ち、キーの位置は初出の位置が保たれる。
マージは浅い。値がともにマッピングでも再帰せず、後の値がそのまま採られる。
入れ子の階層で重ねたいときは、その階層に `std.merge` を書く。
null は普通の値として上書きする。キーの削除はマージの仕事ではなく、`std.mapping` と `std.where` の省略の慣用で行う。

意味は二項のマージの左畳み込みで定める。
空のリストは `{}` に、`[m1, ..., mn]` は `{}` から始めて m1 から mn までを順に重ねた結果になる。
二項の merge(a, b) の意味は次の展開で定める。

```yaml
# merge(a, b) の展開。b が勝ち、キーの位置は初出の位置。
$let:
  a: 先の式
  b: 後の式
$handler: ${std.mapping}
$in:
  $do:
  - $for:
      phase: [0, 1]
  - $let:
      src:
        $if: ${phase == 0}
        $then: ${a}
        $else: ${b}
  - $for:
      e: ${src}
  - $let:
      fresh:
        $if: ${phase == 0}
        $then: true
        $else:
          $let:
            _:
              $std.lookup:
                in: ${a}
                key: ${e.key}
          $in: false
          $default: true
  - $std.where: ${fresh}
  - key: ${e.key}
    value:
      $if: ${phase == 0}
      $then:
        $std.lookup:
          in: ${b}
          key: ${e.key}
        $default: ${e.value}
      $else: ${e.value}
```

a の側（phase 0）は自分のキーをその位置のまま並べ、b に同じキーが在ればその値で差し替える。
b の側（phase 1）は a に無いキーだけを後ろに足す。
左畳み込みは `std.collect` で要素を回りながら途中結果を `std.state` のセルに持ち回る形で書ける。

マージは結合的で単位は `{}` であり、この性質はキーの並びを含めて成り立つ。
引数がリストでないことと、要素がマッピングでないことは形の誤りなのでエラーである。
`std.mapping` がキーの重複をエラーにするのとは矛盾しない。あちらは新しいマッピングの構成であり重複は誤りの兆候、こちらは重複を優先順位で解決することが目的だからである。
作用集合への寄与は引数の式の作用だけである。

### ハンドラを立てる関数

**std.state** は初期値と本体の閉包を受け取り、状態のハンドラの下で本体を評価する。

```yaml
$handler: {$std.state: {n: 0}}
$in: 本体の式
```

節は状態変換関数、すなわち「現在の状態を受け取り、次の状態への適用を経て最終的な値を返す関数」を返す古典的なパラメータ付きハンドラである。
状態はセルのエントリの列であり、`std.collect` はマッピングもエントリの列として回るので、初期値のマッピングをそのまま最初の状態にできる。

```yaml
# std.state の値
$fn: [init, run]
$body:
  $let:
    step:
      $handler:
        std.get:
          $fn: name
          $body:
            $fn: s
            $body:
              $let:
                hits:
                  $std.collect:
                    in: ${s}
                    with:
                      $fn: e
                      $body:
                        $if: ${e.key == name}
                        $then:
                        - ${e.value}
                        $else: []
                k:
                  $resume: ${hits[0]}
              $in:
                $.k: ${s}
        std.set:
          $fn: m
          $body:
            $fn: s
            $body:
              $let:
                s2:
                  $std.collect:
                    in:
                    - ${m}
                    - ${s}
                    with:
                      $fn: part
                      $body:
                        $std.collect:
                          in: ${part}
                          with:
                            $fn: e
                            $body:
                            - ${e}
                k:
                  $resume: null
              $in:
                $.k: ${s2}
        return:
          $fn: x
          $body:
            $fn: s
            $body: ${x}
      $in: {$.run: null}
  $in:
    $.step: ${init}
```

`std.set` の節は、書かれたマッピングのエントリを列の先頭に足す。
`std.get` の節は名前の一致するエントリを先頭から集めるので、`${hits[0]}` は最新の値になり、セルが未初期化ならちょうど `std.fail` を起こす。
継続の再開結果も状態変換関数なので、それを現在の状態に適用して続行する。
`return` の段で状態を捨てるので、値は本体の値であり最終状態は現れない。
本体をこのハンドラで包んで得た関数 `step` を初期値に適用する。
初期値の式は `std.state` の最初の引数として本体より先に評価される。
`std.state` を選択に対してどこに置くかで、状態と分岐の関係が決まる。

```yaml
# 貫流（既定と同じ）: 状態が分岐から分岐へ持ち越される
$handler: {$std.state: {n: 0}}
$in:
  $handler: ${std.list}
  $in: 選択を含む本体
```

```yaml
# 分岐点で分かれる: 各分岐が選択時点の状態を引き継ぎ、以後は独立に進む
$handler: ${std.list}
$in:
  $handler: {$std.state: {n: 0}}
  $in: 選択を含む本体
```

この区別は、`$in` を省いた `$handler` をどの `$do` の文に置くかでも表現できる。
選択のハンドラを包む `$do` に置けば貫流になり、選択のハンドラの中の `$do` に置けば分岐点で分かれる。

**std.list** は本体の閉包を受け取り、選択を処理して、全分岐の結果を文書順に並べたリストに評価される。

```yaml
# std.list の値
$fn: run
$body:
  $handler:
    std.each:
      $fn: xs
      $body:
        $std.collect:
          in: ${xs}
          with:
            $fn: x
            $body:
              $resume: ${x}
    return:
      $fn: x
      $body:
      - ${x}
  $in: {$.run: null}
```

ハンドラは深いので、各 `$resume` の値は残りの計算を同じハンドラで処理し尽くしたリストであり、`std.collect` がそれらを連結する。
内側に選択がなければ `return` 節だけが働き、要素 1 のリストになる。
`std.where` の打ち切りは、展開により空の `$std.each` として現れ、`std.each` の節が 0 個の候補を畳んで分岐を消す。
分岐の中の失敗は節にないので処理せず、全体の失敗として伝播させる。

**std.mapping** は `std.list` の上の導出であり、集めたエントリの列をマッピングに組み立てる。

```yaml
# std.mapping の値
$fn: run
$body:
  $std.collect:
    in:
      $handler: ${std.list}
      $in: {$.run: null}
    with:
      $fn: e
      $body:
      - ${e}
    into: mapping
```

`std.list` が全分岐の `{key, value}` を文書順のリストに集め、`std.collect` がその各要素をそのまま流しながら `into: mapping` でマッピングへ組み立てる。
エントリの検査（ちょうど二つのキー、`key` は文字列、重複の禁止）は `std.collect` の契約に含まれるので、展開には現れない。
`std.where` で分岐を打ち切れば、条件を満たすエントリだけを持つマッピングが作れる。
これは「null を入れること」と「キーが無いこと」の区別、すなわちキーの条件付き省略を兼ねる。

**std.first** は本体の閉包を受け取り、選択と失敗を処理して、失敗しなかった最初の分岐の値に評価される。
最初の成功より後の分岐は評価されず、その作用も起きない。
すべての分岐が失敗または打ち切りなら、全体が `std.fail` になる。
展開は、成功の印を持ち回る外側の `$handler` と、選択と失敗を処理する内側の `$handler` の二段からなる。
印の持ち回りは、`std.state` と同じ技法を外側の `$handler` が宣言するローカル作用で行うので、本体の `std.get` や `std.set` と衝突しない。
展開は紙面に収まらないので参照文書に置く。

### ホストの値

処理系は、初期環境に束縛を加える手段をホストに与える。
ホストが与える値は演算か関数であり、名前は `vault.read` のように束縛とキーの形で与える。
グローバルな名前空間は言語の予約キーのためにあり、`std` は標準のためにあるので、ホストはそれ以外の束縛名を使う。

```yaml
password: {$vault.read: secret/db/password}
```

- **演算**：呼べば作用を起こす。文書の `$handler` が横取りでき、境界に達したときだけホストの実装が既定ハンドラとして走る。作用シグネチャに数えられる。
- **関数**：呼べばホストの実装が走る。作用ではないのでシグネチャに現れず、横取りもできない。

どちらの実装も、値を返す代わりに失敗を通知できる。
処理系は通知を、呼び出し位置で起きた `std.fail`（値は通知された値）として扱い、通常の規則で伝播させる。
したがって途中の `$default` や `std.fail` の節を持つ `$handler` が捕捉でき、捕捉されなければ文書全体のエラーになる。
失敗の通知はデータ起因の部分性（一致しないセレクタなど）のためにあり、ホスト実装のその他の例外は捕捉できないエラーである。

閉包と演算の値をホストの実装へ渡すことはできない。
処理系はこれを二重に検査する。
ホストの値の呼び出しの引数に閉包が流れうる文書は評価前に拒まれ、実行時にホストへ渡る直前の引数にも同じ検査が働く。
名前が長くなるときは、引数を素通しする `$fn` を `$let` で短い名前に束縛する慣用で書く（用例の演算の部分適用）。

## 用例

### 値だけの文書

```yaml
greeting: hello
```

`$` 式を含まない文書はそれ自身に評価される。
値はそのまま計算の結果である。

### 選択の基本形

```yaml
$handler: ${std.list}
$for:
  x: [a, b, c]
  y: [x, y, z]
$in:
  $std.each:
  - ${x}
  - ${y}
```

`std.list` が全分岐の結果を文書順に並べる。
`$in` の本体も選択なので、分岐は 3 × 3 × 2 の 18 本ある。

```yaml
[a, x, a, y, a, z, b, x, b, y, b, z, c, x, c, y, c, z]
```

`$in` の本体を literal なリストに変えると、意味が「2 つの結果を選ぶ」から「2 要素のリストを返す」に変わる。

```yaml
$handler: ${std.list}
$for:
  x: [a, b, c]
  y: [x, y, z]
$in:
- ${x}
- ${y}
```

```yaml
[[a, x], [a, y], [a, z], [b, x], [b, y], [b, z], [c, x], [c, y], [c, z]]
```

この 2 例の対比が「リストは常にデータ、選択は `$std.each`」という原則の眼目である。

### 打ち切りつきの選択

```yaml
$do:
- $handler: ${std.list}
- $for:
    x: [1, 2, 3]
    y: [1, 2, 3]
- $std.where: ${x < y}
- - ${x}
  - ${y}
```

```yaml
[[1, 2], [1, 3], [2, 3]]
```

リスト内包表記に相当する形である。
文に置いた `$handler` と `$for` が残りの文に文脈を導入し、`$std.where` が条件を満たさない分岐を打ち切る。

### 選択の束縛

形ごとのレーベルの列を、レーベルごとの形に組み替える。

```yaml
$let:
  forms:
    "a{id}": [x, y]
    "b{id}": [z]
$handler: ${std.mapping}
$for:
  entry: ${forms}
  label: ${entry.value}
key: ${label}
value:
  id: ${entry.key}
```

```yaml
x:
  id: a{id}
y:
  id: a{id}
z:
  id: b{id}
```

`entry` はマッピングのエントリを、`label` はそのエントリの値のリストの要素を選ぶ。
後の束縛の右辺から先の束縛が見えるので、二段の選択が入れ子の反復になる。
`std.mapping` が全分岐の `{key, value}` を集め直す。

### パラメータと条件分岐

```yaml
server:
  host: {$std.param: db_host}
  port: {$std.param: db_port, $default: 5432}
  tls:
    $if: {$std.param: use_tls}
    $then:
      cert: /etc/ssl/cert.pem
    $else: null
```

`db_host: example.com` と `use_tls: false` を渡して評価すると次になる。

```yaml
server:
  host: example.com
  port: 5432
  tls: null
```

三つの境界は互いに独立であり、パラメータは読み出し専用なので、評価順序は結果に影響しない。

### 分岐を貫く状態

```yaml
$do:
- $handler: ${std.list}
- $std.set: {n: 0}
- $for:
    name: [web, db, cache]
- $let:
    id: {$std.get: n}
- $std.set:
    n: ${id + 1}
- name: ${name}
  id: ${id}
```

状態の既定ハンドラは境界にあり、`std.list` より外側なので、セル `n` は分岐をまたいで貫流し、連番が振られる。

```yaml
- name: web
  id: 0
- name: db
  id: 1
- name: cache
  id: 2
```

`id` の束縛は `name` の束縛より後、すなわち選択より後にあるから、分岐ごとに読み直される。
二つの文を入れ替えると読み出しは分岐の前に一度だけ実行され、全分岐の `id` が 0 になる。

### マッピングの生成と変換

```yaml
$handler: ${std.mapping}
$for:
  e: {web: 80, db: 5432}
key: svc-${e.key}
value: ${e.value}
```

```yaml
svc-web: 80
svc-db: 5432
```

マッピングを `$for` で分解し、`std.mapping` で組み立て直す形である。
途中に `$std.where` を挟めば、条件を満たすエントリだけを残せる。

### 欠落するデータの除外

```yaml
$handler: ${std.list}
$for:
  row:
  - {date: d1, code: c1}
  - {date: d2}
  - {date: d3, code: c3}
date: ${row.date}
code:
  $std.lookup: {in: "${row}", key: code}
  $default: {$std.where: false}
```

```yaml
- {date: d1, code: c1}
- {date: d3, code: c3}
```

2 行目には `code` が無いので、照会が `std.fail` を起こし、`$default` の `{$std.where: false}` がそれを分岐の打ち切りに変える。
失敗を null で埋めたいときは `$default: null` と書く。

### 回数つきの unfold

```yaml
$handler: {$std.state: {acc: 1}}
$in:
  $std.collect:
    in: {$std.range: 5}
    with:
      $fn: _
      $body:
        $do:
        - $let:
            v: {$std.get: acc}
        - $std.set:
            acc: ${v * 2}
        - - ${v}
```

```yaml
[1, 2, 4, 8, 16]
```

種 1 と関数 (*2) から先頭 5 要素を生成する。
`std.range` が回数をリストに変え、`std.collect` が回り、`std.state` が種を持ち回る。
アキュムレータを伴う fold も同じ組み合わせで書ける。

### 関数と合成

```yaml
$let:
  double:
    $fn: x
    $body: ${x * 2}
  succ:
    $fn: x
    $body: ${x + 1}
$in:
  $.succ:
    $.double: 20
```

```yaml
41
```

呼び出しの入れ子が合成である。
内側が先に評価され、その値が外側の引数になるので、`succ(double(20))` を読み下した形になる。
段が長くなるときは、`$let` で一段ずつ名前を付けて並べる。

### 演算の部分適用

マッピング引数の関数は、引数を組み立てるカリー化された関数（adapter）を一度宣言すれば部分適用できる。
表を固定した照会関数を作り、キーの各分岐に適用する。

```yaml
$handler: ${std.list}
$let:
  codes: {ja: 81, us: 1}
  look:
    $fn: [m, k]
    $body:
      $std.lookup:
        in: ${m}
        key: ${k}
  dial:
    $.look: ${codes}
$for:
  c: [ja, us]
$in:
  $.dial: ${c}
```

```yaml
- 81
- 1
```

部分適用 `{$.look: 表}` の引数はその位置で一度だけ評価され、閉包に捕まる。
返った閉包 `dial` は残りの引数 `k` を待つ普通の関数値であり、`std.collect` の `with` にもそのまま置ける。

### 失敗の捕捉

```yaml
port:
  $handler:
    std.fail:
      $fn: msg
      $body:
        $do:
        - $std.log: ${msg}
        - 5432
  $let:
    p: {$std.param: port, $default: 0}
  $if: ${p <= 0 || p > 65535}
  $then:
    $std.fail: invalid port ${p}
  $else: ${p}
```

節が `$resume` を呼ばないので、失敗した時点で本体は打ち切られ、節の値 5432 がハンドラ全体の値になる。

### 引数で調整するハンドラ

```yaml
$let:
  orElse:
    $fn: [d, run]
    $body:
      $handler:
        std.fail: {$fn: _, $body: "${d}"}
      $in: {$.run: null}
$in:
  a:
    $handler: {$.orElse: 0}
    $in: {$std.lookup: {in: {}, key: missing}}
  b:
    $handler: {$.orElse: 0}
    $in: 7
```

```yaml
a: 0
b: 7
```

`orElse` は既定値と本体の閉包をとるカリー化された関数である。
`{$.orElse: 0}` の部分適用が本体の閉包を待つ関数になり、`$handler` がそれに本体を渡す。
節の本体は定義位置の束縛を捕まえるので、引数 `d` が節から見える。

### 最初に成功する分岐

```yaml
log_level:
  $handler: ${std.first}
  $for:
    v: [{$std.param: log_level, $default: null}, {$std.param: fallback_log_level, $default: null}, info]
  $do:
  - $std.where: ${v != null}
  - ${v}
```

`std.first` が選択を処理するので、値はリストではなく、条件を満たした最初の分岐のものになる。
パラメータが一つも渡されていなければ `info` になる。

### 文に置いた文脈の導入

```yaml
$do:
- $handler:
    std.fail: {$fn: _, $body: 0}
- $std.lookup: {in: {}, key: missing}
```

```yaml
0
```

文に置いた `$handler` が残りの文にハンドラを導入し、続く文で `$std.lookup` の照会が起こす `std.fail` を節が既定値に変える。

```yaml
$do:
- $handler: {$std.state: {n: 0}}
- $std.set: {n: 41}
- $let:
    n: {$std.get: n}
- ${n + 1}
```

```yaml
42
```

文に置いた `std.state` のハンドラが残りの文に状態を導入し、後続の文が同じセルを読み書きする。

### 文脈の導入を伴うマッピング

```yaml
$let:
  registry: ghcr.io/acme
  env: {$std.param: env, $default: dev}
name: api
image: ${registry}/api:${env}
replicas:
  $if: ${env == 'prod'}
  $then: 3
  $else: 1
```

パラメータを渡さずに評価すると次になる。

```yaml
name: api
image: ghcr.io/acme/api:dev
replicas: 1
```

素の YAML の設定に、文脈を導入する `$let` を足した形であり、データのキーは動かない。
導入された束縛は、残りから参照できる。

```yaml
database:
  $handler:
    std.fail: {$fn: _, $body: {$resume: null}}
  host: {$std.param: db_host}
  port: {$std.param: db_port}
```

`db_host: db` を渡して評価すると次になる。

```yaml
database:
  host: db
  port: null
```

節が `$resume: null` で再開するので、マッピングの中の未渡しのパラメータがそれぞれ null になる。

残りは主形でもよい。

```yaml
$handler: ${std.list}
$for:
  i0: {$std.range: 15}
$let:
  i: ${i0 + 1}
$if: ${i % 15 == 0}
$then: fizzbuzz
$else:
  $if: ${i % 3 == 0}
  $then: fizz
  $else:
    $if: ${i % 5 == 0}
    $then: buzz
    $else: "${i}"
```

```yaml
[1, 2, fizz, 4, buzz, fizz, 7, 8, fizz, buzz, 11, fizz, 13, 14, fizzbuzz]
```

`$handler` の直下で `$for` と `$let` が文脈を導入し、残りが `$if` の主形なので、束縛は分岐から見える。

### 引数で受けた演算の処理

```yaml
$let:
  run:
    $fn: sig
    $body:
      $handler:
        .sig:
          $fn: _
          $body: handled
      $in: {$.sig: null}
  outer:
    $handler:
      signal:
        $fn: _
        $body: unreachable
    $in: ${signal}
$in:
  $.run: ${outer}
```

```yaml
handled
```

`outer` は宣言した演算の値をハンドラの外へ持ち出している。
値の持ち出しは誤りではなく、`run` の `$handler` が節の名前 `.sig` で引数の演算に解決し、呼び出しを処理する。
