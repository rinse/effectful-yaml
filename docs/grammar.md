# effectful-yaml 言語仕様（草案 0.4）

effectful-yaml は、素の YAML の上に**作用**（effect）つきの計算を埋め込む言語である。
すべての文書は一般の YAML パーサーでそのままパースでき、`$` で始まるキーを持つマッピングだけが計算として解釈される。
`$` を含まない YAML 文書は、それ自身を値とする妥当なプログラムである。
ファイルに置いた文書を effectful-yaml だと明示したいときは、拡張子 `.eyaml` を用いる。

本仕様は名前として monadic-yaml ではなく effectful-yaml を採る。
後述するとおり、この言語は `>>=` や `pure` を書かせるモナディックスタイルではなく、演算を直接呼び出す Koka 風の直接スタイルを採用しており、モナドは意味論にのみ現れて紙面には現れないからである。

## 設計原則

- **素の YAML**：文法上の拡張を一切持たない。特殊な構文はすべてマッピングのキーと文字列の中に閉じ込める。YAML タグ（`!do` など）を使わないのは、タグが JSON 部分集合で表現できず、タグを拒否するパーサー[^1]や jq のような既存ツールと相性が悪いからである。
- **カーネルは最小**：言語が意味を直接与えるのは、少数の構文と唯一の原始演算 `$collect` だけである。標準の演算とハンドラはすべて `std` 名前空間にあり、その意味論はカーネルへの展開で定まる。
- **作用は紙面に現れる**：作用を起こすのは演算の呼び出しと、欠落しうるパスアクセスだけである。裸の参照 `${x}` は純粋であり、作用を隠さない。
- **作用は静的に決まる**：ブロックの作用は、演算が構文上どこに出現するかだけで決まり、実行時の分岐に依存しない。評価結果の形（単値かリストか）も作用から決まる。
- **リストは常にデータ**：YAML のリストがデータでなくなるのは `$do` の直下だけである。この例外を一つに絞ることで、「このリストは値なのか文の並びなのか」という読み手の迷いをなくす。
- **暗黙の null を作らない**：未定義の参照はエラーになる。存在しないキーと添字、渡されていないパラメータ、未初期化のセルの読み出しは、null になるのではなく失敗作用 `std.fail` を起こす。失敗は捕捉できるが、捕捉しなければ文書全体のエラーになる。
- **停止する**：一般再帰に相当する原始（fix）を置かない。`$collect` は有限の構造しか回らないので、関数値の自己適用を書かない文書の評価は、停止しない登録演算をホストが与えない限り必ず停止する。
- **型クラスを持たない**：作用の多相はハンドラが担う。演算は抽象的な名前であり、その意味は包囲する最も近いハンドラが選ぶので、同じ演算がハンドラごとに別の意味を持てる（`std.where` は `$std.list` の下ではリストの、`$std.first` の下では最初の成功のガードになる）。値のオーバーロードはそもそも提供せず、`==` は構造的等価に、算術は数値だけに固定する。

[^1]: たとえば PyYAML の `safe_load` は、登録されていないローカルタグを既定で拒否する。

## 評価モデル

文書はテンプレートとして外側から評価される。
`$` で始まるキーを持つマッピングを **`$` 式**と呼ぶ。
評価関数は次の規則に従う。

- スカラーは、`${...}` の補間を解決した値になる。
- リストは、各要素を先頭から順に評価したリストになる。
- `$` キーを持たないマッピングは、各値を文書順に評価したマッピングになる。
- `$` 式は、主キーごとに定められた規則で評価する。

一つの `$` 式に置ける主キー（`$do` や `$collect` など）は一つだけである。
`$then` のような補助キーは、主キーに従属するものだけを置ける。
`$` キーとそれ以外のキーの混在はエラーである。

### 予約キーとカーネル

ドットを含まない `$` キーは言語が予約する。
予約キーは次の 17 個であり、予約されていないドットなしの名前はエラーになる。

`$do` `$let` `$if` `$then` `$else` `$fn` `$body` `$op` `$pipe` `$through` `$handle` `$with` `$resume` `$collect` `$into` `$in` `$default`

このうちカーネル、すなわち評価器が意味を直接与える構文は次の 6 形である。

- 参照と式 `${...}`
- 束縛と並び `$do` `$let`
- 分岐 `$if`（`$then` `$else`）
- 関数 `$fn`（`$body`）と呼び出し
- ハンドラ `$handle`（`$with` `$resume`）
- 畳み込み `$collect`（`$with` `$into`）

`$op` と `$pipe`（`$through`）は**導出形**であり、意味はカーネルへの展開で定める。
`$in` と `$default` は std の演算とハンドラ（`$std.state` と `$std.param`）が使う補助キーである。

演算はカーネルに属さない。
`$collect` はただ一つの例外であり、これを原始に置く理由は設計判断の節で述べる。

### 作用境界

データの中に現れた最も外側の `$` 式を**作用境界**と呼ぶ。
境界の内側で演算が起こす作用は、途中にハンドラがなければ境界まで伝播し、そこで処理系の**既定ハンドラ**が処理する。
入れ子の `$` 式は境界にならないので、`$do` の中の `$do` は Haskell の do 式の入れ子と同じく、単なるグループ化である。

演算は `$` 式の引数の中であればどこにでも置ける。
たとえば文 `- [1, {$std.each: [a, b]}]` はリストの要素の位置で選択を行うので、外側のブロック全体が 2 通りに分岐する。

境界が互いに独立であることには意味がある。
兄弟関係にある二つの境界は作用を共有しないので、データ部分の評価は順序に依存しない。
複数の場所で状態や選択を共有したければ、その範囲全体を一つの `$do` で包み、単一の境界にする。

### 作用の推論

作用は演算の名前で数える。
各ノードの**作用集合**は、その内側に出現する演算の名前を合併し、ハンドラが節に挙げた名前を除いて、節と `return` の本体の作用を加えたものである。
出現だけを見るので、実行されない分岐の演算も作用に数える。
欠落しうるパスアクセス（後述）は `std.fail` を作用集合に加える。
これにより評価結果の形が実行前に定まる。

- 作用集合に**選択**（`std.each` か `std.where`）が残っている境界は、全分岐の結果を文書順に並べたリストに評価される。
- それ以外の境界は単値に評価される。

境界に達した作用は、処理系が文書を std の既定ハンドラの系列で包んだものとして処理される。
系列は外側から失敗、パラメータ、ログ、状態、選択の順である。

- **失敗**：捕捉されずに届いた `std.fail` は、その値をメッセージとして文書全体のエラーになる。
- **パラメータ**：`std.param` は起動時に与えられたパラメータ表を読む。
- **ログ**：`std.log` は値をホストのログ出力に流す。
- **状態**：暗黙の `$std.state: {}` が置かれる。選択より外側にあるため、状態は分岐をまたいで文書順に貫流する。この振る舞いを変えたいときは `$std.state` を明示的に置く。
- **選択**：`$std.list` 相当の収集が行われる。作用集合に選択がなければ収集は行われず、境界は単値になる。

### 合成と境界

作用境界がどこに生じるかを、構文上の位置ごとに三つに分けて定める。

**合成**：`$do` の文の並び、`$let` の右辺から後続の文への流れ、`$if` の選ばれた分岐、関数呼び出し（`$.名前`）と演算の引数と本体、`$collect` の対象と関数本体、そして境界の内側に現れるデータ構成（リストの要素、`$` キーを持たないマッピングの値）は、境界を作らない。
内側で起きた作用は周囲の計算へそのまま合流する。
データ構成は作用を起こさないが、遮りもしない。
文 `- [1, {$std.each: [a, b]}]` が外側のブロック全体を 2 通りに分岐させて `[1, a]` と `[1, b]` を生むのはこのためであり、`$let` の右辺に `$std.each` を書くと周囲の `$do` 全体が分岐するのも、関数呼び出しの作用が「引数の作用と本体の作用の合併」になるのも同じ理由による。

**部分処理**：ハンドラ（`$handle` の本体、および std の派生ハンドラの本体）が処理する範囲は、そのハンドラが節に挙げた演算だけを取り除く。
それ以外の作用はそのまま透過し、ハンドラ自身の値へ合流する。
既定の状態（貫流）が選択をまたぐのは、状態のハンドラが選択を処理せずに透過させ、選択そのものはさらに外側で処理されるからである。

**境界**：作用境界の節で定めたとおり、データの中に現れた最も外側の `$` 式と、文書全体だけが境界である。
境界に達した計算は、残るすべての作用を既定ハンドラの系列で処理し尽くしてから、初めて具体的な値になる。
境界の内側には、明示のハンドラを除いて作用を堰き止める場所はない。

`$if` は合成なので、選ばれなかった分岐の作用も境界の作用集合に算入される。
したがって `$then` にだけ選択が現れる `$if` を境界の直下に置くと、実行時に `$else` 側が選ばれて単一の値になる場合でも、境界の値は要素 1 のリストになる。
実装は境界の形（単値かリストか）を、実行して得られた値の個数からではなく、この静的な作用集合から決めなければならない。

**引数の評価順**：演算も関数呼び出しも、引数を評価してから、それぞれ演算の実行・本体の評価に進む（値渡し）。
引数の評価で起きた作用は堰き止められず、周囲へ合流する。
`{$.f: {$std.each: [1, 2]}}` は、引数の選択が周囲へ合流するので、f の呼び出しごと分岐する（f が 1 回で `[1, 2]` を受け取るのではない）。
`$std.param` の `$default` は例外で、`$if` の分岐と同じ**遅延位置**である。
パラメータが渡されていれば `$default` は評価されず、その作用も起きない。
作用の推論は出現主義なので、評価されない場合でも `$default` の中の演算は作用集合に数える（`$if` の選ばれない分岐と同じ扱い）。

## 参照と式

**参照**：`${式}` は文字列の中に式の値を埋め込む。
文字列全体が一つの `${式}` であるときは値そのもの（型を問わない）になり、それ以外のときは値を文字列化して埋め込む。
リストとマッピングと null の文字列化はエラーである。

参照が解決するのは `$let` と `$fn` が導入した束縛だけである。
パラメータは `std.param`、状態は `std.get` という演算を通じて読む。
この区別により、作用を起こす読み出しは必ず演算として紙面に現れる。

**パスの部分性**：`${x}` のような裸の参照は純粋である。
`${x.y}` や `${xs[0]}` のようにパスをたどる参照は、キーや添字が存在しないとき失敗作用 `std.fail` を起こす。
失敗はハンドラで捕捉でき、捕捉しなければ境界で文書全体のエラーになる。
一方、束縛名そのものが未定義であること、マッピングでない値のキーをたどること、型の不一致は、データではなく文書の形の誤りなので、捕捉できないエラーのままである。
作用の推論では、パスをたどる参照の出現が `std.fail` を作用集合に加える。

`${}` の中に YAML 構造（演算の呼び出しなど）を書くことはできない。
理由は設計判断の節で述べる。
演算の結果を式で使うには、`$let` で名前を付けてから参照する。

YAML の規則上、`[...]` や `{...}` のフロー形式の中では `${x}` を含むスカラーに引用符が必要になる[^2]。
ブロック形式ではそのまま書ける。
本仕様の用例は、参照を含む箇所をブロック形式で書くことでこれを避けている。

[^2]: フロー文脈のプレーンスカラーは `{` などのフロー指示子を含められない（YAML 1.2 の ns-plain-safe(flow)）。これは本言語ではなく YAML 自体の制約である。

**エスケープ**：文字列とキーの中の `$$` は literal な `$` 一文字になる。
たとえば値 `"costs $$5"` は `costs $5` に、キー `$$do` は literal なキー `$do` に評価される。
`$` 式かどうかの判定は補間より前に、書かれたままのキーに対して行う。

式の文法は次のとおり最小限にとどめる。

```
式      := 論理和
論理和  := 論理積 ("||" 論理積)*
論理積  := 否定 ("&&" 否定)*
否定    := "!" 否定 | 比較
比較    := 加算 (("==" | "!=" | "<" | "<=" | ">" | ">=") 加算)?
加算    := 乗算 (("+" | "-") 乗算)*
乗算    := 単項 (("*" | "/" | "%") 単項)*
単項    := 数値 | '文字列' | true | false | null | 参照名 | "(" 式 ")"
参照名  := 名前 ("." 名前 | "[" 自然数 "]")*
```

- 比較 `==` と `!=` は値の構造的な等価性を判定する。大小比較と算術は数値だけに定義され、それ以外の型に適用するとエラーになる。
- `&&` と `||` と `!` の被演算子、および `$if` と `std.where` の条件は真偽値でなければならない。真偽値への暗黙の変換は行わない。
- `.名前` はマッピングのキーを、`[自然数]` はリストの 0 起点の添字を参照する。存在しないキーや添字は `std.fail` を起こす。
- 0 除算はエラーになる。文字列の連結は補間で書く。

式にはリストとマッピングのリテラルがない。
空リストとの比較が必要なときは、`$let` で `empty: []` のように名前を付けてから `${xs == empty}` と書く。

## 束縛と制御

`$do` と `$let` と `$if` は作用を持たない構文である。

### $do

```yaml
$do:
- 文1
- 文2
- 結果式
```

`$do` は直下のリストを文の並びとして先頭から評価し、最後の文の値をブロックの値とする。
これが「リストはデータ」の唯一の例外である。
空の `$do` の値は null である。

文には任意の式のほか、`$let` と演算を置く。
`$let` は文としては null に評価され、`std.where` と `std.set` と `std.log` の値も null なので、ブロックの結果にしたい値は最後の文に書く。
YAML には unit 型がないため、値を返さないことを表すには null を unit の代用とする。

### $let

```yaml
- $let:
    x: 式1
    y: 式2
```

`$let` は `$do` の文としてだけ書ける。
右辺を文書順に評価し、その値を名前に束縛して、ブロックの残りの文から `${x}` で参照できるようにする。
後の束縛の右辺からは先の束縛を参照できる。
同じ名前の再束縛は許され、外側の束縛を隠す。
束縛名にドットは使えない。呼び出しの名前空間の区切りと衝突するからである。

`$let` は非再帰であり、右辺から自分自身や後の束縛は見えない。

右辺の評価は作用を起こしてよい。
`x: {$std.each: [a, b, c]}` は「a、b、c のそれぞれを x として」と読め、Haskell の `x <- ...` に相当する。
束縛が作用を起こすかどうかは、右辺に演算が見えるかどうかと一致する。

右辺が作用を起こす場合、束縛を書く順序は意味を持つ。
do 文の文の並び替えが意味を変えるのと同じである。
とりわけ、`$std.each` より前に書いた `$std.get` は分岐する前に一度だけ実行され、全分岐が同じ値を見る。
`$std.each` より後に書けば分岐ごとに実行される。

### $if

```yaml
$if: 条件式
$then: 式
$else: 式
```

`$if` は条件の値に応じて `$then` か `$else` の一方だけを評価する。
`$else` は省略できない。
条件が真偽値でなければエラーになる。

## 関数

### $fn

```yaml
$fn: パラメータ名
$body: 式
```

`$fn` は関数の値を作る。
評価すると、定義位置の束縛を捕まえた**閉包**になる。
閉包が境界の外へ出て文書の値に残ることはエラーである。

パラメータはちょうど一つに固定する。
複数の値を渡すときはマッピングで一つに包み、本体から `${arg.名前}` のようにパスで参照する。
一つに固定するのは Kleisli 合成のためで、`>=>` で合成できるのは一引数の関数だけだからである。

### 呼び出しと名前空間

関数の呼び出しは演算の呼び出しと同じ形 `{$名前: 引数}` で書く。
名前は形で三つに分かれ、解決の優先順位のような暗黙の規則を持たない。

- **`$.名前`**：ドットで始まる名前は、レキシカルな束縛を指すローカル名前空間である。名前はドット区切りの単純な識別子の列（`名前(.名前)*`）で、最初の区画が束縛を解決し、残りの区画があればその値のマッピングを順にキーでたどる。たどり着いた値が関数でなければエラーになる。
- **`$名前空間.名前`**：ドットを含む名前は演算を指す。`std.` で始まる名前は標準演算であり、それ以外はホストに登録された演算である。
- **`$名前`**：ドットを含まない名前は予約キーである。予約されていない名前はエラーになる。

グローバル名前空間（ドットを含まない名前）は言語が予約し、予約キーにドットを含む名前を今後も追加しない。
したがって、名前空間を持つ関数と演算が将来の予約キーと衝突することはない。
`$.名前` が何区画のドットを持っても、先頭のドットで区別がつくので、この一意性は崩れない。
`$let` の束縛名自体にはドットを使えない（束縛と制御の節）ため、名前の中のドットは常に「束縛名の終わり・キーアクセスの始まり」の区切りとして読める。
たとえば `$.a.self` は、束縛 `a` の値をマッピングとして読み、キー `self` の値を関数として呼ぶ。
呼び出しの経路の解決は関数という文書の形に関わるので、失敗作用ではなくエラーの語彙（`undefined reference`、`cannot access key`、`missing key`）で報告する。
添字 `[0]` はこの経路では書けない。
添字の先や、計算した式の先にある関数を呼びたいときは、後述の `$pipe` に式として渡す。
`${x}` の参照は呼び出しではないので、この規則の対象外である。

引数を評価してからパラメータに束縛し、本体を定義位置の環境で評価する（レキシカルスコープ）。
呼び出しの作用は、引数の作用と本体の作用の合併である。
関数値が `$if` などで分岐しうる場合、作用の推論は生成されうる閉包の本体の合併で過大近似する。

本体の作用を算入できるのは、関数値をレキシカルに追跡できる呼び出しに限る。
追跡できるのは、`$let` の束縛、マッピングとリストのリテラル、それをたどるパス参照（`${arg.step}`）、呼び出しの引数として渡された関数値、リテラルのリストからの `$std.each` である。
引数の追跡結果をパラメータに束縛して本体を解析するので、呼び出しごとに違う関数を渡す高階の書き方も静的に算入される。
追跡できない経路（実行時のデータから関数を選ぶ場合など）の呼び出しが選択を含むときは、境界の形の検証を実行時に行い、形が合わなければエラーになる。
呼び出しを `$std.list` などの明示のハンドラで包めば、選択はそこで処理され、境界の形は追跡に依存せず静的に定まる。

`$let` が非再帰なので、名前による再帰は書けない。
反復は `$std.each` と `$collect` のようにデータ構造に沿った形で書く。
ただし関数値の自己適用までは構文では排除できないため、停止性の保証は型付け（今後の課題）に委ねる。
言語は fix に相当する原始を提供しない。

### $op

```yaml
{$op: 演算名}
```

`$op` は演算を関数の値として参照する導出形である。
`{$op: 演算名}` は η 展開 `{$fn: x, $body: {$演算名: ${x}}}` と等価であり、意味論はこの展開で定める。
専用の形を残すのは、演算が呼び出しのキーの位置にしか現れられず、式 `${...}` ではパスアクセスの記法と衝突して名指しできないからである。
対象は演算だけであり、`$do` のような構文と std の派生ハンドラは参照できない。
レキシカルな束縛は `${名前}` で値として参照できるので、`$op` の対象外である。

`$pipe` の段に演算を置くときのほか、長い名前の演算に短いローカル名を付ける次の慣用に使う。

```yaml
- $let:
    read: {$op: vault.secrets.read}
- {$.read: db/password}
```

### $pipe

```yaml
$pipe: 式
$through:
- 関数値の式
- 関数値の式
```

`$pipe` は先頭の値を `$through` の各関数に順に通し、最後の結果を値とする導出形であり、各段を `$let` で束縛して `$.名前` で呼ぶ形への展開と等価である。
空の `$through` は先頭の値をそのまま返す。
これが Kleisli 合成 `f >=> g >=> h` の具体形である。
段の関数値の式は、`${double}` のような単純な参照に限らず、`${arg.step}` のようなパスをたどる参照でもよい。
`$.名前` の呼び出しがマッピングのキーをドットでたどる形に限られるのに対し、`$pipe` は関数値を式として受け取るので、添字や計算した式の先にある関数を呼ぶ経路になる。

## $collect

`$collect` は唯一の原始演算である。
構造を先頭から回りながら、要素ごとの結果を一つの構造に組み立てる。

```yaml
$collect: 対象の式
$with: 一引数関数の式
$into: list または mapping   # 省略時 list
```

- 対象はリストまたはマッピングである。マッピングは `{key: キー, value: 値}` のエントリの列として文書順に回る。
- `$with` の関数を各要素に文書順に適用する。関数は要素ごとにリストを返さなければならない。
- `$into: list` のとき、全要素の結果リストを文書順に**連結**したリストになる。
- `$into: mapping` のとき、結果リストの各要素は `key` と `value` のちょうど二つのキーを持ち `key` が文字列であるマッピングでなければならず、全エントリを集めた一つのマッピングになる。キーの重複はエラーである。
- 空の対象の値は、`$into: list` なら空リスト、`$into: mapping` なら空マッピングである。

`$collect` 自身は作用を起こさず、ハンドラで捕捉できない。
作用は対象の式と、追跡できる関数本体の作用の合併である（関数呼び出しと同じ規則）。
対象が有限である限り適用は有限回なので、`$collect` は停止性を壊さない。

`$collect` は圏論の言葉では畳み込み（catamorphism）であり、リストモナドの bind（concatMap）とエントリ列からのマッピング構成を兼ねる。
map は要素を一要素リストで包む関数で、filter は空リストを返す分岐で、連結は恒等関数で書ける。
アキュムレータを伴う古典的な fold は、`$collect` と `$std.state` の組で導出できる（用例の節）。

```yaml
# 各要素を二重にする: [1, 1, 2, 2, 3, 3]
$collect: [1, 2, 3]
$with:
  $fn: x
  $body:
  - ${x}
  - ${x}
```

## 演算

演算は作用を起こす `$` 式であり、名前は必ずドットを含む。
演算の名前そのものが作用の名前である。
各演算は、包囲する最も近いハンドラの節か、境界の既定ハンドラが処理する。
文書に出現する演算名を集めれば、その文書が要求するハンドラの一覧、すなわち文書の**作用シグネチャ**が評価前に得られる。
処理系は、標準でもホスト登録でもなく、どのハンドラの節にも現れない演算を含む文書を評価前に拒否する。

### 標準の演算

`std.` で始まる名前は言語が予約する標準演算であり、ホストは `std.` 名前空間に演算を登録できない。
作用を起こす標準演算は次の 7 つである。

| 演算 | 意味 |
|---|---|
| `$std.each: リストまたはマッピング` | 要素を一つずつ選ぶ。値は選ばれた要素。 |
| `$std.where: 条件式` | 条件が偽の分岐を打ち切る。値は null。 |
| `$std.param: 名前` | 起動時に与えられたパラメータを読む。 |
| `$std.get: 名前` | セルの現在値を読む。 |
| `$std.set: マッピング` | セルに値を書く。未作成のセルは作られる。値は null。 |
| `$std.log: 式` | 値をログに流す。値は null。 |
| `$std.fail: 式` | 計算を失敗させる。値をエラーメッセージとする。 |

パラメータ作用は reader モナドに、状態作用は state モナドに対応する。

補足を述べる。

- `$std.each` の引数がリストなら各要素を、マッピングなら各エントリを `{key: キー, value: 値}` の形で、文書順に選ぶ。`$std.each: ${xs}` のようにデータ駆動の反復が書ける。空のリストやマッピングは分岐 0 本を意味し、`$std.where: false` と同じく打ち切りになる。
- `$std.param` は補助キー `$default` を取れる。`{$std.param: 名前, $default: 式}` は、`{$std.param: 名前}` を `$handle` で包み `std.fail` の節で `$default` の式を返す形への展開と等価である。したがってパラメータが渡されていないときの値は `$default` の式であり、`$default` がなければ `std.fail` が境界まで伝播してエラーになる。
- `$std.get` の名前空間は `$let` の束縛とは別である。同名でも互いに関係しない。未初期化のセルの読み出しは `std.fail` を起こす。
- `$std.set` は複数のセルを文書順に書ける。

### 第一階の標準演算

作用を起こさず、値から値を計算するだけの標準演算を第一階の標準演算と呼ぶ。
導出できないが評価器の協力も要らないので、カーネルではなく供給の層に置く。

| 演算 | 意味 |
|---|---|
| `$std.range: 自然数 n` | リスト `[0, 1, ..., n-1]`。数から構造への唯一の橋。 |
| `$std.upper: 文字列` | 大文字化。 |
| `$std.lower: 文字列` | 小文字化。 |
| `$std.resolve: {base: 文字列, path: 文字列}` | URL の解決。base を基準に path を絶対 URL にする。 |

`$std.range` の引数が自然数でなければエラーになる。
回数の上界つきの unfold（種と関数からの列の生成）は、`$std.range` と `$collect` と `$std.state` で書ける（用例の節）。
上界の代わりに述語で止める unfold は while ループそのものであり、fix と同じ強さを持つので提供しない。

### ホスト登録の演算

処理系に登録された演算は、呼ぶだけで作用を起こす。
ハンドラは登録時にホスト言語で与えるか、文書内の `$handle` で与える。

```yaml
password: {$vault.read: secret/db/password}
```

登録演算の名前は `vault.read` のようにドットで名前空間を含まなければならない。
グローバル名前空間は言語の予約キーのためにあり、`std.` 名前空間は標準演算のためにあるので、利用者はそれ以外の名前空間を使う。
名前が長くなるときは、`$op` と `$let` の慣用で短いローカル名を付ける。
閉包をホスト言語のハンドラへ渡すことはできない。

## ハンドラ

ハンドラは、内側の作用をその場で処理し、外へ伝播させない `$` 式である。
カーネルのハンドラは `$handle` ただ一つであり、std の派生ハンドラはすべて `$handle` と `$collect` への展開で定義される。

### $handle

```yaml
$handle: 本体の式
$with:
  演算名:
    $fn: 引数名
    $body: 節の本体
  return:
    $fn: 値名
    $body: 式
```

`$handle` は利用者が定義するハンドラである。
本体の中で `$with` に書いた演算が呼ばれると、対応する**節**が演算の引数を受け取って評価される。
節の名前は `std.fail` のようにドットを含む演算名か、予約された `return` である。

- 節の本体では `{$resume: 値}` で継続を再開できる。その値は、演算の呼び出し位置に「値」を返して残りの計算（`return` 節を含む）を進めた結果である。
- `$resume` は節の本体の中で呼べる。節の本体で作られた閉包の本体も含み、閉包が捕まえるのはその節の起動に対応する継続である。一度も呼ばない（打ち切り）ことも、複数回呼ぶことも許される。
- 節が `$resume` を呼ばずに値に達したときは、その値がハンドラ全体の値になる（打ち切り）。継続の途中で打ち切られた場合は、その継続を呼んだ `$resume` の位置ではなく、ハンドラ全体が節の値になる。
- ハンドラは深い。再開後の計算にも同じハンドラが効き続ける。
- 節の本体が起こす作用は、このハンドラ自身ではなく外側で処理される。
- `return` 節は、本体が演算を起こさず値に達したときにその値を変換する。省略時は恒等である。

作用の推論では、`$with` に現れた演算の名前が集合から除かれ、節と `return` の本体の作用が加わる。

### std の派生ハンドラ

| 形 | 処理する演算 | 値 |
|---|---|---|
| `$std.list: 式` | `std.each` `std.where` | 全分岐の結果を文書順に並べたリスト |
| `$std.mapping: 式` | `std.each` `std.where` | 全分岐の `{key, value}` を集めたマッピング |
| `$std.first: 式` | `std.each` `std.where` `std.fail` | 失敗しなかった最初の分岐の値 |
| `$std.state: 初期値, $in: 式` | `std.get` `std.set` | 本体の値 |
| `$std.opt: 式` | `std.fail` | 本体の値。失敗なら null |
| `$std.prune: 式` | `std.fail` | 本体の値。失敗なら包囲する選択の分岐を打ち切る |

派生ハンドラの意味論は展開が定める。
実装は等価な組み込みで最適化してよいが、観測できる振る舞い（値、作用、ログの順序）は展開と一致しなければならない。

**$std.list** の展開は、リストモナドの教科書どおりの形である。

```yaml
$handle: 本体
$with:
  std.each:
    $fn: xs
    $body:
      $collect: ${xs}
      $with:
        $fn: x
        $body:
          $resume: ${x}
  std.where:
    $fn: b
    $body:
      $if: ${b}
      $then: {$resume: null}
      $else: []
  return:
    $fn: x
    $body:
    - ${x}
```

ハンドラは深いので、各 `$resume` の値は残りの計算を同じハンドラで処理し尽くしたリストであり、`$collect` がそれらを連結する。
内側に選択がなければ `return` 節だけが働き、要素 1 のリストになる。
分岐の中の失敗は節にないので処理せず、全体の失敗として伝播させる。

**$std.mapping** は同じ骨格で、`return` 節が `{key, value}` を単エントリのマッピングにし（`$collect` の `$into: mapping`）、`std.each` の節が各再開の結果のエントリを集め直す。
エントリの検査（ちょうど二つのキー、`key` は文字列、重複の禁止）は `$collect` の契約に含まれるので、展開には現れない。
`$std.where` で分岐を打ち切れば、条件を満たすエントリだけを持つマッピングが作れる。
これは「null を入れること」と「キーが無いこと」の区別、すなわちキーの条件付き省略を兼ねる。

**$std.state** の展開は、節が状態変換関数を返す古典的なパラメータ付きハンドラである。
`std.get` の節を示す（`std.set` と `return` も同型）。

```yaml
std.get:
  $fn: name
  $body:
    $fn: s
    $body:
      $do:
      - $let:
          hits:
            $collect: ${s}
            $with:
              $fn: e
              $body:
                $if: ${e.key == name}
                $then:
                - ${e.value}
                $else: []
      - $let:
          k:
            $resume: ${hits[0]}
      - $.k: ${s}
```

継続の再開結果も状態変換関数なので、それを現在の状態に適用して続行する。
`${hits[0]}` は未初期化のセルでちょうど `std.fail` を起こす。
展開の全体は、本体をこのハンドラで包んで得た関数を初期値に適用する形であり、初期値の式は本体より先に評価される。
`$std.state` を選択に対してどこに置くかで、状態と分岐の関係が決まる。

```yaml
# 貫流（既定と同じ）: 状態が分岐から分岐へ持ち越される
$std.state: {n: 0}
$in:
  $std.list: 選択を含む本体
```

```yaml
# 分岐点で分かれる: 各分岐が選択時点の状態を引き継ぎ、以後は独立に進む
$std.list:
  $std.state: {n: 0}
  $in: 選択を含む本体
```

貫流が ListT (State s) に、分岐点で分かれる形が StateT s [] に対応する。

**$std.first** は選択と失敗を処理し、失敗しなかった最初の分岐の値に評価される。
最初の成功より後の分岐は評価されず、その作用も起きない。
すべての分岐が失敗または打ち切りなら、全体が `std.fail` になる。
展開は成功の印を私的な演算のパラメータ付きハンドラで持ち回る形になり、紙面に収まらないので参照文書に置く。

**$std.opt** と **$std.prune** は失敗を翻訳する。

```yaml
# $std.opt: 式 の展開。失敗を null に変える。
$handle: 式
$with:
  std.fail:
    $fn: _
    $body: null
```

```yaml
# $std.prune: 式 の展開。失敗を包囲する選択の打ち切りに変える。
$handle: 式
$with:
  std.fail:
    $fn: _
    $body: {$std.where: false}
```

`$std.prune` の節の本体が起こす `std.where` は、このハンドラ自身ではなく外側で処理される（`$handle` の規則）ので、包囲する選択の分岐ごと打ち切られる。
失敗しうる式を要素とみなして選択に流し込むときの標準形であり、欠落したキーを持つデータを黙って除外する用途に使う。

## 用例

### 値だけの文書

```yaml
greeting: hello
```

`$` 式を含まない文書はそれ自身に評価される。
`pure` に相当する構文が要らないのはこのためで、値はそのまま計算の結果である。

### 選択の基本形

```yaml
$do:
- $let:
    x: {$std.each: [a, b, c]}
    y: {$std.each: [x, y, z]}
- $std.each:
  - ${x}
  - ${y}
```

作用集合は選択だけなので、境界の値は全分岐の結果のリストになる。
最後の文も選択なので、分岐は 3 × 3 × 2 の 18 本ある。

```yaml
[a, x, a, y, a, z, b, x, b, y, b, z, c, x, c, y, c, z]
```

最後の文を literal なリストに変えると、意味が「2 つの結果を選ぶ」から「2 要素のリストを返す」に変わる。

```yaml
$do:
- $let:
    x: {$std.each: [a, b, c]}
    y: {$std.each: [x, y, z]}
- - ${x}
  - ${y}
```

```yaml
[[a, x], [a, y], [a, z], [b, x], [b, y], [b, z], [c, x], [c, y], [c, z]]
```

この 2 例の対比が「リストは常にデータ、選択は `$std.each`」という原則の眼目である。

### 打ち切りつきの選択

```yaml
$do:
- $let:
    x: {$std.each: [1, 2, 3]}
    y: {$std.each: [1, 2, 3]}
- $std.where: ${x < y}
- - ${x}
  - ${y}
```

```yaml
[[1, 2], [1, 3], [2, 3]]
```

リスト内包表記に相当する形である。

### パラメータと条件分岐

```yaml
server:
  host: {$std.param: db_host}
  port: {$std.param: db_port, $default: 5432}
  tls:
    $if: {$std.param: use_tls}
    $then:
      cert: /etc/ssl/cert.pem
    $else: null
```

`db_host: example.com` と `use_tls: false` を渡して評価すると次になる。

```yaml
server:
  host: example.com
  port: 5432
  tls: null
```

三つの境界は互いに独立であり、パラメータは読み出し専用なので、評価順序は結果に影響しない。

### 分岐を貫く状態

```yaml
$do:
- $std.set: {n: 0}
- $let:
    name: {$std.each: [web, db, cache]}
    id: {$std.get: n}
- $std.set:
    n: ${id + 1}
- name: ${name}
  id: ${id}
```

状態の既定ハンドラは選択より外側にあるので、セル `n` は分岐をまたいで貫流し、連番が振られる。

```yaml
- name: web
  id: 0
- name: db
  id: 1
- name: cache
  id: 2
```

`id` の束縛は `name` の束縛より後、すなわち選択より後にあるから、分岐ごとに読み直される。
二つの束縛を入れ替えると読み出しは分岐の前に一度だけ実行され、全分岐の `id` が 0 になる。

### マッピングの生成と変換

```yaml
$std.mapping:
  $do:
  - $let:
      e: {$std.each: {web: 80, db: 5432}}
  - key: svc-${e.key}
    value: ${e.value}
```

```yaml
svc-web: 80
svc-db: 5432
```

マッピングを `$std.each` で分解し、`$std.mapping` で組み立て直す形である。
途中に `$std.where` を挟めば、条件を満たすエントリだけを残せる。

### 欠落するデータの剪定

```yaml
$std.list:
  $do:
  - $let:
      row:
        $std.each:
        - {date: d1, code: c1}
        - {date: d2}
        - {date: d3, code: c3}
  - date: ${row.date}
    code:
      $std.prune: ${row.code}
```

```yaml
- {date: d1, code: c1}
- {date: d3, code: c3}
```

2 行目には `code` が無いので、パスアクセス `${row.code}` が `std.fail` を起こし、`$std.prune` がそれを分岐の打ち切りに変える。
失敗を null で埋めたいときは `$std.prune` を `$std.opt` に替える。

### 回数つきの unfold

```yaml
$std.state: {acc: 1}
$in:
  $collect: {$std.range: 5}
  $with:
    $fn: _
    $body:
      $do:
      - $let:
          v: {$std.get: acc}
      - $std.set:
          acc: ${v * 2}
      - - ${v}
```

```yaml
[1, 2, 4, 8, 16]
```

種 1 と関数 (*2) から先頭 5 要素を生成する。
`$std.range` が回数をリストに変え、`$collect` が回り、`$std.state` が種を持ち回る。
アキュムレータを伴う fold も同じ組み合わせで書ける。

### 関数と合成

```yaml
$do:
- $let:
    double:
      $fn: x
      $body: ${x * 2}
    succ:
      $fn: x
      $body: ${x + 1}
- $pipe: 20
  $through:
  - ${double}
  - ${succ}
```

```yaml
41
```

### 失敗の捕捉

```yaml
port:
  $handle:
    $do:
    - $let:
        p: {$std.param: port, $default: 0}
    - $if: ${p <= 0 || p > 65535}
      $then:
        $std.fail: invalid port ${p}
      $else: ${p}
  $with:
    std.fail:
      $fn: msg
      $body:
        $do:
        - $std.log: ${msg}
        - 5432
```

節が `$resume` を呼ばないので、失敗した時点で本体は打ち切られ、節の値 5432 がハンドラ全体の値になる。

### 最初に成功する分岐

```yaml
log_level:
  $std.first:
    $do:
    - $let:
        v: {$std.each: [{$std.param: log_level, $default: null}, {$std.param: fallback_log_level, $default: null}, info]}
    - $std.where: ${v != null}
    - ${v}
```

`$std.first` が選択を処理するので、この境界の値はリストではなく、条件を満たした最初の分岐の単値になる。
パラメータが一つも渡されていなければ `info` になる。

## 設計判断

本節では、検討の分かれ目になった判断とその理由を記す。

**カーネルをただ一つの原始に絞る。**
草案 0.3 は演算 7 つとハンドラ 4 つを言語に組み込んでいたが、`$handle` と `$fn` だけではそれらを利用者が定義できず、根本的な表現能力の欠落を組み込みで塗り潰している形だった。
欠けていた能力を分解すると、任意長の構造の反復、伸長する構成（連結）、計算されたキーによるマッピング構成の三つであり、`$collect` 一つが三つとも与える。
原始に古典的な fold を選ばないのは、fold の step が「アキュムレータに一要素足す」手段すなわち連結を別途要求し、自足しないからである。
`$collect` は構成を演算の内側に持つので自足し、逆に fold は `$collect` と `$std.state` から導出できる。

**fix を置かない。**
一般再帰の原始を提供すれば、std の定義力は上がるが停止性が失われる。
std の派生ハンドラの展開に再帰は不要であり（反復はすべて `$collect` が担う）、必要なのは回数の上界つきの反復だけなので、数を構造に変える `$std.range` で足りる。
述語で止める unfold は μ 作用素として fix と同じ強さを持つため、fix と同時に棄却した。
非有界の反復（空になるまでのページネーションなど）は、1 回の評価を単位としてホスト側がループする領分である。

**演算の名前空間を開き、旧記法を廃止する。**
草案 0.3 の `$each` のようなドットなしの演算は、言語だけが演算を定義できることを意味していた。
本草案では演算名を必ずドット入りとし、標準演算を `std.` 名前空間に置くことで、標準とホスト登録が同じ機構に乗る。
予約キーは 26 個から 17 個に減り、その全てが構文と導出形になった。
旧記法の別名は残さない。二つの綴りが同じ意味を持つと、文書の検索と機械処理の両方が二重化するからである。

**欠落キーを失敗作用にする。**
草案 0.3 では存在しないキーと添字は即エラーだった。
しかしスクレイピング結果のような実データでは、キーの欠落は文書の誤りではなくデータの変動であり、既定値で埋める・その項目を捨てるという回復が本来の処理である。
そこで、文書の形の誤り（未定義の束縛、型の不一致）はエラーのまま残し、データ起因の部分性（キーと添字の欠落、未渡しのパラメータ、未初期化のセル）は `std.fail` に統一した。
maybe のような新しい作用は増やさない。失敗作用がすでに maybe の構造を持っており、その解決は `$std.opt`（null で埋める）と `$std.prune`（分岐を捨てる）が担うからである。
`$std.param` の `$default` も同じ機構の展開になり、遅延評価が失敗の捕捉から自然に出る。

**`pure` を置かない。**
初期スケッチでは `pure: "hello, world"` のような最小の文を検討していた。
直接スタイルでは値がそのまま計算の結果なので、`$do: ["hello, world"]` と書けば足り、専用の構文は不要である。

**モナドの選択を作用の推論に置き換える。**
「このブロックはどのモナドとして評価されるのか」という曖昧さに対して、`singleton: List` のようにブロックごとにモナドを注釈する案も考えられた。
しかし注釈は中身と乖離しうるし、注釈の異なるブロックを合成するときの統合規則が別途必要になる。
作用の推論なら、使われた演算がそのまま答えであり、合成は作用集合の合併で済む。

**`let` と `<-` を統合する。**
初期スケッチの `let:` は名前に反して bind の意味だった。
直接スタイルでは Koka の `val x = ask()` と同じく両者の区別が消えるので、`$let` 一つに統合した。
束縛が作用を起こすかどうかは、右辺に演算が見えるかどうかで判別できる。

**リストの二義性を解消する。**
初期スケッチでは、末尾の `[x, y]` が「2 要素のリスト」なのか「2 つの結果を生む選択」なのか、字面から区別できなかった。
本仕様は前者を literal なリスト、後者を `$std.each` と書き分ける。
用例の 18 要素版と 9 ペア版の対比がこの書き分けを示している。

**YAML タグではなく `$` キーを使う。**
`!do [f, g, h]` のようなタグ構文は YAML としては正当だが、JSON 部分集合で表現できず、タグを扱えないパーサーやツールで壊れる。
「既存の YAML (JSON) パーサーの上で動く」という前提を守るため、マッピングのキーに構文を閉じ込めた。

**`${}` の中に YAML を書けない。**
`${{$std.get: n} + 1}` のように式の中へ演算を埋め込む案は退けた。
YAML パーサーから見ればこれは一個の文字列であり、中の `$std.get` は YAML のノードにならない。
すると作用の推論も、jq やスキーマ検証のような既存ツールも、文字列の中の式言語を別途パースしなければ文書を理解できなくなり、「素の YAML」の原則が崩れる。
演算の結果を式で使うには `$let` で名前を付ける。

**関数を一引数に固定し、呼び出しを演算と同形にする。**
`$call` と名前つき引数を持つ案も考えられたが、Kleisli 合成 `>=>` が要求するのは一引数の関数である。
一引数に固定すれば、関数と演算の呼び出しがどちらも `{$名前: 引数}` になり、利用側は両者を区別しなくてよい。
Koka で `ask()` と自作関数の呼び出しが同形であることに対応する。

**マッピングの生成を専用構文でなくハンドラで扱う。**
計算されたキーを直接書く構文の代わりに、選択の結果を集める `$std.mapping` を置いた。
リストを集める `$std.list` と対になり、キーの条件付き省略も `$std.where` で兼ねられる。
計算されたキーの原始的な構成力は `$collect` の `$into: mapping` にあり、`$std.mapping` はその上の導出である。

**グローバル名前空間を言語に予約する。**
ローカル関数の呼び出しは `$.名前`、演算は `$名前空間.名前` と書き、ドットを含まない `$` 名前は予約キーに限る。
この三分により、言語が将来予約キーを追加しても既存の文書の意味は変わらない。
`$use` のように既定の名前空間を開いて修飾を省く案は、名前を予約済みのグローバル空間へ持ち込み、この保証を壊すので退けた。
修飾の省略は、`$op` で演算を関数値にして `$let` で短い名前に束縛する慣用で足りる。

**草案 0.3 からの変更。**
カーネルを構文 6 形と原始演算 `$collect` に縮めた。
演算 `$each` `$where` `$param` `$get` `$set` `$log` `$fail` を `std.` 名前空間の演算に、ハンドラ `$list` `$mapping` `$first` `$state` を std の派生ハンドラに移し、旧記法を廃止した。
`$std.opt` と `$std.prune` と第一階の標準演算（`std.range` `std.upper` `std.lower` `std.resolve`）を追加した。
存在しないキーと添字、未渡しのパラメータ、未初期化のセルを、エラーから失敗作用 `std.fail` に改めた。
`$resume` を節の本体の中の閉包からも呼べるようにした。
`$param` の `$default` を失敗の捕捉への展開で定義し直した。

## Haskell との対応

用例「選択の基本形」は次の do 式に対応する。

```haskell
do x <- each ["a", "b", "c"]
   y <- each ["x", "y", "z"]
   each [x, y]
```

束縛を持たない文の並び `$do: [f, g, h]` は `f >> g >> h`、すなわち `f >>= \_ -> g >>= \_ -> h` に対応する。
Kleisli 合成 `f >=> g >=> h` は、f と g と h をレキシカルに束縛された関数として、次に対応する。

```yaml
$fn: x
$body:
  $pipe: ${x}
  $through:
  - ${f}
  - ${g}
  - ${h}
```

演算を合成するときは、段に `{$op: 名前空間.名前}` を置く。

意味論のレベルでは、`$do` の文の並びは作用のモナドにおける `>>=` の連鎖に脱糖され、既定ハンドラと明示のハンドラがそのモナドの解釈を与える。
`$collect` はそのモナドの列に対する bind であり、`$std.list` の展開が両者を結ぶ。

## 今後の課題

- スキーマによる型付け。関数値の自己適用を排除して停止性を保証することを含む。
- 演算の部分適用。実装計画を立ててから着手する。
- パラメータを持つハンドラの糖衣構文。`$std.state` の展開が示す「節が関数を返す」形を直接書ける構文。
- 関数値をデータとして直列化する形式。
- 複数文書のストリームの扱い。
- マッピングのキー順序の保存をパーサーに要求することの明文化。
