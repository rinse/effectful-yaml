# CLI（eff-yaml）

effectful-yaml 文書をコマンドラインから評価する CLI である。
カーネルの構文と `std.` 名前空間の演算を持ち、`--ops` でモジュールを渡せばホストの登録演算も使える。

## 使い方

```
eff-yaml [file] [-p name=value]... [--ops module]... [-o file] [--check]
```

- **`file`**：入力の YAML ファイル。省略時と `-` は標準入力から読む。
- **`-p, --param`**：`$std.param` が読む起動時パラメータ。繰り返し指定できる。
- **`--ops`**：登録演算を定義する ESM モジュールのパス（カレントディレクトリからの相対または絶対）。繰り返し指定できる。後に指定したモジュールが同名の演算を上書きする。
- **`-o, --output`**：結果の書き出し先ファイル。省略時は標準出力に書く。
- **`--check`**：`-o` と併用し、書き出し先が最新か検査する。
- **`--version`**：バージョンを表示する。
- **`-h, --help`**：ヘルプを表示する。

評価した結果を YAML として標準出力に書く。
`$std.log` の中身は標準エラー出力に書くので、結果だけをパイプやリダイレクトで受け取れる。
評価に失敗すると終了コード 1 で、メッセージを標準エラー出力に書く（`-o` を指定していてもファイルは書かない）。

出力は原文のコメントと整形を保つ。
評価で値が変わらなかった部分は原文のバイト列のまま出し、値が変わった最小の部分木、すなわち**計算の島**だけを結果の表記に置き換える。
残りがデータであるブロック形式の前置きを持つマッピングでは、前置きの対が行内コメントごと取り除かれ、データのキーの対はコメントを付けたまま残る。
残りが主形の前置きを持つマッピング、フロー形式で書かれた前置き、ブロックのシーケンスの標識と同じ行に書かれた前置きは、マッピング全体が一つの島として置き換わる。
原文の形が結果と対応しないときは、対応しなくなったノード全体、最悪は文書全体が結果の直列化になる。

`-o` を指定したときだけ、出力の先頭に生成元を示す 1 行のヘッダコメントを付ける。
入力ファイル、`-p`、`--ops` の指定をコマンドラインのまま並べる。

```
# Code generated by eff-yaml from config.eyaml -p env=prod --ops ./ops.mjs; DO NOT EDIT.
```

標準入力から読んだときは from の部分を省く。

パラメータの値は YAML として解釈する。
`-p port=5432` は数値になり、文字列にしたければ `-p 'host="5432"'` のように引用する。

`--check` は `-o` と組み合わせたときだけ意味を持つ。
評価結果を `-o` の指定先には書かず、その内容と比較するだけにする。
一致すれば何も出力せず終了コード 0 にする。
ずれていれば再生成コマンドと差分を標準エラー出力に書いて終了コード 1 にする。
ファイルがなければ再生成コマンドだけを書いて終了コード 1 にする。
CI で生成物が最新かどうかを検査する用途を想定している。

## ホストの登録演算

`--ops` に渡すモジュールは、演算名から関数へのマッピングを `default` export する（`ops` という名前つき export でもよい）。

```js
// ops.mjs
export default {
  'str.upper': (s) => String(s).toUpperCase(),
};
```

```
eff-yaml config.eyaml --ops ./ops.mjs
```

関数は同期・非同期のどちらでもよい。
データ起因の失敗（見つからない、一致しない）は `OperationFailure` を投げて通知する。
処理系はこれを呼び出し位置の `std.fail` に翻訳するので、文書側の `$std.opt` や `$with` で捕捉できる（[処理系の利用](usage.md)の「登録演算の失敗」）。
モジュールから `OperationFailure` を import するには、`npm link` かローカルパス依存で `effectful-yaml` を解決できるようにしておく。

```js
// ops.mjs
import { OperationFailure } from 'effectful-yaml';

export default {
  'env.get': (name) => {
    const value = process.env[name];
    if (value === undefined) throw new OperationFailure(`environment variable not set: ${name}`);
    return value;
  },
};
```

`--ops` を複数指定すると、すべてのモジュールのマッピングを後勝ちでマージする。
モジュールが見つからない、または `default` export が演算名から関数へのマッピングでない場合は終了コード 1 でエラーになる。
`std.` 名前空間はホストが登録できないので、演算名にこの接頭辞は使えない。

## 拡張子

effectful-yaml の文書だと明示したいときは、ファイルの拡張子に `.eyaml` を用いる。
文書は素の YAML としてもそのまま妥当なので、`.yaml` のままでもよい。
CLI は拡張子を検査しない。

## 実行

パッケージは未公開なので、リポジトリ内でビルドして使う。

```
npm run build
echo 'greeting: {$std.param: name, $default: world}' | node dist/bin.js -p name=CLI
# greeting: CLI
```

`npm link` を実行すると `eff-yaml` コマンドとして PATH に入る。
コマンド名を `eyaml` にしないのは、Puppet の hiera-eyaml が同名のコマンドを提供していて衝突するからである。

本ページの挙動は `tests/cli.test.ts` が固定している。
