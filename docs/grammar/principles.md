# 設計原則

- 素の YAML：文法上の拡張を一切持たない。特殊な構文はすべてマッピングのキーと文字列の中に閉じ込める。
- 名前空間は環境である：`std` もホストが与える名前も、文書の最外の環境にある束縛にすぎない。`$std.each` は束縛 `std` のキー `each` にある値の呼び出しであり、`$let` で束縛した値の呼び出しと同じ規則で読める。
- カーネルは最小：言語が意味を直接与えるのは 5 形だけである。標準の演算と関数はすべて `std` の中の値であり、その意味論はカーネルへの展開か、値から値への規則で定まる。
- 作用は紙面に現れる：作用を起こすのは演算の呼び出しと、欠落しうるパスアクセスだけである。裸の参照 `${x}` は純粋であり、作用を隠さない。
- 形は書いたとおり：値がリストになるのは、literal なリストと、選択をリストに集める `std.list` の値だけである。処理系が形を補うことはなく、どのハンドラにも捕まらずに境界へ達した選択はエラーになる。分岐が何本になるかを読み手が数えなくても、値の形は紙面から読める。
- リストは常にデータ：YAML のリストがデータでなくなるのは、導出形 `$do` の直下だけである。この例外を一つに絞ることで、そのリストが値なのか文の並びなのかという読み手の迷いをなくす。`$do` はカーネルへの展開で定まるので、カーネルはこの例外を持たない。
- 暗黙の null を作らない：未定義の参照はエラーになる。存在しないキーと添字、渡されていないパラメータ、未初期化のセルの読み出しは、null になるのではなく失敗作用 `std.fail` を起こす。失敗は捕捉できるが、捕捉しなければ文書全体のエラーになる。
- 停止する：一般再帰に相当する原始を置かず、[関数値の流れの検査](checks.md)が自己適用を評価前に拒否する。反復はすべて有限の構造に沿うので、妥当な文書の評価は、停止しないホストの値を与えない限り必ず停止する。
- 型クラスを持たない：作用の多相はハンドラが担う。演算は抽象的な名前を持つ値であり、その意味は包囲する最も近いハンドラが選ぶので、同じ演算がハンドラごとに別の意味を持てる（`std.each` は `std.list` の下では全分岐の列挙に、`std.first` の下では最初の成功までの探索になる）。値のオーバーロードは提供せず、`==` は構造的等価に、算術は数値だけに固定する。

これらを選んだ理由と、退けた代替案は[設計の経緯](../history.md)にある。
