# 文書の読み方

## 値としての YAML

`$` 式を含まない文書は、それ自身に評価される。

```yaml
greeting: hello
```

計算は `$` で始まるキーで書く。

```yaml
$let:
  who: world
$in:
  greeting: hello ${who}
```

```yaml
greeting: hello world
```

`$let` が名前 `who` を束縛し、`$in` の本体がその名前を `${...}` で参照する。
本体はマッピングなので、データのキー `greeting` はそのまま結果に残る。

## 評価の規則

文書はテンプレートとして外側から評価される。
`$` で始まるキーを持つマッピングを `$` 式と呼ぶ。
評価関数は次の規則に従う。

- スカラーは、`${...}` の補間を解決した値になる。
- リストは、各要素を先頭から順に評価したリストになる。
- `$` キーを持たないマッピングは、各値を文書順に評価したマッピングになる。
- `$` 式は、主キーごとに定められた規則で評価する。

## 構文と呼び出しは綴りで分かれる

`$` キーは名前の綴りで二つに分かれ、解決の優先順位のような暗黙の規則を持たない。

- ドットを含まない名前（`$let`）は、言語が予約する構文である。予約されていない名前はエラーになる。
- ドットを含む名前（`$std.each`、`$vault.read`、`$.f`）は、環境にある値の呼び出しである。

読み手はドットの有無だけで、言語が意味を与える構文か、値の呼び出しかを見分けられる。
予約キーは次の 12 個である。

| キー | 役割 |
|---|---|
| `$let` `$in` | 束縛と逐次 |
| `$if` `$then` `$else` | 条件分岐 |
| `$fn` `$param` | 関数 |
| `$handler` `$in` `$resume` | ハンドラ |
| `$do` | 文の並び |
| `$for` | 選択の束縛の頭 |
| `$default` | 失敗したときの既定値 |

`$in` は `$let`・`$for`・`$handler` が共有する一つのキーである。

## `$` 式の形

`$` 式は、主形か、文脈の導入を伴うマッピングのどちらかである。

| 形 | 書き方 |
|---|---|
| 主形 | 主キー（`$do`、`$if`、呼び出しの `$std.each` など）ちょうど一つと、その主キーに従属する補助キー（`$then` など）だけからなる |
| 文脈の導入を伴うマッピング | 頭キー `$let`・`$for`・`$handler` を一つ以上持ち、頭を除いた残りのキーを本体に取る |

主形にデータのキーを混ぜることはエラーである（`{$std.input: x, name: api}`）。

文脈の導入を伴うマッピングでは、文書順で最初の頭キーがそのマッピングに文脈を導入し、そのキーを除いた残りが本体である。
残りは次のいずれかである。

- `$in` ただ一つ。その値が本体の式である。
- データのマッピング。
- 主形。
- 再び文脈の導入を伴うマッピング。

残りがこのどれでもないマッピングはエラーである（`{$let: 束縛, $in: 式, キー: 値}`）。
頭キーどうしの並びは文書順であり、先に書いたものが外側になる。
頭キー以外のキーの位置は意味を持たない。
YAML は一つのマッピングの中の重複キーを許さないので、各頭キーは一つずつしか置けない。
残りを本体に取る規則は導出形であり、展開は[導出形](derived.md)の「文脈の導入」で定める。

補助キー `$default` はどの `$` 式にも添えられる。
`$` 式の形の判定は `$default` を除いてから行う。
