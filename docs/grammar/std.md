# std

`std` は初期環境の束縛であり、値は標準の演算と関数を収めたマッピングである。
ホストは `std` の中に値を加えられない。

| 名前 | 種類 | 意味 |
|---|---|---|
| `std.each` | 演算 | 要素を一つずつ選ぶ。値は選ばれた要素。 |
| `std.param` | 演算 | 起動時に与えられたパラメータを読む。 |
| `std.get` | 演算 | セルの現在値を読む。 |
| `std.set` | 演算 | セルに値を書く。値は null。 |
| `std.log` | 演算 | 値をログに流す。値は null。 |
| `std.fail` | 演算 | 計算を失敗させる。値をエラーメッセージとする。 |
| `std.where` | 関数 | 条件を満たさない分岐を打ち切る。 |
| `std.range` | 関数 | 自然数 n をリスト `[0, ..., n-1]` に変える。 |
| `std.collect` | 関数 | 構造を回り、要素ごとの結果を一つの構造に組み立てる。 |
| `std.lookup` | 関数 | マッピングを計算したキーで引く。 |
| `std.merge` | 関数 | マッピングのリストを一つに重ねる。 |
| `std.list` | 関数 | 本体の閉包を受け取り、全分岐の結果を文書順に並べたリストにする。 |
| `std.mapping` | 関数 | 本体の閉包を受け取り、全分岐の `{key, value}` を集めたマッピングにする。 |
| `std.first` | 関数 | 本体の閉包を受け取り、失敗しなかった最初の分岐の値にする。 |
| `std.state` | 関数 | 初期値と本体の閉包を受け取り、状態のハンドラの下で本体を評価する。 |

関数の意味論は展開が定める。
展開の中で起きる作用は、展開が名指すハンドラが処理し尽くすので、外へは出ない。
展開の中から境界へ達した作用のエラー文言は、展開の内側ではなく、利用者が書いた呼び出しの形と位置を名乗る。

## 作用を起こす演算

標準の演算は 6 つである。
その意味は、[既定ハンドラ](effects.md)と標準のハンドラの節が与える。

- `std.each` の引数がリストなら各要素を、マッピングなら各エントリを `{key: キー, value: 値}` の形で、文書順に選ぶ。`$std.each: ${xs}` のようにデータ駆動の反復が書ける。空のリストやマッピングは分岐 0 本を意味し、その分岐は打ち切りになる。選ばれた要素に名前を付けるのは頭 `$for` である。
- `std.param` の引数は名前の文字列である。渡されていないパラメータの読み出しは、呼び出し位置で `std.fail` を起こす。既定値を添えるには `$default` を使う。
- `std.get` の名前空間は `$let` の束縛とは別である。同名でも互いに関係しない。未初期化のセルの読み出しは `std.fail` を起こす。この失敗は `std.state` の展開の節の本体で起こるので、そのセルを解決する状態ハンドラの位置で生じる。既定の状態ハンドラは境界にあるため、文書内で捕捉するには、明示の `std.state` を捕捉するハンドラの内側に置く。
- `std.set` は複数のセルを文書順に書ける。
- `std.log` の既定ハンドラは値をホストのログ出力に流す。
- `std.fail` の既定ハンドラは値をメッセージとして文書全体のエラーにする。

## 関数

### std.where

条件を満たさない分岐を打ち切る。

```yaml
$std.where: 条件式
```

```yaml
# std.where の値
$fn: cond
$body:
  $if: ${cond}
  $then: null
  $else: {$std.each: []}
```

条件が真なら値は null である。
偽なら空の `$std.each` が分岐 0 本の選択となり、包囲する選択のこの分岐が打ち切られる。
条件が真偽値でなければエラーになる。
打ち切りを処理するのは、展開に現れる `std.each` を処理する選択のハンドラである。

### std.range

自然数 n をリスト `[0, 1, ..., n-1]` に変える。
数から構造への唯一の橋であり、回数の上界つきの反復に使う。
引数が自然数でなければエラーになる。
導出できないが評価器の協力も要らないので、値から値への規則で定める。
回数の上界つきの unfold（種と関数からの列の生成）は、`std.range` と `std.collect` と `std.state` で書ける（[用例](examples.md)の「回数つきの unfold」）。

### std.collect

畳み込みである。
構造を先頭から回りながら、要素ごとの結果を一つの構造に組み立てる。

```yaml
$std.collect:
  in: 対象の式
  with: 一引数関数の式
  into: list または mapping   # 省略時 list
```

- 対象はリストまたはマッピングである。マッピングは `{key: キー, value: 値}` のエントリの列として文書順に回る。
- `with` の関数を各要素に文書順に適用する。関数は要素ごとにリストを返さなければならない。
- `into: list` のとき、全要素の結果リストを文書順に連結したリストになる。
- `into: mapping` のとき、結果リストの各要素は `key` と `value` のちょうど二つのキーを持ち `key` が文字列であるマッピングでなければならず、全エントリを集めた一つのマッピングになる。キーの重複はエラーである。
- 空の対象の値は、`into: list` なら空リスト、`into: mapping` なら空マッピングである。

```yaml
# 各要素を二重にする: [1, 1, 2, 2, 3, 3]
$std.collect:
  in: [1, 2, 3]
  with:
    $fn: x
    $body:
    - ${x}
    - ${x}
```

`std.collect` 自身は作用を起こさず、ハンドラで捕捉できない。
作用は引数の式と `with` の関数本体の作用の合併である（関数呼び出しと同じ規則）。
対象が有限である限り適用は有限回なので、`std.collect` は停止性を壊さない。
関数を引数に取るので導出できないが、値から値への規則で定まり、評価器が実装する。

map は要素を一要素リストで包む関数で、filter は空リストを返す分岐で、連結は恒等関数で書ける。
アキュムレータを伴う古典的な fold は、`std.collect` と `std.state` の組で導出できる。

### std.lookup

マッピングを計算したキーで引く。

```yaml
$std.lookup:
  in: マッピングの式
  key: キーの式
```

式のパス `${m.k}` のキーが literal に限られるのに対し、`std.lookup` はキーを式で与えられる。
意味は選択による照合への展開で定める。

```yaml
# std.lookup の値
$fn: arg
$body:
  $handler: ${std.first}
  $in:
    $do:
    - $for:
        e: ${arg.in}
    - $std.where: ${e.key == arg.key}
    - ${e.value}
```

キーが在ればその値になり、無ければ `std.first` の規則によりこの位置で `std.fail` が起きる。
したがって欠落は、パスアクセスの欠落と同じように `$default` と `$handler` で扱える。
失敗の値の文言だけは展開に委ねず、欠落したキーを含む説明文とする。
`in` の値がマッピングでないことと `key` の値が文字列でないことは、データの変動ではなく型の誤りなのでエラーである（`std.collect` のエントリ検査と同じく契約に含め、展開には現れない）。
作用集合への寄与は `std.fail` と引数の式の作用だけである。

### std.merge

複数のマッピングを一つに重ねる。

```yaml
$std.merge: マッピングのリストの式
```

同じキーは後のマッピングの値が勝ち、キーの位置は初出の位置が保たれる。
マージは浅い。値がともにマッピングでも再帰せず、後の値がそのまま採られる。
入れ子の階層で重ねたいときは、その階層に `std.merge` を書く。
null は普通の値として上書きする。キーの削除はマージの仕事ではなく、`std.mapping` と `std.where` の省略の慣用で行う。

意味は二項のマージの左畳み込みで定める。
空のリストは `{}` に、`[m1, ..., mn]` は `{}` から始めて m1 から mn までを順に重ねた結果になる。
二項の merge(a, b) の意味は次の展開で定める。

```yaml
# merge(a, b) の展開。b が勝ち、キーの位置は初出の位置。
$let:
  a: 先の式
  b: 後の式
$handler: ${std.mapping}
$in:
  $do:
  - $for:
      phase: [0, 1]
  - $let:
      src:
        $if: ${phase == 0}
        $then: ${a}
        $else: ${b}
  - $for:
      e: ${src}
  - $let:
      fresh:
        $if: ${phase == 0}
        $then: true
        $else:
          $let:
            _:
              $std.lookup:
                in: ${a}
                key: ${e.key}
          $in: false
          $default: true
  - $std.where: ${fresh}
  - key: ${e.key}
    value:
      $if: ${phase == 0}
      $then:
        $std.lookup:
          in: ${b}
          key: ${e.key}
        $default: ${e.value}
      $else: ${e.value}
```

a の側（phase 0）は自分のキーをその位置のまま並べ、b に同じキーが在ればその値で差し替える。
b の側（phase 1）は a に無いキーだけを後ろに足す。
左畳み込みは `std.collect` で要素を回りながら途中結果を `std.state` のセルに持ち回る形で書ける。

マージは結合的で単位は `{}` であり、この性質はキーの並びを含めて成り立つ。
引数がリストでないことと、要素がマッピングでないことは型の誤りなのでエラーである。
`std.mapping` がキーの重複をエラーにするのに対し、`std.merge` は重複を優先順位で解決する。
前者は新しいマッピングの構成であり重複は誤りの兆候、後者は重複の解決そのものが目的である。
作用集合への寄与は引数の式の作用だけである。

## ハンドラを立てる関数

`std.list`・`std.mapping`・`std.first`・`std.state` の値は、本体の閉包を受け取る関数である。
`$handler` の式に置く形で使う（[ハンドラの再利用](syntax.md)）。

### std.state

初期値と本体の閉包を受け取り、状態のハンドラの下で本体を評価する。

```yaml
$handler: {$std.state: {n: 0}}
$in: 本体の式
```

節は状態変換関数、すなわち「現在の状態を受け取り、次の状態への適用を経て最終的な値を返す関数」を返す古典的なパラメータ付きハンドラである。
状態はセルのエントリの列であり、`std.collect` はマッピングもエントリの列として回るので、初期値のマッピングをそのまま最初の状態にできる。

```yaml
# std.state の値
$fn: [init, run]
$body:
  $let:
    step:
      $handler:
        std.get:
          $fn: name
          $body:
            $fn: s
            $body:
              $let:
                hits:
                  $std.collect:
                    in: ${s}
                    with:
                      $fn: e
                      $body:
                        $if: ${e.key == name}
                        $then:
                        - ${e.value}
                        $else: []
                k:
                  $resume: ${hits[0]}
              $in:
                $.k: ${s}
        std.set:
          $fn: m
          $body:
            $fn: s
            $body:
              $let:
                s2:
                  $std.collect:
                    in:
                    - ${m}
                    - ${s}
                    with:
                      $fn: part
                      $body:
                        $std.collect:
                          in: ${part}
                          with:
                            $fn: e
                            $body:
                            - ${e}
                k:
                  $resume: null
              $in:
                $.k: ${s2}
        return:
          $fn: x
          $body:
            $fn: s
            $body: ${x}
      $in: {$.run: null}
  $in:
    $.step: ${init}
```

`std.set` の節は、書かれたマッピングのエントリを列の先頭に足す。
`std.get` の節は名前の一致するエントリを先頭から集めるので、`${hits[0]}` は最新の値になり、セルが未初期化ならちょうど `std.fail` を起こす。
継続の再開結果も状態変換関数なので、それを現在の状態に適用して続行する。
`return` の段で状態を捨てるので、値は本体の値であり最終状態は現れない。
本体をこのハンドラで包んで得た関数 `step` を初期値に適用する。
初期値の式は `std.state` の最初の引数として本体より先に評価される。

`std.state` を選択に対してどこに置くかで、状態と分岐の関係が決まる。

```yaml
# 貫流（既定と同じ）: 状態が分岐から分岐へ持ち越される
$handler: {$std.state: {n: 0}}
$in:
  $handler: ${std.list}
  $in: 選択を含む本体
```

```yaml
# 分岐点で分かれる: 各分岐が選択時点の状態を引き継ぎ、以後は独立に進む
$handler: ${std.list}
$in:
  $handler: {$std.state: {n: 0}}
  $in: 選択を含む本体
```

この区別は、`$in` を省いた `$handler` をどの `$do` の文に置くかでも表現できる。
選択のハンドラを包む `$do` に置けば貫流になり、選択のハンドラの中の `$do` に置けば分岐点で分かれる。

### std.list

本体の閉包を受け取り、選択を処理して、全分岐の結果を文書順に並べたリストに評価される。

```yaml
# std.list の値
$fn: run
$body:
  $handler:
    std.each:
      $fn: xs
      $body:
        $std.collect:
          in: ${xs}
          with:
            $fn: x
            $body:
              $resume: ${x}
    return:
      $fn: x
      $body:
      - ${x}
  $in: {$.run: null}
```

ハンドラは深いので、各 `$resume` の値は残りの計算を同じハンドラで処理し尽くしたリストであり、`std.collect` がそれらを連結する。
内側に選択がなければ `return` 節だけが働き、要素 1 のリストになる。
`std.where` の打ち切りは、展開により空の `$std.each` として現れ、`std.each` の節が 0 個の候補を畳んで分岐を消す。
分岐の中の失敗は節にないので処理せず、全体の失敗として伝播させる。

### std.mapping

`std.list` の上の導出であり、集めたエントリの列をマッピングに組み立てる。

```yaml
# std.mapping の値
$fn: run
$body:
  $std.collect:
    in:
      $handler: ${std.list}
      $in: {$.run: null}
    with:
      $fn: e
      $body:
      - ${e}
    into: mapping
```

`std.list` が全分岐の `{key, value}` を文書順のリストに集め、`std.collect` がその各要素をそのまま流しながら `into: mapping` でマッピングへ組み立てる。
エントリの検査（ちょうど二つのキー、`key` は文字列、重複の禁止）は `std.collect` の契約に含まれるので、展開には現れない。
`std.where` で分岐を打ち切れば、条件を満たすエントリだけを持つマッピングが作れる。
これは「null を入れること」と「キーが無いこと」の区別、すなわちキーの条件付き省略を兼ねる。

### std.first

本体の閉包を受け取り、選択と失敗を処理して、失敗しなかった最初の分岐の値に評価される。
最初の成功より後の分岐は評価されず、その作用も起きない。
すべての分岐が失敗または打ち切りなら、全体が `std.fail` になる。

展開は二段のハンドラからなる。
外側は成功の印を持ち回り、内側は選択と失敗を処理する。
印の持ち回りには `std.state` と同じ技法を使うが、`std.state` そのものは流用できない。
本体が `std.get` や `std.set` を使えば同じ記憶を共有してしまうからである。
そこで印は、ローカル作用の宣言 `taken`（印を読む）と `mark`（印を立てる）で持ち回る。
宣言が作る演算の値は宣言ごとに新しく、文書の他のどの演算とも別なので、本体の作用と衝突しない。

```yaml
# std.first の値
$fn: run
$body:
  $let:
    step:
      $handler:
        taken:
          $fn: _
          $body:
            $fn: t
            $body:
              $let:
                k:
                  $resume: ${t}
              $in:
                $.k: ${t}
        mark:
          $fn: _
          $body:
            $fn: t
            $body:
              $let:
                k:
                  $resume: null
              $in:
                $.k: true
        return:
          $fn: x
          $body:
            $fn: t
            $body: ${x}
      $in:
        $handler:
          std.each:
            $fn: xs
            $body:
              $std.collect:
                in: ${xs}
                with:
                  $fn: x
                  $body:
                    $if: {$.taken: null}
                    $then: []
                    $else:
                      $resume: ${x}
          std.fail:
            $fn: _
            $body: []
          return:
            $fn: x
            $body:
              $do:
              - $.mark: null
              - - ${x}
        $in: {$.run: null}
    results: {$.step: false}
  $in: ${results[0]}
```

印のハンドラは、選択を処理する内側の `$handler` を包む位置に置く。
`std.state` の貫流の配置と同じである。
包む順序が逆で選択の内側に印を置くと、各分岐がそれぞれ真新しい印を持つことになり、先行する分岐の成功が後続の分岐から見えなくなって、短絡が起きない。

内側の `$handler` の節の役割は次のとおりである。

- `std.each`：`std.collect` で候補を先頭から回る。印が立っていれば、その候補では再開せず `[]` を返す（評価も作用も起きない）。印が立っていなければ、候補の値で `$resume` する。`std.where` の打ち切りは空の `$std.each` として現れ、この節が 0 個の候補を畳んで `[]` を返す。
- `std.fail`：ハンドラは深いので、`std.each` の分岐の途中で起きた失敗もこの節が受け止める。再開せず `[]` を返すので、失敗した分岐は候補の列に何も残さず、`std.collect` は次の候補へ進む。
- `return`：本体が値 `x` に達したら、まず印を立ててから `x` を要素 1 のリストに包む。成功することと印を立てることを同じ場所で行うので、以後の `std.each` の候補はその成功を確実に見られる。

内側の `$handler` の値は、`std.list` の展開と同じ理由でリストになる。
外側のハンドラが返す状態変換関数を初期の印 `false` に適用したものが `results` であり、`$handler: ${std.first}` の値は `${results[0]}` である。
`${hits[0]}` が未初期化のセルで `std.fail` を起こす `std.state` の展開と同じ理由で、`results` が空リストのとき、すなわちすべての分岐が失敗または打ち切りだったとき、`${results[0]}` は `std.fail` を起こす。
この `std.fail` は二段のハンドラの外で起きるので、どちらの節も受け止めず、そのまま外側へ伝播する。
