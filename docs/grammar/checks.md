# 評価前の検査

処理系は評価を始める前に文書全体を検査する。
どちらの検査も注釈を要しない。
型を書く構文はなく、予約キーも増えない。

## 作用の推論

作用は演算の値で数える。
処理系は、関数値の流れの検査と同じ近似で、各呼び出しの位置に流れうる演算の値を求める。
各ノードの作用集合は、その内側の呼び出しに流れうる演算を合併し、ハンドラが節に挙げた演算を除いて、節と `return` の本体の作用を加えたものである。
出現だけを見るので、実行されない分岐（`$if` の選ばれない側、`$default`）の中の演算も作用に数える。
導出形は展開してから数える。
`$for` の出現は `std.each` を加え、`$default` の出現は本体の `std.fail` を除いて既定値の式の作用を加え、`std.where` の出現は `std.each` を加える。
欠落しうるパスアクセスと、失敗を通知しうるホストの値の呼び出しは `std.fail` を加える。
ローカル作用の宣言が作る演算の呼び出しはその演算を加え、宣言したハンドラがそれを除く。
演算の値が持ち出されて別の位置で呼ばれうることは、関数値の流れと同じ推論で数える。

これにより、文書が要求するハンドラの一覧（作用シグネチャ）が実行前に定まる。

## 関数値の流れと停止性

処理系は関数値と演算の値の流れを文書全体で推論し、自己適用を含みうる文書をエラーとして拒否する。

関数値を作るのは `$fn` だけである。
入力とホストの値の呼び出しの結果は常にデータであり、閉包が文書の外から入ってくることはない。
したがって文書に現れる `$fn` は有限個であり、文書内の各位置に現れうる関数値は、実行せずに過大近似できる。

各 `$fn` が見る関数値——パラメータに流れ込みうる値、本体の中の呼び出しの呼び先、本体の中の演算の値（ハンドラの節が返す値、状態のセルを通って戻る値、節の `$resume` で再開される値を含む）——から、構造（マッピング・リスト・分岐）をたどって別の `$fn` に到達しうるとき、前者は後者に依存する。
この依存が循環をなす（自分自身への依存を含む）文書は、評価前にエラーになる。
関数値を状態のセルに置き、読み出して適用する後結び（Landin の knot）も、演算の値の経路として同じ循環に数える。

例外として、`$resume` の結果の適用は依存に数えない。
継続の適用はハンドラの畳み込みに沿って必ず停止するからである（`std.state` の展開はこの形である）。

値が関数とデータの間で分岐すること自体は誤りではない。
検査が拒むのは、自己適用が要求する循環だけである。
推論は作用の推論と同じ出現主義であり、実行されない分岐の中の呼び出しも数える。
検査は、`$` キーを含めて文書の構文をそのまま降りる構文パス（例 `config.$let.f`）で位置を報告する。

この検査に通った文書の評価は、停止しないホストの値を与えない限り必ず停止する。
