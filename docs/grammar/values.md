# 値と環境

## 値の三種

- データ：スカラー、リスト、マッピング。文書の値になれる。
- 関数：`$fn` が作る閉包。呼び出すと本体が走る。
- 演算：作用の名前を持つ値。呼び出すと作用を起こし、包囲する最も近いハンドラの節が引数を受け取る。

演算の値の出どころは二つに限られる。
一つは初期環境であり、`std.each` のような標準の演算とホストが与えた演算が最初から入っている。
もう一つは、`$handler` の節のマッピングに `throw:` のようなドットを含まない名前で書いた節（ローカル作用の宣言）であり、`$handler` を評価するたびに新しい演算の値を作る（[ローカル作用の宣言](syntax.md)）。
ハンドラは値の種類ではない。
ハンドラを立てるのは構文 `$handler` であり、再利用するハンドラは本体の閉包を受け取る関数として書く（[ハンドラの再利用](syntax.md)）。

関数と演算は文書の中でだけ意味を持つ。
どちらかが作用境界（[作用の伝播](effects.md)）の外へ出て文書の値に残ることはエラーである。
関数と演算を `==` で比較することもエラーである。

## 環境と名前の解決

文書は環境の下で評価される。
環境は、名前と値の組である束縛の列である。
束縛を足すカーネルの構文は次の三つであり、足した束縛はそれぞれの本体（`$let` では後の束縛の右辺も）の中でだけ見え、同じ名前の外側の束縛を隠す。

- `$let`：右辺の値を名前に束縛する。
- `$fn`：呼び出されたとき、引数の値をパラメータ名に束縛する。
- `$handler`：節のマッピングに `throw:` のようなドットを含まない名前（`return` を除く）の節を書くと、その節ごとに新しい演算の値を作り、節の名前に束縛する。本体からは `{$.throw: 引数}` のように呼べる。`std.each:` のような名前空間つきの節と、関数の式で与えた `$handler` は束縛を足さない。

導出形の `$for` は `$let` への展開を通じて束縛する。
文書の最外の環境を初期環境と呼び、処理系が用意する。
初期環境には、標準の演算と関数を収めたマッピングを値とする束縛 `std` と、ホストが与えた束縛がある。

ドットを含む `$` キーと、`${...}` の中の参照名は、どちらもパスである。
パスは名前をドットで繋いだ列で、最初の区画が束縛を解決し、残りの区画があればその値のマッピングを順にキーでたどる。
最初の区画が空の `$.名前` は、一区画のパスを予約キーと区別して書く書き方である。

`$std.each` は束縛 `std` のキー `each` の値の呼び出しであり、`$vault.read` はホストが与えた束縛 `vault` のキー `read` の値の呼び出しであり、`$.f` は束縛 `f` の値の呼び出しである。
三つはすべて同じ規則で解決され、呼び出しの規則も同じである。
`std` は普通の束縛なので、`$let` で同じ名前を束縛すれば、その本体では初期環境の `std` が隠れる。

```yaml
$let:
  std:
    greeting: hello
$in:
  a: ${std.greeting}
  b: {$std.each: [1, 2]}
```

本体の `std` は `$let` が束縛したマッピングを指すので、`${std.greeting}` は `hello` に解決するが、`$std.each` はキー `each` をたどれないので、文書全体が `missing key 'each'` のエラーになる。

パスの最初の区画がどの束縛にも解決しない呼び出しや参照を含む文書は、評価を始める前に `undefined reference` で拒否される。
環境はレキシカルに決まるので、この判定は評価を要しない。
残りの区画がマッピングにないとき、参照はデータ起因の失敗 `std.fail` を起こし、呼び出しは捕捉できないエラー `missing key` になる（[呼び出し](syntax.md)）。
