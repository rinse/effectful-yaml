# ホストの値

処理系は、初期環境に束縛を加える手段をホストに与える。
ホストが与える値は演算か関数であり、名前は `vault.read` のように束縛とキーの形で与える。
グローバルな名前空間は言語の予約キーのためにあり、`std` は標準のためにあるので、ホストはそれ以外の束縛名を使う。

```yaml
password: {$vault.read: secret/db/password}
```

| 種類 | 振る舞い |
|---|---|
| 演算 | 呼べば作用を起こす。文書の `$handler` が横取りでき、境界に達したときだけホストの実装が既定ハンドラとして走る。作用シグネチャに数えられる。 |
| 関数 | 呼べばホストの実装が走る。作用ではないので[作用シグネチャ](checks.md)に現れず、横取りもできない。 |

どちらの実装も、値を返す代わりに失敗を通知できる。
処理系は通知を、呼び出し位置で起きた `std.fail`（値は通知された値）として扱い、通常の規則で伝播させる。
したがって途中の `$default` や `std.fail` の節を持つ `$handler` が捕捉でき、捕捉されなければ文書全体のエラーになる。
失敗の通知はデータ起因の部分性（一致しないセレクタなど）のためにあり、ホスト実装のその他の例外は捕捉できないエラーである。

閉包と演算の値をホストの実装へ渡すことはできない。
処理系はこれを二重に検査する。
ホストの値の呼び出しの引数に閉包が流れうる文書は評価前に拒まれ、実行時にホストへ渡る直前の引数にも同じ検査が働く。
名前が長くなるときは、引数を素通しする `$fn` を `$let` で短い名前に束縛する慣用で書く。
