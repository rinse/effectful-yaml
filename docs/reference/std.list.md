# std.list

`std.list` は本体の閉包を受け取り、選択を処理して、全分岐の結果を文書順に並べたリストに評価される。

- 種別：std の関数（ハンドラを立てる）
- 処理する演算：`std.each`

## 構文

```yaml
$handler: ${std.list}
$in: 本体の式
```

`$handler` の式が関数なら本体の閉包を渡す呼び出しに展開されるので、この形は `{$std.list: {$fn: 本体}}` と同じ意味である（[$handler](handler.md) のハンドラの再利用）。
本体を閉包にせず `{$std.list: 本体}` と書くと、呼び出しは値渡しなので本体の作用がハンドラの立つ前に周囲へ合流してしまう。

## 規則

- 本体の全分岐の結果を、文書順（深さ優先）に並べたリストに評価される。
- 本体に選択がなければ、要素 1 のリストになる。値の形をリストに固定したいときにも使える。
- 打ち切られた分岐は要素を残さない。全分岐が打ち切られれば空リストになる。
- 失敗は処理しない。一つの分岐の失敗は全体の失敗として伝播する。
- 選択を含む計算はいずれかの選択のハンドラで包まなければならない。どのハンドラにも捕まらずに作用境界へ達した選択は `unhandled choice` のエラーになる。
- `std` の値はホストの値であり `$fn` ではないので、`std.list` の本体の中に `std.list` を重ねることは自己適用の検査を受けない。利用者が書いた同じ関数を、それに渡す本体の中で再び使う形は拒まれる（下記）。

## 展開と関数による実装

`std.list` の値は次の関数である。
処理系は等価な組み込みで最適化してよいが、観測できる振る舞い（値、作用、ログの順序）はこの関数と一致しなければならない。

```yaml
$let:
  list:
    $param: run
    $fn:
      $handler:
        std.each:
          $param: xs
          $fn:
            $std.collect:
              in: ${xs}
              with:
                $param: x
                $fn:
                  $resume: ${x}
        return:
          $param: x
          $fn:
          - ${x}
      $in: {$.run: null}
$in:
  $handler: ${list}
  $do:
  - $for:
      n: [1, 2, 3]
  - ${n * 10}
```

```yaml
[10, 20, 30]
```

ハンドラは深いので、各 `$resume` の値は残りの計算を同じハンドラで処理し尽くしたリストであり、`std.collect` がそれらを連結する。
`std.each` の節は `std.collect` で候補を回り、各候補について関数の本体（節の本体が作った閉包）の中で `$resume: ${x}` を呼ぶ。
この呼び出しは、[$handler](handler.md) が定める「節の中の閉包から `$resume` を呼べる」規則の具体例である。
[std.where](std.where.md) の打ち切りは空の `$std.each` として現れ、`std.each` の節が 0 個の候補を畳んで空リストを返すので、専用の節は要らない。
`return` 節は、本体が演算を起こさず値 `x` に達した末端を要素 1 のリスト `[x]` に包む。
内側に選択がなければ `return` 節だけが働き、全体は要素 1 のリストになる。
分岐の中の失敗は `std.fail` の節がないので処理されず、そのまま外側へ伝播して全体の失敗になる。

この関数版を入れ子にするには、`$let` で値を二つ作る。
本体の閉包を受け取る関数を、その閉包の本体の中で再び使う形は、関数値の流れの検査が自己適用として拒むからである。

## 例

```yaml
sizes:
  $handler: ${std.list}
  $do:
  - $for:
      n: [1, 2, 3]
  - ${n * 10}
```

```yaml
sizes: [10, 20, 30]
```
