# $fn

`$fn` は関数の値（閉包）を作る。
呼び出しは `{$パス: 引数}` の形で書き、パスが関数に解決すれば関数の呼び出し、演算に解決すれば演算の呼び出しになる。

- 種別：カーネル構文（関数。作用を持たない。呼び出しの作用は引数と本体に由来する）
- 補助キー：`$body`

## 形

```yaml
$fn: パラメータ名
$body: 式
```

```yaml
$fn: [パラメータ名, パラメータ名, ...]
$body: 式
```

## 規則

- 評価すると、定義位置の束縛を捕まえた閉包になる。
- カーネルの関数はパラメータをちょうど一つに固定する。Kleisli 合成 `>=>` で合成できるのは一引数の関数だけだからである。複数の値はマッピングで一つに包み、本体から `${arg.名前}` のようにパスで参照する。
- 閉包が作用境界の外へ出て文書の値に残ることはエラーである。閉包を `==` で比較することもエラーである。
- 呼び出しは引数を評価してからパラメータに束縛し、本体を定義位置の環境で評価する（レキシカルスコープ）。
- 呼び出しの作用は、引数の作用と本体の作用の合併である。本体に現れる演算は、その関数がどの位置から呼ばれるかによらず作用シグネチャに数えられる。本体が選択を起こす関数は、選択を処理するハンドラの内側で呼ぶ。
- `$let` が非再帰なので、名前による再帰は書けない。反復は [$for](for.md) と [std.collect](std.collect.md) のようにデータ構造に沿った形で書く。言語は fix に相当する原始を提供しない。
- 関数値の自己適用（引数を通じて自分自身に到達しうる適用）は、評価前の関数値の流れの検査が拒否する（[言語仕様](../grammar.md)の「関数値の流れと停止性」）。
- 閉包と演算の値をホストの値の呼び出しに渡すことはできない。処理系は評価前と実行時の二重に検査する。
- `{$fn: x, $let: 束縛, $body: 式}` の `$let` は、残りである `$fn` 全体に文脈を導入する（[言語仕様の文脈の導入の節](../grammar.md)）。束縛は関数の外で一度だけ評価され、`x` は束縛の右辺から見えない。

## 引数名の列と部分適用

`$fn` には相異なる名前の列（1 個以上）も書ける。
この形は導出形であり、意味はカリー化の展開で定める。

```
{$fn: [a, b, ...残り], $body: 本体} ≡ {$fn: a, $body: {$fn: [b, ...残り], $body: 本体}}
{$fn: [a], $body: 本体}            ≡ {$fn: a, $body: 本体}
```

- 展開の各段は一引数のカーネル関数なので、一つ固定の原則は崩れない。
- **部分適用**は通常の適用である。先頭の引数だけを与える呼び出しは、残りの引数を待つ閉包を返す。
- 引数の式はその適用の位置で正格に評価され、値が閉包に捕まり、再評価されない。引数の式の作用は部分適用の位置で一度だけ生じ、本体の作用は最後の引数が与えられて本体が走る位置で生じる。
- 空の列、文字列でない要素、名前の重複は形の誤りでありエラーになる。
- ハンドラの節と `std.collect` の `with` は処理系が一引数で呼ぶ位置なので、そこに引数 2 個以上の `$fn` を書くと閉包が結果の値になり、多くの場合そのまま関数値の脱出のエラーへ至る。
- マッピング引数の関数や演算を部分適用するには、引数を組み立てるカリー化された関数（adapter）を `$let` で一度宣言する。

## 呼び出しとパス

`$` キーは名前の形で二つに分かれ、解決の優先順位のような暗黙の規則を持たない。

| 形 | 指すもの |
|---|---|
| `$パス`（ドットを含む名前） | 環境にある値の呼び出し（`$std.each`、`$vault.read`、`$.f`） |
| `$名前`（ドットを含まない名前） | 予約キー（言語が予約する 12 個。それ以外はエラー） |

- パスは名前をドットで繋いだ列である。最初の区画が環境の束縛を解決し、残りの区画があればその値のマッピングを順にキーでたどる。最初の区画が空の `$.名前` は、一区画のパスを予約キーと区別して書く形である。
- 束縛を導入するのは [$let](let.md) と `$fn`、および [$handler](handler.md) のローカル作用の宣言である。`std` とホストの名前も初期環境の束縛にすぎないので、`$std.each` と `$.f` は同じ規則で解決される。
- たどり着いた値が関数なら関数の呼び出し、演算なら演算の呼び出しであり、データならエラーである。
- パスの最初の区画がどの束縛にも解決しない文書は、評価を始める前に `undefined reference` で拒否される。残りの区画がマッピングにないことは、文書の形に関わる誤りなので失敗作用ではなくエラーの語彙（`cannot access key`、`missing key`）で報告する。
- 添字 `[0]` はパスでは書けない。添字の先や、計算した式の先にある関数は、[$let](let.md) で名前に束縛してから `$.名前` で呼ぶ。
- 最初の区画が `return` である呼び出し（`$.return` と `$.return.x` を含む）は形の誤りであり、評価前に `return is reserved: $.return is not callable` で拒否される。`return` は [$handler](handler.md) の節名として予約されており、節に書いた `return` は束縛を導入しないので、この呼び出しは決して解決しない。`return` という名前への束縛と `${return}` の参照は妨げない。
- `${x}` の参照は呼び出しではないので、この規則の対象外である。参照は環境の束縛を解決するだけであり、`${std.list}` のように関数や演算の値を取り出せる。

## 例

```yaml
$do:
- $let:
    double:
      $fn: x
      $body: ${x * 2}
- {$.double: 21}
```

```yaml
42
```

束縛の値がマッピングなら、ドットで区切ったパスでその中の関数を直接呼べる。

```yaml
$do:
- $let:
    helpers:
      double:
        $fn: x
        $body: ${x * 2}
- {$.helpers.double: 21}
```

```yaml
42
```

引数名の列は部分適用の経路を開く。
表を固定した照会関数を作る。

```yaml
$do:
- $let:
    codes: {ja: 81, us: 1}
    look:
      $fn: [m, k]
      $body:
        $std.lookup:
          in: ${m}
          key: ${k}
- $let:
    dial:
      $.look: ${codes}
- $.dial: ja
```

```yaml
81
```

呼び出しの入れ子が合成である。

```yaml
$let:
  double:
    $fn: x
    $body: ${x * 2}
  succ:
    $fn: x
    $body: ${x + 1}
$in:
  $.succ:
    $.double: 20
```

```yaml
41
```
