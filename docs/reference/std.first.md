# std.first

`std.first` は失敗しなかった最初の分岐の値に評価される。
バックトラック探索とフォールバックの連鎖に使う。

- 種別：std の派生ハンドラ
- 処理する演算：`std.each` `std.fail`

## 形

```yaml
{$std.first: 式}
```

## 規則

- 分岐を文書順に試し、失敗も打ち切りもしなかった最初の分岐の値に評価される。
- 採用された分岐より後の分岐は評価されない。
- すべての分岐が失敗または打ち切りなら、全体が `std.fail` になる。
- 値は選ばれた一つの分岐のものであり、リストではない。全分岐が要るときは `$std.list` を使う。

## 展開の概形

`std.first` の展開は、成功の印を私的な演算対のパラメータ付きハンドラで持ち回る形になり、`$std.list` の展開のように紙面に収まらない。
本節はその**概形**を示す。
ここに書く `first.taken`（印を読む）と `first.mark`（印を立てる）は、この展開の内部だけで使う私的な演算であり、利用者が文書から `$first.taken` のように直接呼べる名前ではない。
規範は規則の節であり、コード断片は仕組みを追うための概形である。展開と組み込み実装の等価性は検証スイートが固定する。

印の持ち回りには、[std.state](std.state.md) の展開が `std.get` / `std.set` に対して行うのと同じ技法、すなわち各節が「現在の印を受け取り、次の印への適用を経て最終的な値を返す関数」を返すパラメータ付きハンドラを使う。
ただし公開の `$std.state` をそのまま流用することはできない。
`std.first` の本体（利用者の式）自身が `std.get` や `std.set` を使えば、同じ記憶を共有してしまい、印が利用者の状態と衝突するからである。
そこで印の持ち回りは、`first.taken` / `first.mark` という文書からは見えない独立した私的なハンドラで行う。

この私的なハンドラは、選択（`std.each`）を処理する内側の `$with` を**包む**位置に置く。
`$std.state` の「貫流」の配置（選択を状態のハンドラが包む形）と同じである。
包む順序が逆で選択の内側に印を置くと、各分岐がそれぞれ真新しい印を持つことになり、先行する分岐の成功が後続の分岐から見えなくなって、短絡（最初の成功より後を評価しない）が起きない。

内側の `$with` が持つ四つの節の概形は次のとおりである。

```yaml
$with:
  std.each:
    $fn: xs
    $body:
      $collect: ${xs}
      $with:
        $fn: x
        $body:
          $if: {$first.taken: null}
          $then: []
          $else:
            $resume: ${x}
  std.fail:
    $fn: _
    $body: []
  return:
    $fn: x
    $body:
      $do:
      - {$first.mark: null}
      - - ${x}
$in: 式
```

節ごとの役割は次のとおりである。

- **`std.each`**：`$collect` で候補を先頭から回る。印が立っていれば、その候補では再開せず `[]` を返す（評価も作用も起きない）。印が立っていなければ、候補の値で `$resume` する。[$std.where](std.where.md) の打ち切りは空の `$std.each` として現れ、この節が 0 個の候補を畳んで `[]` を返す。
- **`std.fail`**：ハンドラは深いので、`std.each` の分岐の途中で起きた失敗もこの節が受け止める。再開せず `[]` を返すので、失敗した分岐の再開結果はちょうど `[]` になり、打ち切られた分岐と同じ扱いで消える。
- **`return`**：本体が演算を起こさず値 `x` に達したら、まず印を立ててから `x` を要素 1 のリストに包む。印を立てるのがこの段である理由は、値に達する（＝成功する）ことと印を立てることを同じ場所で行い、以後の `std.each` の候補がその成功を確実に見られるようにするためである。

この内側の `$with` の値は、`$std.list` の展開と同じ理由でリストになる。
`$collect` 自体は候補の全要素を回るが、印が立った後の候補では `$resume` を呼ばないので、その候補に続く計算（残りの本体や、さらに後にある `std.each` の分岐）は評価されない。
このリストを `results` と呼べば、`$std.first: 式` の値は `${results[0]}` である。
`${hits[0]}` が未初期化のセルでちょうど `std.fail` を起こす [std.state](std.state.md) の展開と同じ理由で、`results` が空リストのとき（＝すべての分岐が失敗または打ち切りだったとき）`${results[0]}` はちょうど `std.fail` を起こす。

## 例

パラメータを何も渡さずに評価する。

```yaml
log_level:
  $std.first:
    $do:
    - $let:
        v: {$std.each: [{$std.param: log_level, $default: null}, info]}
    - $std.where: ${v != null}
    - ${v}
```

```yaml
log_level: info
```
