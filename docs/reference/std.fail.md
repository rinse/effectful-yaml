# std.fail

`std.fail` は計算を失敗させる。

- 種別：std の演算
- 作用：失敗

## 構文

```yaml
$std.fail: 式
```

## 規則

- 引数の値をエラーメッセージとして、計算をその場で打ち切り失敗させる。
- 既定ハンドラは失敗を文書全体のエラーにする。
- 補助キー [$default](default.md) を添えれば、失敗を既定値に置き換えられる。`std.fail` の節を持つ [$handler](handler.md) を立てれば、ログを流すなど任意の回復ができる。
- [std.first](std.first.md) の下では、失敗した分岐が捨てられて次の分岐に進む。
- [std.list](std.list.md) と [std.mapping](std.mapping.md) は失敗を処理しない。一つの分岐の失敗が全体の失敗になる。
- 失敗と打ち切りは違う。`std.where` は分岐を静かに消すが、`std.fail` は処理されない限りエラーとして残る。

## データ起因の部分性も同じ失敗になる

明示の `$std.fail` 呼び出しのほかに、次のデータ起因の部分性もすべて `std.fail` を起こす。

- パスをたどる参照（`${x.y}` や `${xs[0]}`）でキーや添字が存在しないとき。
- `std.lookup` で無いキーを引いたとき。
- `std.param` で渡されていないパラメータを、`$default` なしで読んだとき。
- `std.get` で未初期化のセルを読んだとき。
- ホストが与えた値の呼び出しが、値の代わりに失敗を通知したとき。

これらは、束縛名そのものが未定義であること、マッピングでない値のキーをたどること、型の不一致のような**文書の誤り**とは区別される。
文書の誤りは捕捉できないエラーのままだが、データ起因の部分性は `std.fail` に統一されているので、`$default` と `$handler` で一律に回復できる。
ホスト実装のその他の例外も捕捉できないエラーである。

## 例

`port` を渡さずに評価すると、`invalid port 0` を理由に文書全体がエラーになる。

```yaml
$do:
- $let:
    p: {$std.param: port, $default: 0}
- $if: ${p <= 0}
  $then:
    $std.fail: invalid port ${p}
  $else: ${p}
```
