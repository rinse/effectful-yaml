# $handle

`$handle` は利用者が定義するハンドラであり、カーネルが持つ唯一のハンドラである。
std の派生ハンドラ（`$std.list` や `$std.state` など）はすべて、`$handle` と `$collect` への展開として定義される。

- 種別：ハンドラ
- 処理する作用：`$with` の節に書いた演算
- 補助キー：`$with` `$resume`（`$resume` は節の本体でだけ使える呼び出し）

## 形

```yaml
$handle: 本体の式
$with:
  演算名:
    $fn: 引数名
    $body: 節の本体
  return:
    $fn: 値名
    $body: 式
```

## 規則

- `$with` の節のキーは形で分類する（節名の表を参照）。ドットを含む名前はその演算にマッチする節、`return` は return 節、ドットを含まない `return` 以外の識別子はローカル作用の宣言である。
- 本体で節の演算が呼ばれると、演算の引数が節のパラメータに束縛され、節の本体が評価される。
- 節の本体では `{$resume: 値}` で継続を再開できる。その値は、演算の呼び出し位置に「値」を返して残りの計算（`return` 節を含む）を進めた結果である。
- `$resume` は節の本体の中で呼べる。節の本体で作られた閉包の本体も含み、閉包が捕まえるのはその節の起動に対応する継続である。一度も呼ばない（打ち切り）ことも、複数回呼ぶことも許される。
- 節が `$resume` を呼ばずに値に達したときは、その値がハンドラ全体の値になる（打ち切り）。継続の途中で打ち切られた場合は、その継続を呼んだ `$resume` の位置ではなく、ハンドラ全体が節の値になる。
- ハンドラは深い。再開後の計算にも同じハンドラが効き続ける。
- 節の本体が起こす作用は、このハンドラ自身ではなく外側で処理される。
- `return` 節は、本体が演算を起こさず値に達したときにその値を変換する。省略時は恒等である。
- 作用の推論では、`$with` に現れた演算の名前が集合から除かれ、節と `return` の本体の作用が加わる。

## 節名

節のキーは形で分類する。
規則は上から順に、最初に一致したものを適用する。

| 節名の形 | 意味 |
|---|---|
| `$` で始まる名前 | エラー（将来の予約節のために確保する形） |
| `return` | return 節 |
| 識別子をドットで繋いだ名前（`名前(.名前)+`） | その演算にマッチする節 |
| ドットを含まない識別子 | ローカル作用の宣言 |
| それ以外（空の名前、ドットで始まるか終わる名前、識別子でない文字を含む名前） | エラー |

言語が裸の識別子の空間に予約する節名は `return` ただ一つであり、今後増やさない。
増やすときは `$` を前置した形を使う。

ドットを含む節名は、既存の演算の名前そのものである。

| 作用 | 節名 |
|---|---|
| 選択 | `std.each`（`$std.where` は演算ではなく、`std.each` への展開で処理される） |
| パラメータ | `std.param` |
| 状態 | `std.get` `std.set` |
| ログ | `std.log` |
| 失敗 | `std.fail` |
| 登録演算 | `vault.read` のようにドット入りのまま |

捕捉の単位は作用ではなく演算である。
`std.get` だけを捕まえて `std.set` を素通しにすることもできる。
節に書かなかった演算は外側のハンドラへ抜ける。

## ローカル作用の宣言

ドットを含まない節名は、そのハンドラだけが処理するローカルな作用を宣言する。
名前空間つきの演算名を書かずに、自前の作用を宣言して呼べる。

```yaml
$handle: 本体
$with:
  throw: 節
```

意味はカーネルへの展開で定める。
処理系は宣言の位置の構文パスから内部の演算名を決定的に生成する。
宣言の位置は、`$handle` ではその `$` 式の位置、前置きの `$with` ではそれを置いた文またはマッピングの位置である。
下ではその名前を `throw@位置` と書く。

```yaml
$handle:
  $let:
    throw:
      $fn: 私的名
      $body:
        $throw@位置: ${私的名}
  $in: 本体
$with:
  throw@位置: 節
```

- 宣言は、引数を素通しして内部の演算を呼ぶ関数を本体に束縛する。本体は `{$.throw: 引数}` で呼び、節が引数を受ける。`$let` が値を束縛して `$.名前` で呼ぶのと同じ読み方である。
- 束縛が見えるのは本体だけである。節の本体、`return` 節、ハンドラの外側からは見えない。
- 前置きの `$with` では、残りが本体にあたる。束縛はそこから見える（[$do](do.md) の `$let` と同じスコープ規則）。
- 内部の演算名は宣言ごとに生成される。入れ子のハンドラが同じ `throw` を宣言していても名前は別なので、束縛を経た呼び出しは必ず宣言元のハンドラに届く。
- 内部の演算名は識別子に使えない `@` を含むので、利用者が書ける名前と衝突しない。「演算の名前は必ずドットを含む」という規則は利用者が書ける名前への制約であり、展開が生む内部名には課さない。
- 束縛は普通の束縛である。再束縛で隠せるし、`${throw}` で別名を付けられるし、値として文書の外に残せば関数値の脱出のエラーになる。
- ドットを含む節や `return` 節との混在も、複数のローカル宣言も許される。
- 素通しの関数がハンドラの動的範囲の外で呼ばれると、内部の演算がどのハンドラにも捕まらずに境界へ達し、`local effect 'throw' escaped its handler (declared at 宣言位置)` のエラーになる。関数値の脱出（閉包が文書の値に残る）とは別のエラーであり、判定の時点も呼び出し時と値の確定時で違う。

`return` は節名として予約されているので、`$with: {return: ...}` は return 節でありローカル作用の宣言ではない。
束縛を導入しないので、`$.return` はどこでも解決せず、その出現は評価前に `return is reserved: $.return is not callable` で拒否される（[$fn](fn.md) の呼び出しと名前空間）。

節が `$resume` を呼ばないので、`$.throw` の呼び出しで本体が打ち切られる。

```yaml
$handle:
  $do:
  - {$.throw: boom}
  - never
$with:
  throw:
    $fn: msg
    $body: caught ${msg}
```

```yaml
caught boom
```

## 前置きの $with

節だけを書いた `{$with: 節}` は `$handle` の前置きであり、`$do` の文としても、マッピングのキーとしても置ける。

```yaml
$with: 節
```

本体は、それを置いた文脈の残りである。

```
{$do: [{$with: 節}, 残り...]} ≡ {$handle: {$do: [残り...]}, $with: 節}
{$with: 節} ∪ 残り            ≡ {$handle: 本体式, $with: 節}
```

二つ目の本体式は、残りが `{$in: 式}` ならその式、そうでなければ残りのマッピングである（[$do](do.md) の前置き）。

- 節は、`$with` を書いた位置の束縛を見る。本体に入る残りの文やキーが新たに作る束縛は見えない。
- 逆にローカル作用の宣言が導入する束縛は本体から見える。`$let` の束縛と同じスコープ規則である。
- `$with` が頭キーになるのは、同じマッピングに `$handle` も `$collect` も無いときだけであり、あればそれらの補助キーである。
- 残りの無い `{$with: 節}` は `$do` の文の位置でだけ書ける。
- `$handle` への展開で定義される派生ハンドラの平坦形は、`$with` の前置きで書ける。たとえば `std.fail` の節ひとつだけを持つ `$with` を文に置くと、`{$std.opt: 残り, $default: 節の本体}` と等価である。

失敗を、続く文の既定値として捕捉する。

```yaml
$do:
- $with:
    std.fail: {$fn: _, $body: 0}
- $std.lookup: {in: {}, key: missing}
```

```yaml
0
```

マッピングのキーに置けば、残りが本体になる。

```yaml
database:
  $with:
    std.fail: {$fn: _, $body: {$resume: null}}
  host: {$std.param: db_host}
  port: {$std.param: db_port}
```

`db_host: db` を渡して評価すると次になる。

```yaml
database:
  host: db
  port: null
```

節が `$resume: null` で再開するので、マッピングの中の未渡しのパラメータがそれぞれ null になる。

残りが `$in` ただ一つなら、その値が本体になる。

```yaml
$with:
  std.fail: {$fn: _, $body: 0}
$in:
  $std.lookup: {in: {}, key: missing}
```

```yaml
0
```

## 節の中の閉包から $resume を呼ぶ

節の本体は、その中で作った関数値の本体からも `$resume` を呼べる。
この規則がなければ、`$collect` の `$with` に渡す関数の中から継続を再開する書き方が書けない。

[std.list](std.list.md) の展開がこの規則の具体例である。
`std.each` の節は、選ばれうる要素の列を `$collect` で回り、その `$with` 関数の本体（節の本体が作った閉包）の中で `$resume: ${x}` を呼ぶ。
閉包が捕まえる継続は、`std.each` の節が起動された時点のものであり、`$collect` が要素ごとにこの閉包を呼ぶたびに、同じ継続をその要素の値で再開する。

## 失敗の捕捉

失敗を捕捉し、ログを流して既定値に置き換える。

```yaml
port:
  $handle:
    $do:
    - $let:
        p: {$std.param: port, $default: 0}
    - $if: ${p <= 0}
      $then:
        $std.fail: invalid port ${p}
      $else: ${p}
  $with:
    std.fail:
      $fn: msg
      $body:
        $do:
        - $std.log: ${msg}
        - 5432
```

`port` を渡さずに評価すると次になり、ログに `invalid port 0` が流れる。

```yaml
port: 5432
```

## ログの計装

演算を捕捉し、加工してから同じ演算を呼び直す転送の形である。
節の本体で起こした `std.log` は自分では捕まらず、外側で処理される。

```yaml
$handle:
  $do:
  - $std.log: hello
  - 42
$with:
  std.log:
    $fn: msg
    $body:
      $do:
      - $std.log: 'app: ${msg}'
      - {$resume: null}
```

結果は `42` で、外のログには `app: hello` が流れる。
`std.log` の値は null なので、null で再開している。

## std の派生ハンドラとの関係

`$std.list`、`$std.mapping`、`$std.first`、`$std.state`、`$std.opt` はいずれも `$handle`（`$std.first` はさらに内部の私的な状態も）で書ける形の言語組み込みの省略である。
利用者が独自の選択の集約や、独自の状態の持ち回りを書きたいときは、`$handle` を直接使う。
組み込みの展開は各ページに掲載してあるので、自作するときの雛形として読める。
